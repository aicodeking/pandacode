# PandaCode — working notes

## Project and releases
- PandaCode is open source (the MIT-based PandaCode License in `LICENSE`, which requires forks to credit PandaCode) with no accounts, license checks or telemetry; keep it that way. Never add code that phones home, and never commit secrets or personal paths.
- Follow [docs/releasing.md](docs/releasing.md) for shipping: `npm run release:version X.Y.Z`, write `releases/X.Y.Z.md`, push tag `vX.Y.Z`. `.github/workflows/release.yml` builds macOS (Apple silicon), Windows x64 and Linux x64 and attaches them to a GitHub Release; signing is optional. Only release when the user asks.
- Contributor setup and PR process: [CONTRIBUTING.md](CONTRIBUTING.md). CI is `.github/workflows/ci.yml`.

## Verify
- `npx tsc --noEmit` — typecheck (also runs inside `npm run build`).
- `npm test` — Node unit tests (`tests/*.test.mjs`).
- `npm run test:release` — release script tests (`scripts/release/*.test.mjs`).
- `npm run test:bench` — agent benchmark runner tests (`scripts/agent-bench/*.test.mjs`).
- `npx playwright test` — browser suite against the Vite preview (`npm run dev` on 127.0.0.1:1420 is started/reused automatically; needs Google Chrome at `/Applications/Google Chrome.app`). A server already on the port is reused even if it serves another checkout, so in a second worktree set `PW_PORT=<free port>`. Full run ≈ 3.5 min at the default 4 workers (`PW_WORKERS=N` overrides); pass file paths or `-g "title"` for a subset.
- `npx playwright test -c playwright.webkit.config.ts` — the same suite in WebKit (the real target is WKWebView).

## UI conventions
- Color: never write a literal accent color. Use `--accent`, `--accent-rgb` (for `rgb(var(--accent-rgb) / a)`), `--on-accent` (text on accent fills), `--accent-dim`/`--accent-ink`, `--focus`, `--accent-hover`, `--accent-tint`. `src/palette.ts` sets them from the user's choice (wallpaper accent from `src/wallpaper-accents.ts`, classic yellow, a swatch) or from an imported VS Code theme (`html[data-vsix]`, mapped in `src/palette-core.ts`), which also sets the surface tokens and holds still when wallpapers change. Themes are imported natively by `vsix_themes.rs` (colors only, nothing executed). Regenerate `wallpaper-accents.ts` when scenes change; `tests/palette.test.mjs` checks every scene and 23 recorded real themes for contrast.
- Material: every floating surface (dialog plate, menus, toast) is one glass defined by the `--glass-*` tokens in `src/motion.css`: a solid translucent fill over a backdrop blur, with no top highlight, edge or `--glass-ring` outline. Reduced transparency/contrast rules must keep solid fallbacks.
- Flat: no gradients or borders; separate with surface tone (fills such as `--fill-hover`, `--surface-*`, `--raised`), spacing and radius. Masks, the trace shimmer and focus rings are excepted, and Increase Contrast / forced colors may restore lines.
- Motion: subtle and never in the way. `MOTION = true` in `src/motion.ts` drives surfaces (dialogs, toast, panes; menus arrive via `popover-motion.ts` and leave at once) with short critically damped springs: a few pixels of travel, ~120–220 ms of visible movement, exits ~120 ms; input is never gated and every caller keeps an instant path (`MOTION = false` makes the app instant again). CSS transitions are limited to color, background, opacity, box-shadow and `scale`/`rotate` in 100–200 ms; never animate layout (width, height, grid, top/left). `prefers-reduced-motion: reduce` removes CSS transitions and animations (`styles.css`, `overlay.css`) and motion.ts keeps only a short cross-fade. The live tool trace (`src/trace-motion.ts`, `src/trace-motion.css`) choreographs more: steps blur in, the two newest result cards unfold (older ones fold), the header mirrors the running step with a shimmer, and the turn folds to its summary at the end, with @keyframes and the Web Animations API; the action dock (`src/action-dock.ts`) follows the same rules. Press feedback uses the `scale` property, never `transform`, so a button positioned with `transform` stays under the pointer while pressed. Sidebar task rows are `.task-row` wrappers holding the `.task-item` and its `.task-actions` (the `.task-more` row menu); the selected row has a slim accent bar at its leading edge. The toast (`notify()` in `main.ts`) is warm glass in the bottom-right corner, max 360 px, wraps and clamps, and waits while hovered.
- Action dock (`#action-dock`, `src/action-dock.ts` + `src/action-dock.css`): the workspace header's actions are one `role=toolbar` glass pill (`--glass-warm`, the header's `--header-blur`) at the main pane's right edge, vertically centred by `placement()`; groups are split by a small bar, `--dock-clear` (58px) keeps clickable content out from under it, and at ≤650px and in the board/GitHub views it is a row in the header. Items keep their ids, names and `data-action` (other modules still toggle `hidden`, `active` and `title`; a MutationObserver animates them); one Tab stop with arrow-key roving. Full spec (sizes, springs, indicator, label bubble, entrance): [docs/agents-notes/action-dock.md](docs/agents-notes/action-dock.md); tests `tests/action-dock.spec.ts`.
- The `<dialog>` stays transparent and untransformed: `.dialog-plate` behind it carries the glass, `.dialog-scrim` dims, and a closed-shadow-root ghost carries the exit. Never put `backdrop-filter`/`transform` on the dialog itself — menus opened inside it are `position: fixed` in viewport coordinates.
- Menu triggers (`aria-haspopup`, pickers) keep `--press: 1`; a pressed-scale on an anchor shifts the popover it positions.
- Segmented controls (`.settings-tabs`) hand their highlight to `.segment-thumb` via `trackSegment()`.
- Workspace view (Conversation / Board / GitHub): one icon button `#view-menu` (`data-action="view-menu"`, `aria-haspopup="menu"`, named `Workspace view: <view>`, showing that view's icon — `thread`, `kanban` or `github`, never New chat's `chat` or the sidebar toggle's glyph — plus a small `down` chevron) beside the PandaCode name in the sidebar's `.brand`; `showViewMenu()` in `main.ts` opens a choice menu of the views (GitHub only while `githubEnabled()`), ending at the trigger's right edge in the sidebar so it never spills past it, starting at its left edge in the header. Like the sidebar toggle, `renderSidebarVisibility()` moves it into `.header-leading` while the sidebar is hidden (board, GitHub, collapsed), followed by `#view-divider`; in the narrow rail it sits under the toggle. The old `board-view`/`conversation-view`/`github-view` actions still work and are listed in the command palette. Specs pick a view with the trigger then the `menuitemradio`.
- The top row is one tone per column (header `--bg`-toned glass, inspector strip its own surface, sidebar plain `--sidebar`; no accent gradient or wash). In the conversation view there is no top bar: the header paints nothing, `#breadcrumb` is hidden, and the transcript scrolls under it to the window's top (`--header-under`, first row 16px down via `--transcript-top`, no scrollbar, no fade); in-flow content above the transcript turns this off, and reduced transparency/contrast keep a solid header. The send button rests dim while the prompt is empty, by CSS `:has()` only, never disabled. Details (wallpaper frost values, find-in-thread padding): [docs/agents-notes/workspace-header.md](docs/agents-notes/workspace-header.md).
- The inspector strip is one surface with the panel below: never give `.inspector-strip>.inspector-tabs` a fill (the wallpaper rules' old tab fill is reset in `inspector-bar.css`).
- The inspector's views are one slim tab strip (`.inspector-strip` in `src/inspector-bar.css`): every view's `.inspector-tab[data-view]` stays in the DOM (hidden until open) with its old `data-action` (`tab-files`, `browser`, …); open tabs and the selection persist via `src/inspector-tabs.ts` (`pandacode.inspector.tabs`, default Changes only); `renderInspectorTabs()` adds the tab for whatever `state.inspectorTab` became, so programmatic opens need nothing extra; the `+` menu lists closed views. Specs open a view first with `openInspectorTab()` from `tests/inspector-tab-helper.ts`.
- PandaCode updates itself from GitHub Releases: `src/app-updates.ts` (checks at launch and every 6 h, downloads in the background, installs with a restart only when no agent runs and the user has been idle; decisions in `src/app-updates-policy.ts`), the status-bar `#update-status` button, and Settings → About. Tauri's updater verifies each download against the public key in `tauri.conf.json`; releases carry signed update files and `latest.json` (`scripts/release/updater-manifest.mjs`). This is the only check of PandaCode's own; list any new automatic request in the README privacy table and the website privacy page.

Its webview may call only `tray_*` commands (allowlist in `lib.rs`, capability `capabilities/tray.json`); `tray::refresh` updates the title and emits `tray-changed`, on which the popover re-reads `tray_snapshot` and sizes itself with `tray_resize`. Preview mock: `trayCommand` in `src/preview.ts`; test `tests/tray-popover.spec.ts`.

Native side `src-tauri/src/github_hub.rs` (`github_repos`, `github_repo_pulls`, `github_repo_issues` by `owner/name`; `github_project_repos` maps projects by `origin` remote; `github_clone_repo`). - Branch/worktree UI lives in `src/worktrees.ts` (context bar, `#branch-chip` menu, dialogs, cleanup offer); GitHub in `src/github.ts`; a task's linked PR renders as the inspector's PR tab from `src/github-pull.ts` (native side `github_pull.rs`), and after every run end `github_detect_pull_request` links a PR URL the turn mentioned when it is on the checkout's branch or was created during the turn (an open link is never replaced). Both receive callbacks from `main.ts` instead of importing its state. `linkChip()` and every GitHub affordance return nothing while `githubEnabled()` is false.
- Token saver (`src/token-saver.ts`, panel in `src/token-saver-panel.ts`): per-thread packs (Caveman Lite/Full/Ultra, Lean code, Quiet tools, RTK when `token_saver_tools` finds `rtk`) become one folded `Response style (PandaCode token saver…` block appended at send, only when the packs change and every `REMIND_EVERY` messages, so every harness gets it without paying for it each turn. The pack text lives only in `src/token-saver-packs.json`, read by the window and by `token_saver.rs` (`include_str!`); both hash all 96 outputs to one value, so update both hashes when the text changes. The architect gives each worker a `tokenSaver` (`"none"` or `{packs, level}`; default `"none"`, never inherited, `rtk` taken without an install check; docs/token-saver.md). An active thread block ends with the JSON's `subagents` sentence, asking the agent to pass the style to its own subagents; worker blocks (`token_saver::worker_guidance`) and the app instructions never carry it. Keep pack text short; cite benchmarks in `saves`, mark estimates `(est.)`.
- Local VMs (Apple silicon): `src-tauri/src/vm*` drives Tart on Virtualization.framework (headless with VNC; `vm/rfb.rs` RFB client, `vm/screen.rs` input mapping, commands through `tart exec`, no SSH). The panel (`src/vm-panel.ts`, mocked in `src/preview-vm.ts`) draws frames on a canvas because the app CSP allows no `blob:` images; agents get `pandacode_vm_*` tools (`vm/tools.rs`); idle VMs are suspended/stopped. Details: [docs/agents-notes/local-vms.md](docs/agents-notes/local-vms.md).
- Cloud sandboxes and deploys live in `src-tauri/src/cloud*`. Machine IDs are `provider:native-id` so the `pandacode_vm_*` tools and the VM panel route by prefix (`cloud::split`); keys go through `secret_store.rs` (on macOS one 0600 `secrets.json`, never the Keychain) under `app.pandacode.cloud`. Providers: Daytona (REST), Docker-family engines, VPS over the shared SSH transport `cloud/ssh.rs`, Cloudflare (Sandbox SDK Worker), AWS (CLI login, SSM only) and AgentCore. Deploys go through the approval-gated `pandacode_cloud_cli` (`cloud/deploy.rs`) with credentials only in that process's environment and scrubbed from output. Settings UI `src/cloud-settings.ts`, mocks `src/preview-vm.ts`, HTTP tests `cloud::http::mock`. Per-provider details: [docs/agents-notes/cloud-sandboxes.md](docs/agents-notes/cloud-sandboxes.md).

- Model picker (`src/model-picker.ts` + `src/model-picker.css`, also loaded by the launcher's `overlay-model-picker.ts`): an always-focused combobox search over a `role=tablist` rail (Recent, Teams, each installed harness) and a listbox of one-line rows; effort is a segmented `role=radiogroup` (`trackSegment()`). Keyboard rules (Tab never closes; Esc clears then closes), query behaviour and sizes: [docs/agents-notes/agents-and-teams.md](docs/agents-notes/agents-and-teams.md). Preview: `?teams`.
- Prompt attachments (images, documents, folders, sketches) live in `src/attachments.ts`; the mockup editor in `src/sketch.ts` is lazy-loaded from the `+` menu. Images ride the existing `imageIds` pipeline (`browser-captures/<uuid>.png`, four per message including screenshots); documents and folders become `Document context:` / `Folder context:` blocks. Sent context renders as read-only `.prompt-chip`s under the user's text (`src/message-attachments.ts` parses the blocks `CONTEXT_BOUNDARY` in `main.ts` splits; extend both when adding a block type): workspace files and documents open in a file tab, outside documents and folders are revealed with `reveal_path`, images show from the capture registry via `prompt_image` (image blocks carry an `Image ID:` line; captures are pruned after 7 days, then the chip shows the block's text), GitHub items open their https URL, and anything else (browser elements, unknown blocks) opens its raw text in a dialog. Bot briefs and token-saver notes stay hidden. A dropped item that cannot be attached (unreadable, unsupported, over a cap, imageless harness) is inserted at the caret as its quoted path instead, or for a browser File as its name with a note.
- Thread switching draws in one frame: `selectSession` shows the thread's remembered page (`threadPages` in `main.ts`, only pages whose messages belong to that thread) and redraws after the refresh only if the page changed; `markdown()` in `dom.ts` reuses formatted HTML by source text, so nothing reflows from raw text. The sidebar updates with `morph()` (`dom.ts`), which keeps unchanged rows and replaces any element whose `id`/`data-id` changed, so a click never lands on a row that changed task underneath it.
- Sidebar sections (`sidebarSections()` in `src/sidebar-sections.ts`, drawn by `renderNavigation`): Pinned, then Active, Finished and Settled (there are only these three states plus Pinned; no archive, no Chats or Tasks lists). Settled is docked at the bottom of `#navigation` (sticky). Membership never depends on the sort (pure sorting in `src/sidebar-sort.ts`); an opened thread holds its section (`sectionHold`) so a click never moves its row. Rows are `.task-row` wrappers with `.task-actions` (`data-task`, never `data-id`); the list is one Tab stop (`syncRovingFocus`). Full rules (ordering, caps, filter, menus, undo, native ranking): [docs/agents-notes/sidebar.md](docs/agents-notes/sidebar.md); specs `tests/sidebar-sections.spec.ts`, `tests/thread-order.spec.ts`, `tests/sidebar-keyboard.spec.ts`.
- Find in thread (⌘F, `src/thread-find.ts`): matches in user and agent message text are painted with the CSS Custom Highlight API (`thread-find`, `thread-find-current`), never by rewriting the DOM; a MutationObserver re-runs the query as the transcript changes, and the current match opens any folded turn around it. ⌘G/⇧⌘G and Enter/⇧Enter step; Esc closes without stopping a running agent.
- Agent questions (`src/agent-input.ts`) render rich Markdown through `src/rich-markdown.ts`: header, question and option text are Markdown; `![alt](path)` loads a workspace image as a data: URL via `workspace_image` (task-scoped, image types, 8 MB); remote images become links and are never fetched; ```chart JSON (bar/line/pie) is drawn as SVG; ```svg is sanitized; ```html is sanitized static HTML in a shadow root (no scripts, forms, frames or non-inline images). The app CSP is unchanged. `RICH_QUESTIONS` in `lib.rs` tells agents about it through the cached app instructions.
- Menus and dialogs are one line per row. Choice-menu items show a detail beside the label only when label + detail fit (`BRIEF_ROW` in `choice-menu.ts`); longer details, long `.dialog-description`s (`LONG_DESCRIPTION` in `main.ts`), static `.field-help` hints, and long setting-row `small`s move behind an `infoMark()` (`src/tooltip.ts`) whose text is still in the DOM as `.sr-only`. Live hints opt out with `data-live`; live status `small`s keep a class and stay inline. Never nest a mark inside a `<label>`/`<h2>` — it would join the field's accessible name.
- Overlays mounted inside the open dialog (`.floating-menu`, `.tip-bubble`) are ignored by the dialog motion observer; add new overlay classes there if they mount into `#dialog`.
- Anything rendered by the composer must be styled from an always-loaded stylesheet: `architect.css` (and other lazily imported CSS) only arrives with its module, which is how the Team button once changed size on first click.
- Native: `workspace::run_process` is the one bounded runner for external tools (`git`, `gh`); user text goes to `gh` as `--flag=value`.
- Turn speed and tokens ([docs/worker-tokens.md](docs/worker-tokens.md#turn-speed-cached-instructions-and-warm-spares)):
  - The fixed app instructions (`app_instructions.rs`) go once in the system prompt to Claude-family harnesses (`--append-system-prompt`), Pi and Oh My Pi (`takes_system_instructions`); others get them on a new conversation and every 8th turn.
  - A clean Claude-family turn ends at `result`; its process is reaped in the background and same-session launches await that exit (`providers::await_exit`; never proceeds without a confirmed exit, fails the launch after 10 s; the background exit waits `BACKGROUND_EXIT_WAIT` 3 s then `TERM_WAIT` 0.5 s, inline finishes `EXIT_WAIT` 1 s, a same-session launch hurries the reap, so it waits at most as long as at HEAD: the natural exit, or SIGTERM at `EXIT_WAIT`; a warm spare and Turn checks wait patiently (`await_exit_patiently`) for the natural exit without cutting it); managed workers, cloud runs, failed and stopped runs finish inline. stdin closes at once, a nonzero late exit is logged, and Turn checks wait for the exit (`checks::turn_report_after_exit`, patiently) and the queue's next launch awaits it too (`providers::await_exit`). The Done state and PR detection start about 0.8 s sooner (median of 6 measured turns); timings and caveats are in worker-tokens.md.
  - `providers::quiesce` (discards the spare, then awaits the session's exit) guards the harness console, worktree removal (merge awaits `providers::await_exit` likewise), task deletion and bot reset/delete; worktree removal and merge re-check that no agent started and deletion re-checks busy under the lock. Quit waits up to `QUIT_EXIT_WAIT` for background exits before killing.
  - After a successful plain-Claude turn `providers/warm.rs` prewarms the next turn's process (2 ordinary spares, 10 idle minutes; none for managed workers, cloud runs, GLM or MiMo; the relay probe is in worker-tokens.md). It is adopted only when every field of the warm key matches (`warm::key_with`). Measurements and caveats: worker-tokens.md.
  - A lead with live workers keeps its spare in a separate pool (`LEAD_LIMIT` 2), renewed at most `MAX_RENEWALS` (2) times (`warm.rs`; `lead_spare.rs` decides); Pause/Stop drop it.
- Worker trim (opt-in, off by default: `architect::worker_trim_on`; `Role::wants()` in `src-tauri/src/app_instructions.rs`, listing in `app_instructions/catalog.rs`, recomputed every turn; [docs/worker-tokens.md](docs/worker-tokens.md)): managed workers do not want titles, schedules or agent-made tools; read-only workers also not change tracking, progress or design writes. Only a new conversation drops a family: a resumed one keeps listing any it may hold (persisted in `session-state.json`; no record keeps all) and refuses its calls (no prompt on Claude, whose `can_use_tool` auto-allows the refused set; Codex/ACP may still prompt). The change-tracking instruction is one cached text (`turn_changes::instruction()`, 625 B); only runs whose native edits wait for approval (`edits_wait_for_run`: Standard-mode Claude/GLM/MiMo) get a 160 B per-turn note (`turn_note`).
- Harnesses: adding a provider means touching every `"kimi" | "opencode" | "antigravity"`-style match in `providers.rs`/`acp.rs` and the allowlists in `storage.rs`, `overlay.rs`, `architect*.rs`, `terminal.rs`, `slash_commands*.rs`, `provider_settings.rs`, plus `ProviderId` and its `Record` maps on the frontend; record real frames in the tests and keep an ignored live smoke test per installed CLI. Provider environment variables (`provider_settings.rs`) apply at every harness spawn; cloud runs inherit none unless opted in. Storage schema is at `user_version` 36: a migration step bumps `storage::SCHEMA_VERSION` and the tests that assert the number. Checklist, key-based relays, environment rules and the per-version schema history: [docs/agents-notes/harnesses-and-schema.md](docs/agents-notes/harnesses-and-schema.md).
- Devin CLI (`providers/devin.rs`, docs/providers.md#devin-cli) runs `devin acp` with `ACP_BACKEND` removed (Devin Desktop terminals set it, and then the server ignores the CLI sign-in); PandaCode never calls `authenticate`. Each model has its own `thought_level`, reported only after switching to it, so discovery switches every non-Fusion model across parallel empty sessions (about 2.5 s; Fusion switches take ~1 s each and are listed without efforts) and deletes them, as command discovery does, so Devin's history stays clean. Modes: Standard/Accept edits → `accept-edits`, Plan → `plan` (its `exit_plan_mode` request is the "Implement this plan?" approval, answered `plan_accept_edits`), Full → `bypass`; approvals only ever pick `allow_once`. Unchanged mode/model/effort are not resent on resumed sessions; steering is live. Live tests: `cargo test --lib installed_devin -- --ignored` (one sends two short prompts and deletes its session).
- ZCode (`providers/zcode.rs`, docs/providers.md#zcode) has no ACP mode; PandaCode speaks z.ai's private `zcode app-server` protocol (NDJSON stdio, `session/create|subscribe|send`, events on `session/event`, permissions as `interaction/requestPermission` reverse requests answered with the offered `response` object). One server per run, deferred persistence, resume by saved `sess_<uuid>`; model/effort are set and verified against the returned snapshot. Modes: Standard → `build`, Accept edits → `edit`, Plan → `plan`, Full → `yolo`; steering holds for the next turn; screenshots and interactive questions are refused with a note; slash-command discovery and the harness console are not offered. Protocol shapes are pinned per recorded version (`.agents/state/zcode-harness/protocol.md`); live test `cargo test --lib installed_zcode_lists_models -- --ignored` (catalog only, never a prompt).
- Queue and steering: while an agent runs, Enter queues (`queue_*` commands, shown by `src/message-queue.ts` above the composer) and ⌘/Ctrl Enter steers (`steer_task` → `RunInput::Steer`, `providers/steering.rs`). Steering never stops a run: Claude-family harnesses steer on stream input (launched with `--replay-user-messages` so a late steer keeps the run open for its turn), Codex uses `turn/steer`, Pi `steer`, OpenCode a second `session/prompt` (`acp.rs`); anything a turn cannot take (startup, between turns, refused, other ACP agents) is held by the run and sent as the next turn of the same session (`mode: "next-turn"`). `steer` agent events report `pending`/`delivered`/`failed` by id; the composer shows the pending state and requeues a failed steer. A clean run end delivers the next entry; a failure, stop or restart holds the queue until Resume. The prompt stays enabled during runs, so `renderComposer` must keep focus and the caret. The wider roadmap is in `docs/parity-plan.md`.
- Remote access, PandaCode Connect ([docs/remote-access.md](docs/remote-access.md)), is opt-in: no network traffic until GitHub sign-in. The relay (`relay/`, a Cloudflare Worker) forwards only X25519 + XChaCha20-Poly1305 ciphertext; the native side is `src-tauri/src/remote*`, secrets in `connect-secrets.json` (0600, never the keychain). A task can run on another computer as a mirror (an ordinary session row with `remote_*` columns; agent commands routed by `remote::route`, `Store::workspace_root` refuses it). Machine orchestration ([docs/machine-orchestration.md](docs/machine-orchestration.md), off by default) uses `pandacode_machine_*` tools in `remote/orchestrate.rs`. - Bots ([docs/bots.md](docs/bots.md)) live in `src-tauri/src/bots*` and `src/bots*.ts`. Each bot owns a workspace project (hidden by `userProjects()`) and each conversation is an ordinary task; `run_finished`/`approval_requested` hooks in `lib.rs` route replies and approvals to channels, and prompts in a bot's own conversation go through `bot_message`. Shared-channel and message tables live in `bots::SCHEMA` and idempotent `bots::upgrade()` (no app schema bump); connection secrets stay in `secret_store` and never reach the webview; the local web chat binds to 127.0.0.1 and checks Host. - Markdown everywhere (transcript, streaming, subagents, team workers, launcher, bot chat) goes through `markdownHtml()` in `src/dom.ts`, which uses Software Mansion's Enriched Markdown engine: the md4c WebAssembly parser vendored in `src/vendor/enriched-markdown/` (see its README for provenance and updating) and the renderer in `src/enriched-markdown.ts`. Output is sanitized by DOMPurify, then math placeholders are typeset by KaTeX (`src/math.ts`, lazy). `marked` remains only as a fallback if the WebAssembly cannot start. The app CSP therefore includes `'wasm-unsafe-eval'` (never plain `'unsafe-eval'`; `tests/bundle.test.mjs` guards both), and the bots web chat page loads the same parser from the local server at `/assets/md4c.js`. New Markdown elements need styles in `styles.css` (`.md-*` classes).
- Projectless chats ([docs/chats.md](docs/chats.md)): `chat_create` (`src-tauri/src/chats.rs`) makes `~/PandaCode Chats/chat-<id>/`, registers it as a project named Chat and creates the task; a project is a chat by folder location (`isChatProject` in `src/chats.ts`), so `userProjects()` hides it and the sidebar lists its tasks under Chats. After deleting or moving a chat task, `chat_cleanup` forgets the project and removes the folder only if nothing but PandaCode's files remain.

- Task schedules ([docs/schedules.md](docs/schedules.md)): wake-ups and timed messages for any thread, set by the user or by agents (`pandacode_schedule_wakeup`/`_message`/`list_schedules`/`cancel_schedule`, `src-tauri/src/schedules/tools.rs`, not in bot tasks). `schedules.rs` holds the IPC from `src/schedules-api.ts` (schema 35) and a 15 s clock loop that holds everything while paused; `after` schedules are only marked due by `schedules::run_finished`, and delivery goes through `send_prompt` in `lib.rs` (queued when the task is busy). The fired message ends with a trace block (`TRACE_HEADER`) the UI parses: keep its format exact.
- Workflow recipes ([docs/recipes.md](docs/recipes.md)): JSON step lists in `.pandacode/recipes/` or app data (`recipes.rs`), opened from the composer `+` menu (`openRecipes()` in `main.ts`, `src/recipes.ts`). A dry run marks each step supported, fallback, manual or blocked for the task's harness; running queues the steps through the ordinary message queue.
- Turn checks (`src/turn-checks.ts`, `checks.rs`, off by default in Settings → Agents): after a clean turn the app runs the checkout's own fast test/check command with the user's environment, bounded by `run_process`; a failure queues one editable fix message, never a loop, and bot tasks are skipped.
- Files and file tabs: the inspector's Files tab is an inline tree (`fileTree`/`toggleFolder` in `main.ts`; open folders are per task in `ThreadPanel.folders` and reloaded by `refreshInspector`). Opening a file (tree, search, transcript links, the agent's `open_file`) adds a tab beside Conversation (`src/file-tabs.ts`), kept per task and dropped when the task's workspace changes; the file view covers the conversation pane, which stays mounted and `inert` so its scroll position survives. Text goes through `read_file` and `renderDocument`; PDF, Word (.docx), spreadsheets and images go through `read_document_file` (raw bytes, 64 MB, typed and scoped in `workspace::read_document_bytes`) and `src/office-viewer.ts`, which lazy-loads pdf.js, docx-preview or SheetJS. Documents are untrusted: docx renders in a shadow root with altChunks off, zips are size-checked before parsing (`src/zip-limit.ts`), PDFs draw canvases only (no annotation layer). HTML still opens in the Browser panel; diffs stay in the inspector.

Secret paths and refused roots are `workspace/secret_paths.rs`, an ordered policy documented in its module doc; every verdict is a `CASES` (or roots) row in `secret_paths_tests.rs`, and strict must refuse whatever plain refuses.
