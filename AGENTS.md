# PandaCode — working notes

## Project and releases
- PandaCode is open source (the MIT-based PandaCode License in `LICENSE`, which requires forks to credit PandaCode) with no accounts, license checks or telemetry; keep it that way. Never add code that phones home, and never commit secrets or personal paths.
- Follow [docs/releasing.md](docs/releasing.md) for shipping: `npm run release:version X.Y.Z`, write `releases/X.Y.Z.md`, push tag `vX.Y.Z`. `.github/workflows/release.yml` builds macOS (Apple silicon), Windows x64 and Linux x64 and attaches them to a GitHub Release; signing is optional. Only release when the user asks.
- Contributor setup and PR process: [CONTRIBUTING.md](CONTRIBUTING.md). CI is `.github/workflows/ci.yml`.

## Verify
- `npx tsc --noEmit` — typecheck (also runs inside `npm run build`).
- `npm test` — Node unit tests (`tests/*.test.mjs`).
- `npm run test:release` — release script tests (`scripts/release/*.test.mjs`).
- `npx playwright test` — browser suite against the Vite preview (`npm run dev` on 127.0.0.1:1420 is started/reused automatically; needs Google Chrome at `/Applications/Google Chrome.app`). A server already on the port is reused even if it serves another checkout, so in a second worktree set `PW_PORT=<free port>`. Full run ≈ 3.5 min at the default 4 workers (`PW_WORKERS=N` overrides); pass file paths or `-g "title"` for a subset.
- `npx playwright test -c playwright.webkit.config.ts` — the same suite in WebKit (the real target is WKWebView).

## UI conventions
- Color: never write a literal accent color. Use `--accent`, `--accent-rgb` (for `rgb(var(--accent-rgb) / a)`), `--on-accent` (text on accent fills), `--accent-dim`/`--accent-ink`, `--focus`, `--accent-hover`, `--accent-tint`. `src/palette.ts` sets them from the user's choice (wallpaper accent from `src/wallpaper-accents.ts`, classic yellow, a swatch) or from an imported VS Code theme (`html[data-vsix]`, mapped in `src/palette-core.ts`), which also sets the surface tokens and holds still when wallpapers change. Themes are imported natively by `vsix_themes.rs` (colors only, nothing executed). Regenerate `wallpaper-accents.ts` when scenes change; `tests/palette.test.mjs` checks every scene and 23 recorded real themes for contrast.
- Material: every floating surface (dialog plate, menus, toast) is one warm glass defined by the `--glass-*` tokens in `src/motion.css`; a yellow highlight sits at the top edge. Reduced transparency/contrast rules must keep solid fallbacks.
- Motion: PandaCode is instant. `MOTION = false` in `src/motion.ts` turns off every spring, entrance and exit (each caller has an instant path), and a global `transition:none!important` (end of `styles.css` and `overlay.css`) removes CSS transitions. Only looping status animations (spinners, working pulses) run. The one exception is the live tool trace (`src/trace-motion.ts`, `src/trace-motion.css`): steps blur in, the two newest result cards unfold (older ones fold), the header mirrors the running step with a shimmer, and the turn folds to its summary at the end. It uses @keyframes and the Web Animations API (never transitions) and is instant under prefers-reduced-motion. Press feedback uses the `scale` property, never `transform`, so a button positioned with `transform` stays under the pointer while pressed.
- The `<dialog>` stays transparent and untransformed: `.dialog-plate` behind it carries the glass, `.dialog-scrim` dims, and a closed-shadow-root ghost carries the exit. Never put `backdrop-filter`/`transform` on the dialog itself — menus opened inside it are `position: fixed` in viewport coordinates.
- Menu triggers (`aria-haspopup`, pickers) keep `--press: 1`; a pressed-scale on an anchor shifts the popover it positions.
- Segmented controls (`.view-switch`, `.settings-tabs`) hand their highlight to `.segment-thumb` via `trackSegment()`.
- The inspector's views are one slim tab strip (`.inspector-strip` in `src/inspector-bar.css`): every view's `.inspector-tab[data-view]` stays in the DOM (hidden until open) with its old `data-action` (`tab-files`, `browser`, …); open tabs and the selection persist via `src/inspector-tabs.ts` (`pandacode.inspector.tabs`, default Changes only); `renderInspectorTabs()` adds the tab for whatever `state.inspectorTab` became, so programmatic opens need nothing extra; the `+` menu lists closed views. Specs open a view first with `openInspectorTab()` from `tests/inspector-tab-helper.ts`.
- PandaCode updates itself from GitHub Releases: `src/app-updates.ts` (checks at launch and every 6 h, downloads in the background, installs with a restart only when no agent runs and the user has been idle; decisions in `src/app-updates-policy.ts`), the status-bar `#update-status` button, and Settings → About. Tauri's updater verifies each download against the public key in `tauri.conf.json`; releases carry signed update files and `latest.json` (`scripts/release/updater-manifest.mjs`). This is the only check of PandaCode's own; list any new automatic request in the README privacy table and the website privacy page.
- Menu bar item (`src-tauri/src/tray.rs`, Tauri `tray-icon`): a template panda icon titled with the running count. Left click toggles a popover window labelled `tray` (`?view=tray` → `src/tray-popover.ts` + `.css`, built like the launcher: transparent glass, hidden on blur or Esc, centered under the icon's click rect and clamped to the work area); right click is a native Open/Quit menu. The popover lists Running, Needs you and Finished, not viewed (in memory with success/failure; cleared by `tray_seen` from `selectSession` or by `tray_open`, which emits `tray-open-session`) and Plan usage from the cached `agent_usage::query_usage`, checked only when the popover opens or on its refresh button — never polled. Its webview may call only `tray_*` commands (allowlist in `lib.rs`, capability `capabilities/tray.json`); `tray::refresh` updates the title and emits `tray-changed`, on which the popover re-reads `tray_snapshot` and sizes itself with `tray_resize`. Preview mock: `trayCommand` in `src/preview.ts`; test `tests/tray-popover.spec.ts`.

Agents get `pandacode_vm_*` tools (`vm/tools.rs`); the inspector's VM tab is `src/vm-panel.ts`, mocked in `src/preview-vm.ts`. Live tests are `#[ignore]`d and take `PANDACODE_VM`/`PANDACODE_VNC`.
- Cloud sandboxes and deploys live in `src-tauri/src/cloud*`. Machine IDs are `provider:native-id` (`daytona:`, `cloudflare:`, `aws:`, `agentcore:`), so the `pandacode_vm_*` tools and the VM panel route by prefix (`cloud::split`). Keys go through `secret_store.rs` (shared with bots, providers and connections: on macOS one 0600 `secrets.json` in app data, never the Keychain, with old Keychain items moved over once on first read; Secret Service/Credential Manager elsewhere) under `app.pandacode.cloud`; non-secret settings are one JSON value beside them (`cloud::Settings`). Daytona is REST (`cloud/daytona.rs`, toolbox computer use). Cloudflare deploys `cloud/cloudflare_worker/` (Sandbox SDK 1.0 container Worker, bearer token, 10 min idle) with Wrangler; Cloudflare cannot list Durable Objects, so `cloudflare_sandboxes` remembers names. AWS uses the user's AWS CLI login: EC2 desktops via SSM only (no inbound ports; VNC on the instance's localhost, carried by an SSM port-forward in `cloud/aws_screen.rs`), and AgentCore code interpreters (`cloud/agentcore.rs` signs InvokeCodeInterpreter with SigV4 and reads the event stream). Deploys: `pandacode_cloud_cli` (`cloud/deploy.rs`, approval-gated) runs vercel, wrangler, railway, aws or gcloud in the checkout with credentials only in that process's environment and scrubbed from output (Vercel, Wrangler and Railway use an installed CLI or a pinned `npx` package fetched on first use, never bundled; Railway runs only deploy subcommands in `RAILWAY_ALLOWED`; aws and gcloud use only the user's installed CLI and login, with `aws_refusal`/`gcloud_refusal` and `scrub_aws`/`scrub_gcloud`); the header Deploy menu (`src/deploy.ts`) starts a task with a platform brief. Settings → Agents → Cloud sandboxes is `src/cloud-settings.ts`; preview mocks are in `src/preview-vm.ts`. HTTP tests use `cloud::http::mock`.
- Cloud agents ([docs/cloud-agents.md](docs/cloud-agents.md)): `src-tauri/src/cloud/sandbox.rs` is the `Sandbox` trait every provider implements (`cloud/<provider>.rs`; Railway and AgentCore can't host agents). `src-tauri/src/cloud_agents/` runs the ordinary provider pipeline over a remote transport: `transport.rs` swaps the harness for PandaCode's own binary in bridge mode (`bridge.rs`, `handle_cloud_bridge` in `main.rs`), which drives `runner.sh` on the machine through byte-acknowledged `inbox` appends and polled `out`; `resume.rs` re-attaches active runs (`sessions.cloud`, schema 27) at startup; `tasks.rs` holds the IPC, prepare/before/after-run steps; `setup.rs`, `credentials.rs` and `sync.rs` install the harness, copy logins and move git bundles to and from the task's mirror worktree. UI: `src/cloud-agents.ts`, the Run on menu in `src/remote-target.ts`, keyed provider forms in `src/cloud-settings.ts`; mocks in `src/preview.ts`/`src/preview-vm.ts`.
- Teams: the composer's Team button toggles an automatic team (`toggleTeam` in `main.ts`, `config.auto`), or, with Settings → Agents → Classic team setup (`src/team-mode.ts`, a per-window preference), opens the Architect & workers setup. Named agent teams (`src/agent-teams.ts` in Settings) are team profiles with `config.rosterOnly` and `config.name`; the model picker lists them under Agent teams, picking one calls `architect_configure` with the profile, and picking a plain model removes it. Natively, `staff_from_roster` in `architect.rs` refuses any worker model outside a roster-only team.
- Prompt attachments (images, documents, folders, sketches) live in `src/attachments.ts`; the mockup editor in `src/sketch.ts` is lazy-loaded from the `+` menu. Images ride the existing `imageIds` pipeline (`browser-captures/<uuid>.png`, four per message including screenshots); documents and folders become `Document context:` / `Folder context:` blocks. Sent context renders as read-only `.prompt-chip`s under the user's text (`src/message-attachments.ts` parses the blocks `CONTEXT_BOUNDARY` in `main.ts` splits; extend both when adding a block type): workspace files and documents open in a file tab, outside documents and folders are revealed with `reveal_path`, images show from the capture registry via `prompt_image` (image blocks carry an `Image ID:` line; captures are pruned after 7 days, then the chip shows the block's text), GitHub items open their https URL, and anything else (browser elements, unknown blocks) opens its raw text in a dialog. Bot briefs and token-saver notes stay hidden. A dropped item that cannot be attached (unreadable, unsupported, over a cap, imageless harness) is inserted at the caret as its quoted path instead, or for a browser File as its name with a note.
- Thread switching draws in one frame: `selectSession` shows the thread's remembered page (`threadPages` in `main.ts`, only pages whose messages belong to that thread) and redraws after the refresh only if the page changed; `markdown()` in `dom.ts` reuses formatted HTML by source text, so nothing reflows from raw text. The sidebar updates with `morph()` (`dom.ts`), which keeps unchanged rows and replaces any element whose `id`/`data-id` changed, so a click never lands on a row that changed task underneath it.
- Sidebar sections (`sidebarSections()` in `src/sidebar-sections.ts`, drawn by `renderNavigation`): Active (running, approval/answer, a usage limit still in effect, or a failed/interrupted run you have not seen) and Needs review (stage review, last response < `REVIEW_WINDOW`, finished while another thread was open: `pandacode.sidebar.unreviewed`) above Pinned/Chats/folders (or one flat list), Completed (closed by default, `pandacode.sidebar.completedOpen`; 10 rows, then "Show 25 more") below. Membership never depends on the sort; each section has its own order (Active by latest start, Needs review by latest response, Completed by completion, never `updatedAt`). Running threads are always Active. However a thread is opened (click, ⌘1…9, ⌘⇧[ / ], board, palette), `selectSession` records the section its row was in (`sectionHold`, `sectionOf()`), and the open thread stays there, so a click on its row never moves it; once a held thread runs, the hold becomes Active: it stays there while open and goes to its folder when you open another thread, never back to Completed. The open thread also stays listed in Completed past its first page (as `shownTasks` does for folders). Sorting lives in `src/sidebar-sort.ts` (pure, `tests/sidebar-sort.test.mjs`): the header's Sort and view menu (`showSidebarSort`, saved as `pandacode.sidebar.sort`) picks tasks Manual/Recent/Created, projects Recent/Added (`Project.addedOrder`, the native rowid; the list itself arrives sorted by name)/Name/Manual (folders dragged or moved with Alt+↑/↓, saved as `pandacode.sidebar.projectOrder`), 3–15 tasks per folder (one segmented row in the menu, so the whole menu fits a 720px window; Chats too; Pinned is never capped), and Group by project or Flat list (rows show the project's icon, and its name when the list is wider than 264px; a `sidebar-nav` container query hides it and the row tooltip keeps it). Manual puts never-ranked tasks first, then `sidebarOrder`; natively a New task published by its first prompt takes rank 0 and shifts the others down once the sidebar has been arranged (`rank_published_drafts` in `storage.rs`, a TEMP trigger, so no schema change), so a later reorder never sinks it; `reorder_sessions` never ranks drafts. Pinned always keeps manual order; only Manual rows are draggable. Folder order reads every task of the project (`folderGroups({ all })`), so a folder holds still when its task starts. The filter field (`#sidebar-filter`, Esc clears; `/` focuses it from the task list or anything that is not a control, never while typing, and is left alone when the field is hidden: narrow windows hide it, and so does the Bots panel, which has its own search) sets `state.query`, matches title, branch, PR/issue and project, and while set shows matches in collapsed folders, closed Completed and past every cap; heading clicks then change nothing, so nothing is saved; with no match the list says "No tasks match". Rows: two-line cards in Active, Needs review and Pinned; one 28px line elsewhere; needs-you states show a word (Approval, Answer, Failed, `Limited · <reset>`), unread rows a dot and bold title. Each row is `.task-row#task-row-<id>` holding `.task-item` plus sibling `.task-actions` buttons (`data-task`, never `data-id`, `tabindex=-1`) that cover the status/age slot behind a fade to `--row-bg`, the row's own hover/focus/selected background (the title never shrinks): tick and a … menu (`showSidebarTaskMenu`, four groups: pin/move — moves only where rows can move — · rename (by id, without opening)/read/new task from the branch · copy branch/path/ID · complete/archive/delete), or restore and delete in the archive view. Folder headings carry a chevron, a task count (when collapsed, hovered or focused) and a … menu, also on right-click (`showFolderMenu`: New task, Collapse other projects, Reveal in Finder / Show in Explorer / Open folder by platform, Remove project). The list is one Tab stop (`syncRovingFocus` in `thread-order.ts`): ↑/↓/Home/End move, →/← open and close headings, ⌘↩ ticks, Shift+F10 opens the menu; ⌘1…9 and ⌘⇧[ / ] (never while typing in a field). Undo (toast or ⌘Z) after complete (restoring the exact stage and unread mark; native `set_task_stage` allows `in_progress` only to undo completing a stopped/failed run), archive and unpin. Folder list ids are per project (`folder-tasks-<id>`) so morph keeps them. Menus (`choice-menu.ts`) are the `--glass-*` material (solid under reduced transparency/contrast), take `heading`/`separator` items and `segment`/`short` items for one-row segmented choices (← → step along them), and mark the current choice with a trailing check (one rule in `styles.css`; model and project menus keep their fill). Preview samples: `?sections`; specs `tests/sidebar-sections.spec.ts`, `tests/thread-order.spec.ts`, `tests/sidebar-keyboard.spec.ts`.
- Find in thread (⌘F, `src/thread-find.ts`): matches in user and agent message text are painted with the CSS Custom Highlight API (`thread-find`, `thread-find-current`), never by rewriting the DOM; a MutationObserver re-runs the query as the transcript changes, and the current match opens any folded turn around it. ⌘G/⇧⌘G and Enter/⇧Enter step; Esc closes without stopping a running agent.
- Agent questions (`src/agent-input.ts`) render rich Markdown through `src/rich-markdown.ts`: header, question and option text are Markdown; `![alt](path)` loads a workspace image as a data: URL via `workspace_image` (task-scoped, image types, 8 MB); remote images become links and are never fetched; ```chart JSON (bar/line/pie) is drawn as SVG; ```svg is sanitized; ```html is sanitized static HTML in a shadow root (no scripts, forms, frames or non-inline images). The app CSP is unchanged. `RICH_QUESTIONS` in `lib.rs` tells agents about it through the cached app instructions.
- Menus and dialogs are one line per row. Choice-menu items show a detail beside the label only when label + detail fit (`BRIEF_ROW` in `choice-menu.ts`); longer details, long `.dialog-description`s (`LONG_DESCRIPTION` in `main.ts`), static `.field-help` hints, and long setting-row `small`s move behind an `infoMark()` (`src/tooltip.ts`) whose text is still in the DOM as `.sr-only`. Live hints opt out with `data-live`; live status `small`s keep a class and stay inline. Never nest a mark inside a `<label>`/`<h2>` — it would join the field's accessible name.
- Overlays mounted inside the open dialog (`.floating-menu`, `.tip-bubble`) are ignored by the dialog motion observer; add new overlay classes there if they mount into `#dialog`.
- Anything rendered by the composer must be styled from an always-loaded stylesheet: `architect.css` (and other lazily imported CSS) only arrives with its module, which is how the Team button once changed size on first click.
- Native: `workspace::run_process` is the one bounded runner for external tools (`git`, `gh`); user text goes to `gh` as `--flag=value`.
- Turn speed and tokens: the fixed app instructions (sidebar titles, `pandacode-run.sh`, change tracking; `app_instructions()` in `lib.rs`) go to Claude-family harnesses once as `--append-system-prompt`, which caches with the prefix; other harnesses get them in the message on a new conversation and every 8th turn. Only a one-line current-title note rides each message. After a successful Claude turn, `providers/warm.rs` starts the next turn's process in the background (at most 2, 10 idle minutes); a follow-up adopts it only when model, mode, effort, folder, resume ID, instructions and tool catalog all match (the MCP server is rebound to the new turn at the same address), so it skips the CLI's startup. Anything else starts cold.
- Harnesses: adding a provider means touching every `"kimi" | "opencode" | "antigravity"`-style match in `providers.rs`/`acp.rs`, the allowlists in `storage.rs`, `overlay.rs`, `architect*.rs`, `terminal.rs`, `slash_commands*.rs`, `provider_settings.rs`, plus `ProviderId` and its `Record` maps on the frontend (tsc flags the maps). ACP harnesses share `acp.rs`; provider quirks (Grok's `authenticate` step, plan-mode policy, `_meta.totalTokens` usage) live behind `config.provider` checks there. Record real frames in the tests, and keep an ignored live smoke test per installed CLI. Key-based Claude Code relays (GLM, MiMo) each get a `providers/<id>.rs` with `environment()/arguments()/configure()/models()`, a `Credential` in `provider_settings.rs` (own secure-store account + env var), and an entry in the `keyed` table of `src/provider-settings.ts`, which renders the card's key form and status. Schema is at `user_version` 30 (version 30 added `message_attachments`, the images a user message carried: captures copied to `<app data>/attachments/<session>/`, moodboard images linked by id; served to phones by `task.attachment`; version 29 added `bots.skills`/`bots.mcp`, a bot's skill and MCP references, and `bot_tasks`, the bot a project task started with; version 28 added `bots.soul`, a bot's optional personality; version 27 added `sessions.cloud` for cloud agents; version 26 added the mirror columns `sessions.remote_device`, `remote_session` and `remote_synced_id`; the bot tables in `bots::SCHEMA`; version 24 added `sessions.limited_at`, `limited_until` and `resume_at_reset`; version 23 `queued_messages`, the durable per-task queue in `message_queue.rs`; version 22 added `sessions.draft`, set for a New task until its first saved prompt publishes it; version 21 added `sessions.pinned` and `sessions.sidebar_order`, version 20 `sessions.title_origin`, version 19 `sessions.last_prompt_at`). Drafts are excluded from `list_sessions`; empty ones are deleted on leave (`discard_draft`) and at startup. Adding a migration step means bumping `storage::SCHEMA_VERSION` (the outer guard reads it; a test checks it matches the newest `PRAGMA user_version=`) and updating the tests that assert the number.
- Devin CLI (`providers/devin.rs`, docs/providers.md#devin-cli) runs `devin acp` with `ACP_BACKEND` removed (Devin Desktop terminals set it, and then the server ignores the CLI sign-in); PandaCode never calls `authenticate`. Each model has its own `thought_level`, reported only after switching to it, so discovery switches every non-Fusion model across parallel empty sessions (about 2.5 s; Fusion switches take ~1 s each and are listed without efforts) and deletes them, as command discovery does, so Devin's history stays clean. Modes: Standard/Accept edits → `accept-edits`, Plan → `plan` (its `exit_plan_mode` request is the "Implement this plan?" approval, answered `plan_accept_edits`), Full → `bypass`; approvals only ever pick `allow_once`. Unchanged mode/model/effort are not resent on resumed sessions; steering is live. Live tests: `cargo test --lib installed_devin -- --ignored` (one sends two short prompts and deletes its session).
- Queue and steering: while an agent runs, Enter queues (`queue_*` commands, shown by `src/message-queue.ts` above the composer) and ⌘/Ctrl Enter steers (`steer_task` → `RunInput::Steer`, `providers/steering.rs`). Steering never stops a run: Claude-family harnesses steer on stream input (launched with `--replay-user-messages` so a late steer keeps the run open for its turn), Codex uses `turn/steer`, Pi `steer`, OpenCode a second `session/prompt` (`acp.rs`); anything a turn cannot take (startup, between turns, refused, other ACP agents) is held by the run and sent as the next turn of the same session (`mode: "next-turn"`). `steer` agent events report `pending`/`delivered`/`failed` by id; the composer shows the pending state and requeues a failed steer. A clean run end delivers the next entry; a failure, stop or restart holds the queue until Resume. The prompt stays enabled during runs, so `renderComposer` must keep focus and the caret. The wider roadmap is in `docs/parity-plan.md`.
- Remote access, PandaCode Connect ([docs/remote-access.md](docs/remote-access.md)), is opt-in: there is no network traffic until GitHub sign-in (device flow). The relay is `relay/`, a Cloudflare Worker with one SQLite Durable Object per account, hibernated WebSockets, and GitHub app-checked sign-in. It forwards only X25519 + XChaCha20-Poly1305 ciphertext. The native side is `src-tauri/src/remote*`: a host answers only devices in its account's presence, and only while "Allow remote control" is on (no per-device pinning; Full access for remote tasks is a separate, default-off host setting). The relay token and device key live in `connect-secrets.json` (0600, `remote/secrets.rs`), never the keychain: macOS re-prompts for keychain items after every unsigned update. `secret_store.rs` shares its file code (`load`/`update`: 0600 temp, fsync, rename, lock file). Requests, responses and events carry `ts`/`nonce` against replay. A task can *run on another computer* as a mirror: an ordinary local session row with `remote_device`/`remote_session`/`remote_synced_id` (schema 26), started by `remote_start_task` (host side `remote/start.rs` finds or clones the GitHub project into `~/PandaCode`). Agent commands for a mirror (`send_message`, `stop_session`, approvals, input, `steer_task`, model/effort) are routed natively by `remote::route`; the queue stays local. Hosts push raw `AgentEvent`s (`agent.events`, one frame per subscriber per 100 ms, text deltas merged, then `run.finished`), which the viewer re-emits as `agent-event` under the local id, and messages are copied with `task.messages` after each run (`remote/mirror.rs`). `Store::workspace_root` refuses a mirror (`This task runs on <name>.`), so git, worktree and file commands never touch the local disk. There is no remote view. The UI is `src/remote*.ts`, with mocks in `src/preview-remote.ts`. Builds need `PANDACODE_RELAY_URL` and `PANDACODE_GITHUB_CLIENT_ID`.
- Bots (docs/bots.md) live in `src-tauri/src/bots*` and `src/bots*.ts`. Each bot owns a workspace project and each conversation is an ordinary task, so `run_finished`/`approval_requested` hooks in `lib.rs` route replies and approvals back to channels. Bots are listed in the sidebar's Bots section (`renderBots` in `main.ts`, from `bots_list`, which includes each bot's `desktopSession`); a row opens that conversation via `bot_desktop_thread` in the ordinary conversation pane: the same transcript, streaming, composer and model picker as any task (a model chosen there is saved on that conversation with `configure_session`; the bot's profile model applies to new conversations). `botForThread()` in `main.ts` finds the bot for any thread in its workspace, so the header shows `botCrumb()` (name, state, pause, Settings), an empty thread shows `botWelcome()`, the prompt reads "Message <bot>…", and the `.bot-thread` class hides the project bar; these styles live in `styles.css` because they render before the bots module loads. Settings are a modal (`showBotSettings`, `mountBots` with `layout: 'settings'`): Profile, Conversations, Memory, Schedules, Channels, Rules and Activity, styled by `src/bots-settings.css`; the Bots window (`layout: 'window'`) is the same body beside a bot list and creates bots, which then open in their conversation. There is no separate bot chat view. Prompts typed in a bot's own conversation go through `bot_message` so the brief and memories apply; the brief folds behind the message's attached context. Bot workspaces stay out of the project tree, filter and picker (`userProjects()`). Bot tasks drain their queue natively; the window skips `dispatchQueue` for bot projects. Channel secrets stay in `secret_store` via `bots/secrets.rs` and never reach the webview. The local server (`bots/channels/http.rs`) binds 127.0.0.1 only and checks the Host header for web chat.
- Markdown everywhere (transcript, streaming, subagents, team workers, launcher, bot chat) goes through `markdownHtml()` in `src/dom.ts`, which uses Software Mansion's Enriched Markdown engine: the md4c WebAssembly parser vendored in `src/vendor/enriched-markdown/` (see its README for provenance and updating) and the renderer in `src/enriched-markdown.ts`. Output is sanitized by DOMPurify, then math placeholders are typeset by KaTeX (`src/math.ts`, lazy). `marked` remains only as a fallback if the WebAssembly cannot start. The app CSP therefore includes `'wasm-unsafe-eval'` (never plain `'unsafe-eval'`; `tests/bundle.test.mjs` guards both), and the bots web chat page loads the same parser from the local server at `/assets/md4c.js`. New Markdown elements need styles in `styles.css` (`.md-*` classes).
- Projectless chats ([docs/chats.md](docs/chats.md)): `chat_create` (`src-tauri/src/chats.rs`) makes `~/PandaCode Chats/chat-<id>/`, registers it as a project named Chat and creates the task; a project is a chat by folder location (`isChatProject` in `src/chats.ts`), so `userProjects()` hides it and the sidebar lists its tasks under Chats. Chat tasks hide the project bar, Deploy and Run (`body.chat-thread`), and `app_instructions(true)` drops the run-script text. After deleting or moving a chat task, `chat_cleanup` forgets the project and removes the folder only if nothing but PandaCode's files remain.
- Design canvas ([docs/design-canvas.md](docs/design-canvas.md)): agents write HTML artboards to `.pandacode/design/` with `pandacode_design_*` tools (`src-tauri/src/design.rs`), and the inspector's Design tab (`src/design-canvas.ts`, mounted by `syncDesignPanel()` in `main.ts`) shows them in script-free sandboxed iframes with element comments. It refreshes on `design-changed` and at run end; a hidden canvas makes no calls.
- Skills & rules library ([docs/skills-library.md](docs/skills-library.md)): Settings → Skills & rules (`src/skills-library.ts`, native `skills.rs`) imports a skill or rule once into app data, turns it on per harness and scope, and scans for drift. Nothing activates without the user.
- Jujutsu ([docs/jj.md](docs/jj.md)): `jj.rs` runs the user's `jj` through `workspace::run_process`; `refreshInspector()` loads `jj_status` beside `git_status`. A non-colocated jj checkout gets the jj Changes panel (`showJjPanel` in `src/jj.ts`), a colocated one keeps Git with a `jjChip()` on the branch card.
- Capabilities & cache panel ([docs/capabilities.md](docs/capabilities.md)): Settings → Tools & add-ons mounts `src/capabilities-panel.ts`, a read-only inventory of each harness's commands, MCP servers, hooks and skills (`capabilities.rs`) plus observed cache reads/creations from the usage ledger. It never returns secrets, hook bodies or absolute config paths.
- Workflow recipes ([docs/recipes.md](docs/recipes.md)): JSON step lists in `.pandacode/recipes/` or app data (`recipes.rs`), opened from the composer `+` menu (`openRecipes()` in `main.ts`, `src/recipes.ts`). A dry run marks each step supported, fallback, manual or blocked for the task's harness; running queues the steps through the ordinary message queue.
- Turn checks (`src/turn-checks.ts`, `checks.rs`, off by default in Settings → Agents): after a clean turn the app runs the checkout's own fast test/check command with the user's environment, bounded by `run_process`; a failure queues one editable fix message, never a loop, and bot tasks are skipped.
- Files and file tabs: the inspector's Files tab is an inline tree (`fileTree`/`toggleFolder` in `main.ts`; open folders are per task in `ThreadPanel.folders` and reloaded by `refreshInspector`). Opening a file (tree, search, transcript links, the agent's `open_file`) adds a tab beside Conversation (`src/file-tabs.ts`), kept per task and dropped when the task's workspace changes; the file view covers the conversation pane, which stays mounted and `inert` so its scroll position survives. Text goes through `read_file` and `renderDocument`; PDF, Word (.docx), spreadsheets and images go through `read_document_file` (raw bytes, 64 MB, typed and scoped in `workspace::read_document_bytes`) and `src/office-viewer.ts`, which lazy-loads pdf.js, docx-preview or SheetJS. Documents are untrusted: docx renders in a shadow root with altChunks off, zips are size-checked before parsing (`src/zip-limit.ts`), PDFs draw canvases only (no annotation layer). HTML still opens in the Browser panel; diffs stay in the inspector.
- Workspace search: the inspector's Search tab (`src/search-panel.ts`) lists file-name matches from the @-mention index and find-in-files results from `search_text` (`workspace::search_text`). Agents' optional `codedb` code search is `code_search.rs`.
- Browser preview mocks for new IPC commands live in `src/preview.ts` (`previewWorktree`, `previewGithub`); add one for every new command so the Playwright suites can cover it.
- Mobile app (`mobile/`, Expo, iOS + Android): a viewer and controller for PandaCode Connect that never runs tasks. `src/connect/` is the client: crypto byte-compatible with `remote/crypto.rs`, the relay socket, trust pins and RPC. `src/store/` is zustand plus a pure `reduce.ts` for live events; it ignores the host's raw `done` and ends a run on `run.finished`. Screens are in `src/app/`: Inbox, Computers and Settings are tabs of the system tab bar (`(tabs)/_layout.tsx`, expo-router `NativeTabs`: a real UITabBarController with Liquid Glass and minimize on scroll, Material bottom navigation on Android), each its own Stack; the Inbox is one inbox across all computers (`(tabs)/inbox/index.tsx`, sections in `src/store/inbox.ts`: Running first, then Needs you with approvals and questions before failures and limits, then Recent; running rows show `Working 6m` or `Stalled 4m` after `STALL_MS` without an event (`live.lastEventAt`, else the host's `lastEventAt`), the current tool or Thinking from `glanceOf`, and `+N agents`; only the small `RunClock` ticks, every 15 s, and `client.ts` also subscribes to every listed running task (`glance`, at most 20) so the inbox sees their events). Traces match the desktop: `src/store/trace.ts` ports `src/tool-trace.ts` (kinds, sentences, edit diffs, todos, subagent snapshots, tool groups) and `src/ui/Trace.tsx` draws tool rows (icon, status, duration, tap for diff/checklist/command output/raw input and output), subagent panels, the run's Plan card and the Thinking line; `reduce.ts` keeps tool start/end times, `subagents`, `todos`, `thinking`, `startedAt`, a limit past its run end, and merges newer hosts' `lastEventAt`/`runStartedAt`/`subagents` (`withHostActivity`; older hosts send none). The task screen and the New task, Task info and Model & permissions sheets stay in the root Stack and cover the tab bar. The task screen is at `task/[device]/[session].tsx` with a native Stack header (`src/ui/TaskHeader.tsx`: title, system back, and `Stack.Toolbar` SF Symbol items for Model & permissions, Task info and Stop while running; transparent so the wallpaper shows behind the title; the inverted transcript scrolls under the bar (top padding = header height) with iOS's automatic scroll edge effect turned off (`scrollEdgeEffects` hidden on every edge: sized from the flipped list it blurred most of the transcript), and `HeaderBlur` draws a systemChromeMaterial blur with a soft fade and hairline behind the bar on Liquid Glass systems; a non-translucent bar always paints opaque whatever `headerStyle` says). Sent prompts show at once as optimistic bubbles (`src/store/sent.ts`: Sending…, Steer · Sending…, Queued) replaced by the first matching saved user message; the phone also fetches messages when a watched task turns running and after a steer. Threads open newest first (`loadMessages` in `client.ts`): the store holds each thread's newest window, drawn at once from the disk cache (`src/store/threads.ts`, pure `thread-cache.ts`: one hashed file per device+session in cache/threads/ with the last 200 messages, written 1.5 s after a change, 8 MB total with LRU eviction, cleared on sign-out), else a `task.messages {tail: true, limit: 60}` page behind a grey skeleton; afterId pages then catch up ("Couldn't refresh" with Retry if that fails) and `{beforeId}` pages load as the inverted list nears the top (`loadOlder`, `older` in the store). Hosts whose replies lack `hasOlder` (or refuse the params) are remembered in `legacy` and paged by afterId as before (`src/connect/paging.ts`). Every tasks.list queues a background prefetch (`src/store/prefetch.ts`: running, waiting, then each host's 5 newest, skipping threads whose cached id matches the row's `lastId`), one call at a time and held while a thread is open or a prompt sends; inbox rows start the cache read on press-in. `src/connect/perf.ts` logs dev-only `[thread-perf]` tap→paint→current timings. Live Activities (`src/live/`, `expo-widgets`: Lock Screen card and Dynamic Island, extension `com.aicodeking.pandacode.LiveActivity`, App Group `group.com.aicodeking.pandacode`) summarise running/waiting tasks while the app is alive; background updates need APNs (`docs/app-store/live-activities.md`), turns folded by `src/store/turns.ts` and a glass composer. Liquid Glass comes from `expo-glass-effect`, with solid fallbacks. Sends made while offline wait in the outbox (`src/store/outbox.ts`, kept in SecureStore) and go out in order on reconnect. Snoozes and pins are phone-only. Harness logos are copied from `src/assets/providers/`. On the iPhone Duo iOS itself moves the status bar, the tab bar and native header items (never custom header views) into a vertical rail on one edge; there is no custom rail, and nothing may pad the root layout or the tab controller won't reach the edge. Screens keep content clear of side insets themselves (`contentInsetAdjustmentBehavior="automatic"` plus `insets.left/right` on lists, the composer dock and floating views; never a fixed tab bar height). When the rail is drawn on a wide window (`useSplit()` in `src/ui/split.tsx`: `useVerticalBarEdgeIOS() != null` and width >= 700) the app becomes a split view: the inbox sidebar (`Sidebar.tsx`, rendered by the root layout on every route so the stack never resizes during a tab switch, which drops the tabs from the rail) beside the selected task or a New thread pane (`NewThread.tsx`); the sidebar toggle and New task are native header items. Every other phone keeps the single-column layout. The desktop's 21 wallpaper scenes are copied to `mobile/assets/wallpapers/` and drawn once behind every screen (`src/ui/Backdrop.tsx`; `src/ui/wallpaper.ts` is the same schedule as `src/wallpapers.ts`, and `tests/wallpaper.test.ts` compares them), with visibility, blur and scene in Settings (`WallpaperSettings.tsx`); the phone starts at 26 % and 2 px (`phoneWallpaperPreferences` in `wallpaper.ts`, which leaves the shared schedule alone and moves old saves still at the untouched 20/0; saves carry `version: 2`). Screens and the tab controller are transparent so the glass refracts it; Reduce Transparency turns it off. Settings → Appearance (System/Light/Dark, `src/ui/appearance.ts`, in SecureStore) calls `Appearance.setColorScheme`, so native headers, tabs, sheets, glass, blur, keyboard and status bar follow; colours come from `theme.ts` tokens/PlatformColor, and black harness tiles (`black` in `harness.tsx`) sit on a light rim in dark mode. Project tiles (`ProjectTile.tsx`: inbox rows, sidebar, New thread/New task pickers, Task info) show the host's `projects.icons` data: URLs via `connect.projectIcons` (batches of 50, after `tasks.list` for listed tasks' projects and for the picked project; cached per device+project in memory and `project-icons.json` in the cache directory, refetched daily, missing ids retried after 10 min, hosts answering `Unknown method.` skipped for the session; pure logic in `src/store/icon-cache.ts`), else the coloured initial. `EXPO_PUBLIC_PANDACODE_DEMO=1` seeds fake data for screenshots. The task header also carries a pull request item (`arrow.triangle.pull`, shown once `connect.loadPull` finds a linked PR via `task.pull`, else `task.pullDetect`; cached in `pulls`, rechecked at run end), Changes (`plus.forwardslash.minus`) and a More menu (Model & permissions, Task info), all `Stack.Toolbar` items; they push `pull.tsx` (state, checks, labels, body, files, commits, timeline, Merge with a confirmed merge/squash/rebase, Open on GitHub), `changes.tsx` (`task.changes` plus counts from one `task.diff`, pull to refresh, reloaded at run end) and `diff.tsx` (`task.pullDiff`/`task.diff` for one path in `src/ui/DiffView.tsx`; line kinds in `src/store/diff.ts`). Bots: `bots.list` runs after each `tasks.list`; rows with a `botId` leave the project sections and the inbox and Duo sidebar list each bot under Bots (`botRows` in `src/store/inbox.ts`, `src/ui/BotRow.tsx`); a bot opens its desktop conversation (`bot.thread`) in the ordinary task screen, whose composer sends through `bot.message` and whose header shows the avatar, name and Pause/Resume (`bot.pause`). Older hosts answer `Unknown method.`: `newer()` in `client.ts` marks the host `outdated` and the screen says "Update PandaCode on <computer> to use this." The demo answers all of these from `src/demo-host.ts` and `src/demo-pull.ts`. PandaCode's own MCP tools (team coordination, title, track_files, simulator, VM, design, preview) read as sentences from `src/store/pandacode-tools.ts` (`Dispatched 3 workers`, `Asked GPT-6 for a follow-up`, `Tapped (200, 618)`; worker names from the task's team through `WorkerNamesContext`), with icons in `Trace.tsx` and cards in `src/ui/ToolCards.tsx` (an assignment card per dispatched worker, the finish summary and team messages as Markdown, a checkpoint, a screenshot when the result carries its bytes); other MCP calls read `server › tool` with pretty-printed arguments. Agents: the task header's `person.3` item (shown when the task has subagents or team workers) and the inbox's `+N agents` badge push `agents.tsx` (Team workers and Subagents: harness logo, model, status, elapsed time, current tool from the worker's own watched session, one-line summary), and a row pushes `agent.tsx` (a worker's checkpoint, summary, files and `task.workerMessages` transcript, refreshed every 5 s while it runs; a subagent's prompt, tools and reply). Teams come from `task.team` (`src/store/team.ts` decodes it and applies the `team` live event's changed worker row; `{ removed: true }` drops it) into `teams` in the store, asked once when a task opens and every 5 s on the Agents screens while the team works (`src/ui/useTeam.ts`); a host without `task.team` is remembered for the session apart from `outdated` and the screen says to update it. The demo's architect task (`src/demo-team.ts`) has three workers (done, running with a checkpoint, failed) and dispatch/finish/message calls. It relies on the host methods `tasks.list`, `task.start` with `projectId`, and `pending` in `subscribe`. Attachments: newer hosts send `attachments` rows on task.messages (`parseAttachments`/`bubbleAttachments` in `src/store/attachments.ts`; rows or images without an id, and older hosts, keep the name chips parsed from the prompt); user bubbles show images as a thumbnail grid (`src/ui/Attachments.tsx`) that opens `src/ui/ImageViewer.tsx` (native modal, pinch/double-tap zoom, swipe between images, swipe down to close, Share on iOS), and document/folder chips open the message's own context block in a monospace sheet. Bytes come through `task.attachment`/`task.workspaceImage` chunks (`src/connect/attachments.ts`: one download at a time for the app, each chunk after the thread's own message calls, prefetch held while any waits, concurrent asks deduped, 'Unknown method.' remembered per host) into cache/attachments/ (`src/store/attachment-files.ts`: `.part` files resume, 64 MB LRU, cleared on sign-out). Agent replies never hand images to the native Markdown renderer (it would fetch remote ones): `replyParts` draws workspace-relative `![alt](path)` as tappable thumbnails and turns anything with a scheme into a link. The demo's docs thread carries two bundled images and a document (`src/demo-images.ts`). Verify with `cd mobile && npx tsc --noEmit && npm test && npx expo lint`. `/ios` and `/android` are generated by prebuild and are not committed.
