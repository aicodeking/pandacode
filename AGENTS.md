# PandaCode — working notes

Rules an agent needs before writing any code. Detailed subsystem notes are in [docs/agent-reference.md](docs/agent-reference.md): read the section for an area (index below) before changing it. New detail goes there or in `docs/*.md`, not here: this file must stay under 65,536 bytes (`tests/agents-md.test.mjs`).

## Project and releases
- PandaCode is open source (the MIT-based PandaCode License in `LICENSE`, which requires forks to credit PandaCode) with no accounts, license checks or telemetry; keep it that way. Never add code that phones home, and never commit secrets or personal paths.
- Follow [docs/releasing.md](docs/releasing.md) for shipping: `npm run release:version X.Y.Z`, write `releases/X.Y.Z.md`, push `main`, wait for its CI run to go green, then push tag `vX.Y.Z` (the release workflow refuses a commit without a green push CI run on main). `.github/workflows/release.yml` builds macOS (Apple silicon and Intel), Windows (x64 and arm64) and Linux (x64 and arm64) and attaches them to a GitHub Release; signing is optional. Only release when the user asks.
- Contributor setup and PR process: [CONTRIBUTING.md](CONTRIBUTING.md). CI is `.github/workflows/ci.yml`.

## Verify
- `npx tsc --noEmit` — typecheck (also runs inside `npm run build`).
- `npm test` — Node unit tests (`tests/*.test.mjs`).
- `npm run test:release` — release script tests (`scripts/release/*.test.mjs`).
- `npx playwright test` — browser suite against the Vite preview (`npm run dev` on 127.0.0.1:1420 is started/reused automatically; needs Google Chrome at `/Applications/Google Chrome.app`). A server already on the port is reused even if it serves another checkout, so in a second worktree set `PW_PORT=<free port>`. Full run ≈ 3.5 min at the default 4 workers (`PW_WORKERS=N` overrides); pass file paths or `-g "title"` for a subset.
- `npx playwright test -c playwright.webkit.config.ts` — the same suite in WebKit (the real target is WKWebView).

## UI conventions
- Color: never write a literal accent color. Use `--accent`, `--accent-rgb` (for `rgb(var(--accent-rgb) / a)`), `--on-accent` (text on accent fills), `--accent-dim`/`--accent-ink`, `--focus`, `--accent-hover`, `--accent-tint`. `src/palette.ts` sets them from the user's choice (wallpaper accent from `src/wallpaper-accents.ts`, or with Wallpapers off the `Sky` swatch, a calm sky blue (`SKY_SCENE`), classic yellow, a swatch) or from an imported VS Code theme (`html[data-vsix]`, mapped in `src/palette-core.ts`), which also sets the surface tokens and holds still when wallpapers change. Themes are imported natively by `vsix_themes.rs` (colors only, nothing executed). Regenerate `wallpaper-accents.ts` when scenes change; `tests/palette.test.mjs` checks every scene and 23 recorded real themes for contrast.
- Material: every floating surface (dialog plate, menus, tooltips, toast) is one glass defined by the `--glass-*` tokens in `src/motion.css`: a solid translucent fill (dark is neutral, `rgb(34 34 34 / .72)`) over a backdrop blur with a 1px `--glass-border` hairline (black 8% light / white 8% dark), no top highlight or `--glass-ring` outline. Reduced transparency/contrast rules must keep solid fallbacks.
- Surfaces (as in the reference, `/tmp/redesign/reference2.png`): hairline borders + soft shadows, no gradients. Cards, inset panels, segmented tracks, chips and raised buttons carry a 1px `--ds-border` (text 7% dark / 9% light; `--ds-border-strong` 16%/14% on raised thumbs) and `--ds-shadow-card` / `--ds-shadow-raised`; fills are one step off the surface (`--ds-card`, `--ds-card-inner`, `--ds-raised`). The inset panels (`.main-pane`, `.inspector`, `.settings-content`) draw the hairline as an inset outline over their content plus `--ds-shadow-card` (none when the main pane is full-bleed). Use only `--ds-*` tokens, never literal greys. Increase Contrast turns hairlines solid (`--border`/`--text`) and drops shadows; forced colors use system colours.
- Design system (`src/design-system.css`, after `styles.css`): `--ds-*` tokens derived from the palette (cards, rows, controls, geometry, type, status and state tones); no gradients, no literal greys. Cards nest `.ds-card` > `.ds-card-inner`; rows `.ds-row`; segments `.ds-seg` via `trackSegment()`; primary/raised buttons `.ds-btn-primary`/`.ds-btn`; switches `.ds-toggle`. State tones go on a leading icon as `data-state-tone`, never `data-tone`. Increase Contrast, reduced transparency, forced colours, wallpapers and imported VS Code themes are all handled there; contrast is checked by `tests/palette.test.mjs`. Inset shell (`src/inset-shell.css`): one `--frame` tone under the sidebar, with the conversation, inspector and Settings content as inset `--panel-surface` panels. Full token and shell detail: [ref](docs/agent-reference.md#design-system-and-shell).
- Type and radius:
  - Pair display, title and heading size with matching role weight and leading and `--tracking-tight`. Subheading requires its role weight. Use role leading when setting it, or an allowed fixed-height pairing.
  - Use sentence-case subheading for group labels and caption medium with caption leading for column headers.
  - Reserve body medium for buttons and controls; options of every segmented control (any `[data-segmented]` track or `.segment-thumb` parent, such as `.ds-seg`, `.gh-tabs`, `.saver-levels`, `.choice-menu-segment`, plus the horizontal `.bs-nav`) stay regular body weight in every state, while vertical rails such as `.model-menu-tab` use medium on the active row like list navigation. `tests/design-tokens/segmented.mjs` discovers tracks from `src/` CSS and `data-segmented` tags, fails any weight on a track or option that is not proven regular (custom properties, `font` shorthands and `font-variation-settings` resolved, failing closed), and verifies the unconditional `[data-segmented],.ds-seg` body-weight and `font-variation-settings:normal` reset in `src/design-system.css`, which a track may not undo with `inherit`/`unset` or `all:`. It reads `src/` CSS only (inline styles and script style writes are not scanned), and `.bs-nav` and `.jev-assist-tabs` have no thumb, so they are conventions, not guarded. Full mechanics and boundaries: [Design system and shell](docs/agent-reference.md#design-system-and-shell).
  - Use strong on small roles for uppercase labels with `--tracking-caps`, and on prose `strong` and `b`. Set `text-transform:uppercase` with caps tracking.
  - Include a line height in non-CSS-wide `font` shorthands. Set an explicit weight when inheriting or resetting an input, select or textarea font outside the bare base reset.
  - Set caption leading explicitly to `--type-caption-leading`, `1`, a listed row or control height, or `--leading-code` in monospace. Pair `--mono-size` with `--leading-code`, `--type-meta-leading`, `--type-body-leading`, `1`, `0`, `normal` or a listed row or control height.
  - Keep the shared base HTML resets (plus the shared `.markdown` table-header rules) in `src/type-base.css`. Every Shadow DOM builder (`generativeSheet()`, custom views, rich-HTML) adopts it, then `src/shadow-base.css`, for shared typography and HTML rules. Custom views receive both through `renderBlock(kind, source, baseCss)`. Use `--tracking-none` for `kbd`. The mono reset covers `code`, `pre`, `samp` and `tt`; shadow-base never restates type-base's heading resets. The guard inventories every `attachShadow` under `src/` (every shared `SCRIPT_EXTS` extension, `.ts/.tsx/.mts/.cts/.js/.mjs/.cjs`, plus `.html`), including `\u`/`\x`-escaped spellings and constant strings folded across `+`, templates and `.join()` (the shared `tests/design-tokens/ts-fold.mjs`; identifiers are not resolved), and rejects declarative Shadow DOM (`shadowrootmode=`, folded the same way) in script strings and HTML (`tests/design-tokens-flow.test.mjs`).
  - No synthetic caps (`font-variant` small/petite/unicase/titling caps, `font-feature-settings`/`-webkit-font-feature-settings` caps tags, including `var()` indirection) and no `initial`/`revert`/`revert-layer` on `font`, `font-size`, `font-family`, `font-weight`, `line-height`, `letter-spacing`, `font-variant` or `all`; no `font-stretch` other than `normal`. Canvas `.font` and `letterSpacing` writes (literals, templates, `+`, `join`, `String`, `concat`, `Object.assign` and bound keys are traced) and SVG typography attributes (`font-size`, `font-weight`, `font-family`, `font-variant`, `letter-spacing`) follow the scale and caps rules too.
  - Use one radius per element kind. Use `--ds-card-radius`, `--ds-inner-radius` and `--ds-control-radius` for their roles. Only `src/tokens.css` defines them: `:root` defaults, and its dialog step-down to inner, control and chip (in-dialog viewer plates stay at card; portaled `.floating-menu`/`.tip-bubble` keep page radii). Use one-value `border-radius`, or logical corner longhands with one value each.
  - Use only the shared select chevron (with its `:dir(rtl)` position) and `background-color` for fills; never override its position, repeat, size, `background-origin`, `background-clip` or `appearance`, and never set `background-attachment`, `background-blend-mode` or `mask`/`-webkit-mask` (`-image` too) on a select (a component `appearance:none` erases the forced-colors arrow; only the shared rule sets it). Set `padding-block` and `padding-inline-start`, and preserve at least 30px of `padding-inline-end`. The standalone launcher (`src/overlay.css`, which does not load `design-system.css`) mirrors the shared chevron and forced-colors fallback (native arrow, `8px` end padding) on `.launcher-project select`; Shadow DOM sheets carry their own copy (`src/generative-ui.css`). These rules also apply to class-only rules on any class `src/` puts on a `<select>` (such as `.settings-select`, `[class~="settings-select"]`, `[class="settings-select"]`, or a `[class^=]`/`[class$=]`/`[class*=]` substring a known class satisfies).
  - Inline prose and copy `code`, `samp` and `tt` read `--code-inline-size` (0.9em) in Light DOM, the launcher and Shadow DOM, while `pre :is(code,samp,tt)` inherits `--mono-size`; standalone file-path chips (such as `.tool-trace-files code`) keep `--mono-size`. Markdown and bare Shadow DOM h1/h2 read `--md-heading-lg` with `--tracking-none` (no `--tracking-tight` exception; Markdown parity also locks `samp`/`tt` on every inline-code parent path in every host, `ul`/`ol` wrappers, items and `code` (not `samp`/`tt`) nested up to three levels, nested blockquotes, captions, and bare Shadow DOM headings, code and table heads). Only inline `code` carries the chip pill and LTR isolate (`src/styles.css:160,178`): code tokens are left-to-right source text, while `samp`/`tt` share its font, size and weight without the chip fill and flow with the prose, Markdown citations and compact brand chips `--md-cite-size`, KaTeX `--md-katex-size`. All four are defined only in `src/tokens.css`.
  - Use tokens for sizes, weights and radii. The literal allowlist covers the wordmark size, family and line-height, brand letter tile, simulator bezel and heatmap cell radius. See [Design system and shell](docs/agent-reference.md#design-system-and-shell).
- Drags inside the window: use `draggable=true` and the usual `dragstart`/`dragover`/`drop`/`dragend` handlers, which `src/pointer-drag.ts` replays from the pointer, because Tauri's file-drop handler keeps native `dragover` and `drop` from ever reaching the page. A browser spec proves nothing about native drags unless it discards trusted drag events (`tests/pointer-drag.spec.ts`). OS file drops stay on `onDragDropEvent`.
- Motion: subtle and never in the way. `MOTION = true` in `src/motion.ts` drives surfaces with short critically damped springs (a few pixels, ~120–220 ms; exits ~120 ms); input is never gated and every caller keeps an instant path. CSS transitions only for color, background, opacity, box-shadow and `scale`/`rotate` (`translate` only for switch knobs) in 100–200 ms with `--ds-ease-in`/`--ds-ease-out`; never animate layout (width, height, grid, top/left) or backdrop-filter. Press feedback uses `scale`, never `transform`. Nothing transitions before `data-ready`; `prefers-reduced-motion: reduce` removes transitions and animations (instant paths, short cross-fades for surfaces). Pulses use `state-pulse` (opacity only). Full rules (settle, dock, trace, switches, thread switch, inspector): [ref](docs/agent-reference.md#motion).
- The `<dialog>` stays transparent and untransformed: `.dialog-plate` behind it carries the glass, `.dialog-scrim` dims, and a closed-shadow-root ghost carries the exit. Never put `backdrop-filter`/`transform` on the dialog itself — menus opened inside it are `position: fixed` in viewport coordinates.
- Menu triggers (`aria-haspopup`, pickers) keep `--press: 1`; a pressed-scale on an anchor shifts the popover it positions.
- Segmented controls (`.ds-seg`, `.gh-tabs`, `.saver-levels`) hand their highlight to `.segment-thumb` via `trackSegment()`; the thumb is placed with the `translate` property (never `transform`, which the size FLIP's `scale` would compose with), so it slides evenly between options of different widths.
- Generative UI containers come from one list, `GU_CONTAINERS` in `src/generative-ui-selectors.ts`: `GU_CONTAINER_SELECTOR`, `TIGHT_CUSTOM` and `SHADOW_SURFACE` (`src/generative-ui.ts`) derive from it whole, and every `src/generative-ui.css` `:is()`/`:where()` group naming two or more containers must match it. Never hand-repeat the class list, slice or alias it, or reach the module other than by a plain named import: `tightContainerProblems()` in `tests/design-tokens/gu-containers.mjs` AST-scans every `src/` script module and fails partial uses, derived values used outside `.matches()`/`.closest()`/`.querySelector()`/`.querySelectorAll()`, namespace, default or renamed imports, re-exports, and `import()`, `require()` or `import.meta.glob()` loads of the module. Full mechanics and documented boundaries: [Design system and shell](docs/agent-reference.md#design-system-and-shell).
- Anything rendered by the composer must be styled from an always-loaded stylesheet: `architect.css` (and other lazily imported CSS) only arrives with its module, which is how the Team button once changed size on first click.
- Text entry: any handler that submits or cancels on Enter or Escape checks `isImeKey()` (`src/dom.ts`): WKWebView sends the committing Enter after compositionend with keyCode 229.

## Native and data

- Native: `workspace::run_process` is the one bounded runner for external tools (`git`, `gh`); user text goes to `gh` as `--flag=value`.
- Network and secrets: no traffic before opt-in (Connect needs GitHub sign-in; the router profiler downloads only while routing is on); a new automatic request goes in the README privacy table and the website privacy page. Secrets live in `secret_store.rs` (0600 file on macOS, never the Keychain) and never reach the webview. The app CSP allows `'wasm-unsafe-eval'`, never `'unsafe-eval'`, and no `blob:` images.
- PandaCode updates itself from GitHub Releases: `src/app-updates.ts` (checks at launch and every 6 h, downloads in the background, installs with a restart only when no agent runs and the user has been idle; decisions in `src/app-updates-policy.ts`), the status-bar `#update-status` button, and Settings → About. Tauri's updater verifies each download against the public key in `tauri.conf.json`; releases carry signed update files and `latest.json` (`scripts/release/updater-manifest.mjs`). This is the only check of PandaCode's own; list any new automatic request in the README privacy table and the website privacy page.
- Schema and harnesses: schema is at `user_version` 37; a migration bumps `storage::SCHEMA_VERSION` (a test checks it matches the newest `PRAGMA user_version=`) and the tests that assert the number. Adding a provider means touching every `"kimi" | "opencode" | "antigravity"`-style match in `providers.rs`/`acp.rs`, the allowlists in `storage.rs`, `overlay.rs`, `architect*.rs`, `terminal.rs`, `slash_commands*.rs`, `provider_settings.rs`, plus `ProviderId` and its `Record` maps (tsc flags them), and the Skills manager (`skill_manager/matrix.rs` `rules`, `roots.rs` skill roots, `cli.rs` `agent_id`, `HARNESS_NAMES` in `skill-manager-model.ts`, then `UPDATE_SKILL_MATRIX=1 cargo test skill_manager_matrix_fixture` for the preview's `tests/fixtures/skill-matrix.json`); ACP harnesses share `acp.rs`; record real frames in tests and keep an ignored live smoke test per installed CLI. `provider_configuration` returns the roster; `src/provider-settings.ts` generates a card for any harness without a hand-written one. Details and per-provider notes: [ref](docs/agent-reference.md#providers-and-harnesses).
