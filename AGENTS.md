# PandaCode — working notes

## Project and releases
- PandaCode is open source (the MIT-based PandaCode License in `LICENSE`, which requires forks to credit PandaCode) with no accounts, license checks or telemetry; keep it that way. Never add code that phones home, and never commit secrets or personal paths.
- Follow [docs/releasing.md](docs/releasing.md) for shipping: `npm run release:version X.Y.Z`, write `releases/X.Y.Z.md`, push tag `vX.Y.Z`. `.github/workflows/release.yml` builds macOS (Apple silicon), Windows x64 and Linux x64 and attaches them to a GitHub Release; signing is optional. Only release when the user asks.
- Contributor setup and PR process: [CONTRIBUTING.md](CONTRIBUTING.md). CI is `.github/workflows/ci.yml`.

## Verify
- `npx tsc --noEmit` — typecheck (also runs inside `npm run build`).
- `npm test` — Node unit tests (`tests/*.test.mjs`).
- `npm run test:release` — release script tests (`scripts/release/*.test.mjs`).
- `npx playwright test` — browser suite against the Vite preview (`npm run dev` on 127.0.0.1:1420 is started/reused automatically; needs Google Chrome at `/Applications/Google Chrome.app`). A server already on the port is reused even if it serves another checkout, so in a second worktree set `PW_PORT=<free port>`. Full run ≈ 3.5 min at the default 4 workers (`PW_WORKERS=N` overrides); pass file paths or `-g "title"` for a subset.
- `npx playwright test -c playwright.webkit.config.ts` — the same suite in WebKit (the real target is WKWebView).

## UI conventions
- Color: never write a literal accent color. Use `--accent`, `--accent-rgb` (for `rgb(var(--accent-rgb) / a)`), `--on-accent` (text on accent fills), `--accent-dim`/`--accent-ink`, `--focus`, `--accent-hover`, `--accent-tint`. `src/palette.ts` sets them from the user's choice (wallpaper accent from `src/wallpaper-accents.ts`, classic yellow, a swatch) or from an imported VS Code theme (`html[data-vsix]`, mapped in `src/palette-core.ts`), which also sets the surface tokens and holds still when wallpapers change. Themes are imported natively by `vsix_themes.rs` (colors only, nothing executed). Regenerate `wallpaper-accents.ts` when scenes change; `tests/palette.test.mjs` checks every scene and 23 recorded real themes for contrast.
- Material: every floating surface (dialog plate, menus, toast) is one glass defined by the `--glass-*` tokens in `src/motion.css`: a solid translucent fill over a backdrop blur, with no top highlight, edge or `--glass-ring` outline. Reduced transparency/contrast rules must keep solid fallbacks.
- Flat: no gradients or borders; separate with surface tone (fills such as `--fill-hover`, `--surface-*`, `--raised`), spacing and radius. Masks, the trace shimmer and focus rings are excepted, and Increase Contrast / forced colors may restore lines.
- Motion: subtle and never in the way. `MOTION = true` in `src/motion.ts` drives surfaces (dialogs, toast, panes; menus arrive via `popover-motion.ts` and leave at once) with short critically damped springs: a few pixels of travel, ~120–220 ms of visible movement, exits ~120 ms; input is never gated and every caller keeps an instant path (`MOTION = false` makes the app instant again). CSS transitions are limited to color, background, opacity, box-shadow and `scale`/`rotate` in 100–200 ms; never animate layout (width, height, grid, top/left). `prefers-reduced-motion: reduce` removes CSS transitions and animations (`styles.css`, `overlay.css`) and motion.ts keeps only a short cross-fade. The live tool trace (`src/trace-motion.ts`, `src/trace-motion.css`) choreographs more: steps blur in, the two newest result cards unfold (older ones fold), the header mirrors the running step with a shimmer, and the turn folds to its summary at the end, with @keyframes and the Web Animations API; the action dock (`src/action-dock.ts`) follows the same rules. Press feedback uses the `scale` property, never `transform`, so a button positioned with `transform` stays under the pointer while pressed. Sidebar task rows are `.task-row` wrappers holding the `.task-item` and its `.task-actions` (the `.task-more` row menu); the selected row has a slim accent bar at its leading edge. The toast (`notify()` in `main.ts`) is warm glass in the bottom-right corner, max 360 px, wraps and clamps, and waits while hovered.
- Action dock (`#action-dock`, `src/action-dock.ts` + `src/action-dock.css`): the workspace header's actions are one `role=toolbar` glass pill of 38px items (`--dock-item`; 28px under 640px tall, 26px under 520px) in `--glass-warm` with the header's own `var(--header-blur)` (`--header-glass` over a wallpaper) at the main pane's right edge (left of an open inspector, at the window edge when it is closed; left of the overlay inspector at 651–920px), vertically centred by `placement()` in the free space between the header (or open file tabs) and `#composer-area`, 12px clear of both, re-placed by a ResizeObserver (pane, composer, file tabs, main pane, dock) and on resize. Groups (panels: inspector, terminal, browser, moodboards, Agents · actions: Run, Deploy, Task actions · update prompt `#update-status` + Later) are split by a 20×2 rounded bar of `color-mix(in srgb,var(--text) 20%,transparent)`, which folds in and out with a lone group's item (its `::before`, animated through `pseudoElement`); while the dock's own height springs, the centring follows it frame by frame. The header keeps only its leading items and `.header-actions` (the preview note). `--dock-clear` (58px) narrows the transcript, file tabs, task details, JEV activity, file view and composer column (not on the New task page) so nothing clickable sits under the dock; a shared bot channel never runs under the header (`.channel-thread` is excluded from `--header-under`), so its settings button stays in its own row. At ≤650px and in the board/GitHub views the same element is a `position: relative` row in the header (`--dock-clear: 0`). Items keep their ids, names and `data-action`; other modules still toggle `hidden`, `active` and `title`, and the dock's MutationObserver moves each `title` into `data-dock-tip`, springs items in/out on `hidden` (height in a column, width in a row; a leaving item is `inert` with `data-leaving` until it collapses, and its group stays until then), and grows/fades the active accent fill (`::before`; several panels can be on). One shared `.action-dock-indicator` pill slides to the hovered or keyboard-focused item on its own softer `PILL_SPRING` (damping .85, response .28 ≈ 367 ms), dissolves (`data-muted`) over an active item so it never pops under the accent fill, and fades out on leave. The label bubble (`#action-dock-tip`, the same glass and `--header-blur`, mounted in the header beside the dock so its blur sees the thread) waits 350 ms on hover, shows at once on keyboard focus or while another is up (300 ms grace), slides and resizes between labels, sits left of the dock or below the row (kept inside the window), and Escape hides it without reaching the app. One spring (`DOCK_SPRING`, damping .85, response .2 ≈ 267 ms); hover scales the icon to 1.05, press to .94 (the icon only on `aria-haspopup` triggers); the entrance (16 ms stagger) plays once per window session (`sessionStorage`) after the composer lays out, and startup renders before the first press or key never animate. Roving: one Tab stop, ↑/↓/←/→/Home/End. Spec: `tests/action-dock.spec.ts`.
- The `<dialog>` stays transparent and untransformed: `.dialog-plate` behind it carries the glass, `.dialog-scrim` dims, and a closed-shadow-root ghost carries the exit. Never put `backdrop-filter`/`transform` on the dialog itself — menus opened inside it are `position: fixed` in viewport coordinates.
- Menu triggers (`aria-haspopup`, pickers) keep `--press: 1`; a pressed-scale on an anchor shifts the popover it positions.

Like the sidebar toggle, `renderSidebarVisibility()` moves it into `.header-leading` while the sidebar is hidden (board, GitHub, collapsed), followed by `#view-divider`; in the narrow rail it sits under the toggle. The old `board-view`/`conversation-view`/`github-view` actions still work and are listed in the command palette. Specs pick a view with the trigger then the `menuitemradio`.
- The top row is one tone per column: the workspace header is `--bg`-toned glass (no accent gradient), the inspector strip is the inspector's own surface, and the sidebar is plain `--sidebar` (no accent wash). In the conversation view there is no top bar: the header paints nothing (no fill, blur or `::before` band) and only keeps the drag region and leading items, the project name (`#breadcrumb`) is hidden (a bot conversation keeps its crumb), and the transcript scrolls under it to the window's top edge with no fade, mask or line; the transcript has no visible scrollbar; it is pulled up by `--header-under` to the window's top and its first row sits 16px down at rest (`--transcript-top` = `--header-fade`, 16px; the header's height while the sidebar is collapsed, so the leading buttons and traffic lights stay clear), so nothing is hidden at rest; its `scroll-padding-top` clears that gap, and find in thread (`clearTop()` in `src/thread-find.ts`) lands matches below that padding and its own bar. Anything in flow above the transcript (file tabs, details, JEV activity) turns this off; the board, GitHub view and new-task page never use it. Reduced transparency/contrast drop the band and keep the solid header. Over a wallpaper the header glass is the frost material at .78 light / .72 dark with a 14px blur and a 48px fade (denser than `--workspace-frost-surface`, so muted header text stays legible) with no hairline, and the frost (`--workspace-frost-surface`, `--thread-surface`) is .5 light / .55 dark. Section headings carry no lead icons (Settled keeps its toggle chevron). The send button rests dim (`--fill-active`, `--muted`) while the prompt is empty with no attachments, by CSS `:has()` only; it is never disabled for it.
- The inspector strip is one surface with the panel below: never give `.inspector-strip>.inspector-tabs` a fill (the wallpaper rules' old tab fill is reset in `inspector-bar.css`).
- The inspector's views are one slim tab strip (`.inspector-strip` in `src/inspector-bar.css`): every view's `.inspector-tab[data-view]` stays in the DOM (hidden until open) with its old `data-action` (`tab-files`, `browser`, …); open tabs and the selection persist via `src/inspector-tabs.ts` (`pandacode.inspector.tabs`, default Changes only); `renderInspectorTabs()` adds the tab for whatever `state.inspectorTab` became, so programmatic opens need nothing extra; the `+` menu lists closed views. Specs open a view first with `openInspectorTab()` from `tests/inspector-tab-helper.ts`.
- PandaCode updates itself from GitHub Releases: `src/app-updates.ts` (checks at launch and every 6 h, downloads in the background, installs with a restart only when no agent runs and the user has been idle; decisions in `src/app-updates-policy.ts`), the status-bar `#update-status` button, and Settings → About. Tauri's updater verifies each download against the public key in `tauri.conf.json`; releases carry signed update files and `latest.json` (`scripts/release/updater-manifest.mjs`). This is the only check of PandaCode's own; list any new automatic request in the README privacy table and the website privacy page.
- Menu bar item (`src-tauri/src/tray.rs`, Tauri `tray-icon`): a template panda icon titled with the running count. Left click toggles a popover window labelled `tray` (`?view=tray` → `src/tray-popover.ts` + `.css`, built like the launcher: transparent glass, hidden on blur or Esc, centered under the icon's click rect and clamped to the work area); right click is a native Open/Quit menu. Its webview may call only `tray_*` commands (allowlist in `lib.rs`, capability `capabilities/tray.json`); `tray::refresh` updates the title and emits `tray-changed`, on which the popover re-reads `tray_snapshot` and sizes itself with `tray_resize`. Native side `src-tauri/src/github_hub.rs` (`github_repos`, `github_repo_pulls`, `github_repo_issues` by `owner/name`; `github_project_repos` maps projects by `origin` remote; `github_clone_repo`). - Token saver (`src/token-saver.ts`, panel in `src/token-saver-panel.ts`): per-thread packs (Caveman Lite/Full/Ultra, Lean code, Quiet tools, RTK when `token_saver_tools` finds `rtk`) become one folded `Response style (PandaCode token saver…` block appended at send, only when the packs change and every `REMIND_EVERY` messages, so every harness gets it without paying for it each turn. - Local VMs (Apple silicon): `src-tauri/src/vm*` drives Tart (`vm/tart.rs`; one-click install of the notarized release in `vm/setup.rs`, team `9M2P8L4D89`) on Virtualization.framework. VMs run headless with `--vnc-experimental`; `vm/rfb.rs` is a small RFB client (that server answers only when the screen changed, so captures are incremental with a quiet window) and `vm/screen.rs` maps clicks, drags, scrolls, typing and key combos, scaling screenshots to 1280 px wide. Commands run through `tart exec` (Tart Guest Agent, no SSH). New VMs start right away, and a Linux VM without a desktop gets one in the background whenever PandaCode starts it (`vm/desktop.rs`). The panel draws frames on a canvas: the app CSP allows no `blob:` images, and `tests/vm.spec.ts` runs under that CSP. Linux guests start at 2 GB; idle VMs are suspended (macOS) or stopped (Linux) after `vm::IDLE`, and on quit. Agents get `pandacode_vm_*` tools (`vm/tools.rs`); the inspector's VM tab is `src/vm-panel.ts`, mocked in `src/preview-vm.ts`. Live tests are `#[ignore]`d and take `PANDACODE_VM`/`PANDACODE_VNC`.
- Cloud sandboxes and deploys live in `src-tauri/src/cloud*`. Machine IDs are `provider:native-id` (`daytona:`, `cloudflare:`, `aws:`, `agentcore:`), so the `pandacode_vm_*` tools and the VM panel route by prefix (`cloud::split`). Keys go through `secret_store.rs` (shared with bots, providers and connections: on macOS one 0600 `secrets.json` in app data, never the Keychain, with old Keychain items moved over once on first read; Secret Service/Credential Manager elsewhere) under `app.pandacode.cloud`; non-secret settings are one JSON value beside them (`cloud::Settings`). Daytona is REST (`cloud/daytona.rs`, toolbox computer use). Docker (`cloud/docker.rs`, non-keyed like AWS/gcloud) runs one task machine per name on a selectable engine (Docker, Podman (`--url` endpoints, `rm --ignore`, array JSON lists), Apple Containers, or the `lxc` LXD/Incus client — which uses its own configured remotes; ownership is the `pc-` name prefix there, labels elsewhere) and endpoint (local daemon, `unix://`, `ssh://` over the shared SSH transport, or TLS `tcp://` for Docker). VPS providers (DigitalOcean, Vultr, Hetzner, and RunPod pods) are plain Linux boxes over the shared SSH transport `cloud/ssh.rs`: one ed25519 keypair in the secure store (`vps_key`, materialized 0600 on use), system `ssh`/`scp`, trust-on-first-use known_hosts in app data, machines tagged/labelled `pandacode` (RunPod instead filters its unfiltered pod list by the `pc-` name prefix), per-machine addresses cached in `ssh::address_cache` with one refresh-and-retry (transport failures carry the `ssh::UNREACHABLE` marker), recycled addresses forgotten from known_hosts (port-aware). Cloudflare deploys `cloud/cloudflare_worker/` (Sandbox SDK 1.0 container Worker, bearer token, 10 min idle) with Wrangler; Cloudflare cannot list Durable Objects, so `cloudflare_sandboxes` remembers names. AWS uses the user's AWS CLI login: EC2 desktops via SSM only (no inbound ports; VNC on the instance's localhost, carried by an SSM port-forward in `cloud/aws_screen.rs`), and AgentCore code interpreters (`cloud/agentcore.rs` signs InvokeCodeInterpreter with SigV4 and reads the event stream). Deploys: `pandacode_cloud_cli` (`cloud/deploy.rs`, approval-gated) runs vercel, wrangler, railway, aws or gcloud in the checkout with credentials only in that process's environment and scrubbed from output (Vercel, Wrangler and Railway use an installed CLI or a pinned `npx` package fetched on first use, never bundled; Railway runs only deploy subcommands in `RAILWAY_ALLOWED`; aws and gcloud use only the user's installed CLI and login, with `aws_refusal`/`gcloud_refusal` and `scrub_aws`/`scrub_gcloud`); the header Deploy menu (`src/deploy.ts`) starts a task with a platform brief. Settings → Agents → Cloud sandboxes is `src/cloud-settings.ts`; preview mocks are in `src/preview-vm.ts`. HTTP tests use `cloud::http::mock`.
- Cloud agents ([docs/cloud-agents.md](docs/cloud-agents.md)): `src-tauri/src/cloud/sandbox.rs` is the `Sandbox` trait every provider implements (`cloud/<provider>.rs`; Railway and AgentCore can't host agents). `src-tauri/src/cloud_agents/` runs the ordinary provider pipeline over a remote transport: `transport.rs` swaps the harness for PandaCode's own binary in bridge mode (`bridge.rs`, `handle_cloud_bridge` in `main.rs`), which drives `runner.sh` on the machine through byte-acknowledged `inbox` appends and polled `out`; `resume.rs` re-attaches active runs (`sessions.cloud`, schema 27) at startup; `tasks.rs` holds the IPC, prepare/before/after-run steps; `setup.rs`, `credentials.rs` and `sync.rs` install the harness, copy logins and move git bundles to and from the task's mirror worktree. UI: `src/cloud-agents.ts`, the Run on menu in `src/remote-target.ts`, keyed provider forms in `src/cloud-settings.ts`; mocks in `src/preview.ts`/`src/preview-vm.ts`.
- Agents (`#agents-toggle`, `mountAgents()` in `src/action-dock.ts`): the team and subagent panels open from the dock's Agents item (panels group, `worktree` icon), never from floating triggers over the thread (the old `.architect-trigger`/`.subagents-trigger` stay in the DOM, `display:none`). The item is shown while the task has a team (`ArchitectView.present`) or subagents (`Subagents.present`), which announce changes with a `pandacode:agents` window event; its `.dock-badge` (accent fill, `--on-accent` text, popping in/out with the dock spring) counts running workers plus running subagents, and its name is `Agents: N running`. Both views' hosts live in `#agents-flyout`, one glass beside the dock in the header (left of it, aligned with the item; below the item in the row layout), with every panel present stacked inside. Hover opens it after 150 ms without taking focus; it stays while the pointer is on the item or the flyout and closes 300 ms after it leaves both (which also carries the pointer across the gap); click/Enter/Space pins or unpins it; Escape closes it (window capture, unless a dialog or another menu is above) and refocuses the item. A panel opened elsewhere (a transcript link, `openWorker`, the Subagents command) shows the flyout pinned; closing the last panel hides it. The item has no label bubble (`data-dock-notip`). Spec: the `Agents item` tests in `tests/action-dock.spec.ts`; preview hook `__previewSubagent(sessionId, data)`.
- Teams: the composer's Team button toggles an automatic team (`toggleTeam` in `main.ts`, `config.auto`), or, with Settings → Agents → Classic team setup (`src/team-mode.ts`, a per-window preference), opens the Architect & workers setup. Natively, `staff_from_roster` in `architect.rs` refuses any worker model outside a roster-only team.
- Model picker (`src/model-picker.ts`, styles in `src/model-picker.css`, loaded by `main.ts` and the launcher's `overlay-model-picker.ts`, whose own CSS only maps launcher tokens): a combobox search (always focused, `aria-activedescendant` into the listbox) over a 160px `role=tablist` rail (Recent from `pandacode.recent-models.*`, Teams, then each installed harness with its connections indented) and a listbox of one-line 28px rows for the viewed harness only. A query flattens rows across harnesses (teams first, then at most one `Use "x" with <harness>` row: the viewed harness, else the current one, if it takes custom IDs and the query names no harness; with no hits "No matching models." sits above it) and turns the rail into a hit map scrolled to the first hit; an overflowing rail fades at the bottom. Harnesses without a logo asset get a lettered `.provider-logo-tile`. Effort is a segmented `role=radiogroup` (`trackSegment()`, neutral `--fill-active` thumb (only the current model row carries the accent tint), `Default` first, a dot on the model's reported default); a named team shows "Set per worker". Keys: typing goes to search, ↑/↓ wrap, Home/End, ←/→ change harness while the query is empty, Enter picks, Tab cycles search → rail → effort and never closes, Esc clears the query and then closes. The rail collapses to logos below 520px. Preview: `?teams` seeds two named teams.
- Prompt attachments (images, documents, folders, sketches) live in `src/attachments.ts`; the mockup editor in `src/sketch.ts` is lazy-loaded from the `+` menu. Images ride the existing `imageIds` pipeline (`browser-captures/<uuid>.png`, four per message including screenshots); documents and folders become `Document context:` / `Folder context:` blocks. Sent context renders as read-only `.prompt-chip`s under the user's text (`src/message-attachments.ts` parses the blocks `CONTEXT_BOUNDARY` in `main.ts` splits; extend both when adding a block type): workspace files and documents open in a file tab, outside documents and folders are revealed with `reveal_path`, images show from the capture registry via `prompt_image` (image blocks carry an `Image ID:` line; captures are pruned after 7 days, then the chip shows the block's text), GitHub items open their https URL, and anything else (browser elements, unknown blocks) opens its raw text in a dialog. Bot briefs and token-saver notes stay hidden. A dropped item that cannot be attached (unreadable, unsupported, over a cap, imageless harness) is inserted at the caret as its quoted path instead, or for a browser File as its name with a note.
- Thread switching draws in one frame: `selectSession` shows the thread's remembered page (`threadPages` in `main.ts`, only pages whose messages belong to that thread) and redraws after the refresh only if the page changed; `markdown()` in `dom.ts` reuses formatted HTML by source text, so nothing reflows from raw text. The sidebar updates with `morph()` (`dom.ts`), which keeps unchanged rows and replaces any element whose `id`/`data-id` changed, so a click never lands on a row that changed task underneath it.
- Sidebar sections (`sidebarSections()` in `src/sidebar-sections.ts`, drawn by `renderNavigation`): Pinned first, then Active (running, approval/answer, a usage limit still in effect, or a failed/interrupted run you have not seen) and Finished (every other unpinned task that is not settled: review, pending, interrupted, board-staged and chats alike, however old, open or not, until you settle it; a turn that ended out of sight — another thread, another app, the board — is in `pandacode.sidebar.unreviewed` and its row shows unread until opened). There are only three states, Active, Finished and Settled, plus Pinned; no Chats or Tasks lists (`sections.rest` holds only Pinned, and an open thread never holds in a section it no longer belongs to). All projects never draws project folders; a chosen project lists its sections too. Active and Finished fold from their headings (one `section()` in `renderNavigation`; keys `active`/`review` in `pandacode.sidebar.collapsedSections`; `.section-fold` headings are roving stops). Settled (stage `completed`; there is no archive, and a task still `archived` from older data or a mirror counts as settled in `taskStage()`, its Reopen clearing the flag first; closed by default, `pandacode.sidebar.completedOpen`; 10 rows, then "Show 25 more") docked at the bottom of `#navigation`, above the Bots bar: the list is a flex column and `.completed-group` is `position: sticky; bottom: 0` with `margin-top: auto` (`sidebar-tree.css`), so its heading never scrolls out of sight; open, its rows scroll inside a panel capped at `clamp(84px, 100vh - 600px, 30vh)` (so Active and Finished keep about half the list) while the sections above scroll in the list (`renderNavigation` sets the list's `scroll-padding-bottom` to the dock's height so keyboard focus never lands under it). It stays inside `#navigation`, so morph, roving focus and every handler are unchanged. Membership never depends on the sort; Active and Settled have their own order (Active by latest start, Settled by completion, never `updatedAt`); Finished follows the Sort and view choice (Manual: never-arranged tasks newest first, then `sidebarOrder`) and is draggable under Manual. Running threads are always Active. However a thread is opened (click, ⌘1…9, ⌘⇧[ / ], board, palette), `selectSession` records the section its row was in (`sectionHold`, `sectionOf()`), and the open thread stays there, so a click on its row never moves it; once a held thread runs, the hold becomes Active: it stays there while open and goes to its section when you open another thread, never back to Settled. The open thread also stays listed in Settled past its first page (as `shownTasks` does for capped lists). Sorting lives in `src/sidebar-sort.ts` (pure, `tests/sidebar-sort.test.mjs`): the header's Sort and view menu (`showSidebarSort`, saved as `pandacode.sidebar.sort`) picks tasks Manual/Recent/Created and 3–15 tasks shown per section (Finished; one segmented row; Pinned is never capped). The stored `projects`/`group` fields still parse but are unused. Manual puts never-ranked tasks first, then `sidebarOrder`; natively a New task published by its first prompt takes rank 0 and shifts the others down once the sidebar has been arranged (`rank_published_drafts` in `storage.rs`, a TEMP trigger, so no schema change), so a later reorder never sinks it; `reorder_sessions` never ranks drafts. Pinned always keeps manual order; only Manual rows are draggable. With routing off, `profileId: "auto"` falls back to the lead's model rather than failing. The composer's Team button (`showTeamMenu` in `main.ts`) offers No team and, while routing is on, Cheap/Balanced/Best team, each setting the one global mode with `model_routing_configure` (a running auto team's label and next routed dispatch follow it) and turning on an automatic team (`setTeam`); main.ts caches one `RoutingStatus` (one shared in-flight `loadRouting()`, retried on focus and on render until loaded, at most every `ROUTING_RETRY_MS`; changes take a `routingTicket`, reads take none and land only if no change started since or is pending, so a read never overrides a change), and `src/model-routing.ts` announces each status it renders (newest request only) as a `pandacode:routing` window event so only the Team button updates. The lead's `profileId: "auto"` routes over the team's `catalog` (all models of installed harnesses, up to 1000, rebuilt when a team turns on), not the 24-entry roster; named agent teams stay within their roster. A fresh `auto` worker in Balanced is staffed on `route.ladder[0]` and in Cheap on the first rung whose lower bound clears min P (the opener; else, and in Best, the policy pick; `routing::staff`, note `ladder 1/N, opener; policy pick …`). Escalation: a dispatch assignment's `replaces: <worker ID>` (a worker that failed, or completed with a result that failed the lead's check; optional `replaceReason`; stopped/unfinished and already-replaced workers are refused) abandons that worker, and with `auto` routes with `failed` = the whole chain of models that failed the assignment (rebuilt from the saved `architect_requests` by `routing::failed_chain`, no worker field), so the pick never steps down; a chain of `routing::MAX_ATTEMPTS` (3) refuses any further replacement (auto or hand-picked) and tells the lead to report to the user; `route_models` returns `decidedBy` and the first 4 ladder rungs. Cards without data are unrated and never auto-picked. Model health (`model_health.rs`, docs/model-routing.md#unavailable-models-and-failover): harness errors pause a model per harness (saved in app data, two paused models pause the harness until a success), paused models never reach the router, and a failed team worker fails over to the same model on another harness; Settings lists them with Allow now.
