# /btw side threads

Type `/btw <question>` at the start of a prompt to ask something on the side while the task keeps working. It works whether the agent is idle or running: the message never joins the task's queue and never steers its run.

- **Where it runs.** A side thread is an ordinary task in the same project, harness, model and checkout, titled `BTW: <question>`. A task in a worktree gets its side thread by forking (`fork_session_at_message`), the only way to share that checkout; the copied transcript stays hidden in the panel. Tasks that run on another computer or a cloud machine, and bot conversations, cannot open side threads. Archived and completed tasks can: ask about finished work without reopening it. Attachments in the prompt are refused for `/btw`; remove them or send without it.
- **The panel.** The inspector's *By the way* tab (view `btw` in `src/inspector-tabs.ts`, opened and selected by `/btw`, closable like any tab; `src/btw-panel.ts`, styles in `src/btw.css`) shows the side thread's transcript with live streaming, its own prompt (Enter sends; the send button is disabled while the side agent answers, so nothing queues), a *Needs your input* note with *Open thread* when the side agent asks for approval or input, *New side thread*, *Open as full thread*, *Close*, and *Insert into main* on each answer. `/btw` alone opens the panel and focuses its prompt.
- **Referencing the main thread.** Every side-thread message carries a `Main thread context:` block (shown as a *Main thread context* chip that opens its raw text, via `src/message-attachments.ts`) built by `mainContext()` in `src/btw.ts`: the main thread's title and status, then its user and agent messages the side thread has not seen yet (the recent tail on the first message), plus its in-progress reply. It is capped at 24 KB, keeps the newest text, and says when older text was left out, including history older than the loaded page.
- **Links.** `localStorage['pandacode.btw']` maps each main task to `{ sideId, seenId, hiddenThrough? }`. Follow-ups reuse the linked side thread; a deleted or archived side thread is not reused (unarchiving it brings it back) and the next `/btw` starts a new one, and deleting the main task removes its link. Concurrent `/btw` sends for one task run one at a time, so they never create two side threads. Esc in the panel returns to the main prompt and never stops the main agent. The panel comes back with the main thread through the inspector's per-thread state.

Tests: `tests/btw.test.mjs` (parser and context builder) and `tests/btw.spec.ts`.
