# Model routing

Moved verbatim from `AGENTS.md`, which keeps a short summary of each bullet. Paths and links below are relative to the repository root.

- Model routing ([docs/model-routing.md](../model-routing.md)): Panda Router (v4) runs natively (`src-tauri/src/panda_router.rs` + `panda_router/`: ONNX int8 profiler via `ort`, `tokenizers`, deterministic MIRT matcher over model cards, success head, policy with an escalation ladder; `model_routing.rs`: settings, download, IPC; `src/model-routing.ts`). The profiler files come from `raw.githubusercontent.com` at a pinned commit of `aicodeking/PandaOrchestrator` and are sha256-verified; bumping the commit means updating the hashes (in `ASSETS` and the CI `router` job) and `panda_router::ASSET_DIR`, with the old directory added to `OLD_ASSET_DIRS` in `model_routing.rs` (deleted once the new files load). Settings default to Balanced with min P 0.5 (clamped 0.3–0.9, on P's lower bound); `Settings.version` marks files saved since v4, and in an older file a saved 0.8 (the old default) becomes 0.5. Download happens only while routing is on, when a team turns on or first routes, or on an explicit Settings click, never at launch, and never on macOS < 13.4 (`unsupported_os`; the bundled ONNX Runtime targets 13.4); `ort`/`tokenizers` link only where `cfg(panda_onnx)` holds (Apple-silicon macOS, arm64 Linux, Windows; same predicate in Cargo.toml and `build.rs`), so Intel Mac and x86_64 Linux builds use `panda_router/onnx_stub.rs` and the heuristic, and CI's macOS `router` job checks tokenizer ids and well-formed ONNX output (numeric parity varies by CPU, so it is opt-in with `PANDA_ROUTER_STRICT=1`); a profiler that verifies but cannot load stays on the heuristic for the process (`unusable`), with no re-downloads; dispatch and `route_models` never wait for it and use the keyword heuristic until it is ready. With routing off, `profileId: "auto"` falls back to the lead's model rather than failing. The composer's Team button (`showTeamMenu` in `main.ts`) offers No team and, while routing is on, Cheap/Balanced/Best team, each setting the one global mode with `model_routing_configure` (a running auto team's label and next routed dispatch follow it) and turning on an automatic team (`setTeam`); main.ts caches one `RoutingStatus` (one shared in-flight `loadRouting()`, retried on focus and on render until loaded, at most every `ROUTING_RETRY_MS`; changes take a `routingTicket`, reads take none and land only if no change started since or is pending, so a read never overrides a change), and `src/model-routing.ts` announces each status it renders (newest request only) as a `pandacode:routing` window event so only the Team button updates. The lead's `profileId: "auto"` routes over the team's `catalog` (all models of installed harnesses, up to 1000, rebuilt when a team turns on), not the 24-entry roster; named agent teams stay within their roster. A fresh `auto` worker in Balanced is staffed on `route.ladder[0]` and in Cheap on the first rung whose lower bound clears min P (the opener; else, and in Best, the policy pick; `routing::staff`, note `ladder 1/N, opener; policy pick …`). Escalation: a dispatch assignment's `replaces: <worker ID>` (a worker that failed, or completed with a result that failed the lead's check; optional `replaceReason`; stopped/unfinished and already-replaced workers are refused) abandons that worker, and with `auto` routes with `failed` = the whole chain of models that failed the assignment (rebuilt from the saved `architect_requests` by `routing::failed_chain`, no worker field), so the pick never steps down; a chain of `routing::MAX_ATTEMPTS` (3) refuses any further replacement (auto or hand-picked) and tells the lead to report to the user; `route_models` returns `decidedBy` and the first 4 ladder rungs. Cards without data are unrated and never auto-picked. Model health (`model_health.rs`, docs/model-routing.md#unavailable-models-and-failover): harness errors pause a model per harness (saved in app data, two paused models pause the harness until a success), paused models never reach the router, and a failed team worker fails over to the same model on another harness; Settings lists them with Allow now.
