# Remote access (PandaCode Connect) and machine orchestration

Moved verbatim from `AGENTS.md`, which keeps a short summary of each bullet. Paths and links below are relative to the repository root.

- Remote access, PandaCode Connect ([docs/remote-access.md](../remote-access.md)), is opt-in: there is no network traffic until GitHub sign-in (device flow). The relay is `relay/`, a Cloudflare Worker with one SQLite Durable Object per account, hibernated WebSockets, and GitHub app-checked sign-in. It forwards only X25519 + XChaCha20-Poly1305 ciphertext. The native side is `src-tauri/src/remote*`: a host answers only devices in its account's presence, and only while "Allow remote control" is on (no per-device pinning; Full access for remote tasks is a separate, default-off host setting). The relay token and device key live in `connect-secrets.json` (0600, `remote/secrets.rs`), never the keychain: macOS re-prompts for keychain items after every unsigned update. `secret_store.rs` shares its file code (`load`/`update`: 0600 temp, fsync, rename, lock file). Requests, responses and events carry `ts`/`nonce` against replay. A task can *run on another computer* as a mirror: an ordinary local session row with `remote_device`/`remote_session`/`remote_synced_id` (schema 26), started by `remote_start_task` (host side `remote/start.rs` finds or clones the GitHub project into `~/PandaCode`). Agent commands for a mirror (`send_message`, `stop_session`, approvals, input, `steer_task`, model/effort) are routed natively by `remote::route`; the queue stays local. Hosts push raw `AgentEvent`s (`agent.events`, one frame per subscriber per 100 ms, text deltas merged, then `run.finished`), which the viewer re-emits as `agent-event` under the local id, and messages are copied with `task.messages` after each run (`remote/mirror.rs`). `Store::workspace_root` refuses a mirror (`This task runs on <name>.`), so git, worktree and file commands never touch the local disk. There is no remote view. Machine orchestration ([docs/machine-orchestration.md](../machine-orchestration.md), off by default) lets agents link other computers (`Settings.links`) and launch mirrors as child threads (`machine_threads`) through `pandacode_machine_*` tools in `remote/orchestrate.rs` (composed by `with_machines` beside `with_vm`, never for team tasks; `machine_launch` and `machine_message` ask for approval unless the task runs in Full access, like every PandaCode host tool; the link's access still caps the child thread's mode, and a Read-only link refuses them; `machine_stop` never asks); `mirror::commit` is the one start path for both `remote_start_task` and `machine_launch` and re-checks the link and parent mode at the commit point (`commit_mode`), and settled threads wake their idle parent once with a `MachineThreads` app-origin turn (`launch_app_turn` in `lib.rs`), claimed under the run's admission lock and marked reported in the turn's own transaction (`Store::begin_task_turn_reporting`); due wakes retry at run end, reopen, startup and re-enable (`orchestrate::reconcile`). Every machine tool answers within 45 s (harness tool calls time out at 60 s): link requests live 10 min in `links.rs` apart from the call (an answer nobody waited for wakes the task with a `MachineLink` turn), and `machine_launch` commits the row and spawns `mirror::start` in the same step (`mirror::commit`); a machine thread's `startId` is its own id, so its lost reply follows main's `task.startStatus` path and a start a quit cut off is followed up again after restart (`mirror::load_starts`; `Store::open` keeps such rows instead of turning them back into drafts); a stop while starting ends the thread here at once and sends `task.cancelStart`, and a failed start keeps the thread as `error` (`fail_start`, from `mirror::not_started`). A link counts only while the device hosts and still has the key it was linked under (`Link::key`). Wakes are at-least-once: a wake turn that never reached its agent (no assistant or tool message after it) gives its claim back (`orchestrate::restore_wake`, at run end, on a failed prepare and at startup in `recover_wakes`). A parent interrupted by a restart can be woken; one the user stopped cannot, even after a quit right after Stop (`stop_requested`). Machine approvals wait at most `orchestrate::APPROVAL_WAIT` (240 s) on both the MCP host and Codex dynamic tools (`expire_approvals`), and the MCP host ends a call whose client closed the connection, so a late Approve runs nothing. `remote.json` saves take turns under `Remote::saving` and write the current state.
 The UI is `src/remote*.ts`, with mocks in `src/preview-remote.ts`. Builds need `PANDACODE_RELAY_URL` and `PANDACODE_GITHUB_CLIENT_ID`.
