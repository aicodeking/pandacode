# Sidebar sections

Moved verbatim from `AGENTS.md`, which keeps a short summary of each bullet. Paths and links below are relative to the repository root.

- Sidebar sections (`sidebarSections()` in `src/sidebar-sections.ts`, drawn by `renderNavigation`): Pinned first, then Active (running, approval/answer, a usage limit still in effect, or a failed/interrupted run you have not seen) and Finished (every other unpinned task that is not settled: review, pending, interrupted, board-staged and chats alike, however old, open or not, until you settle it; a turn that ended out of sight — another thread, another app, the board — is in `pandacode.sidebar.unreviewed` and its row shows unread until opened). There are only three states, Active, Finished and Settled, plus Pinned; no Chats or Tasks lists (`sections.rest` holds only Pinned, and an open thread never holds in a section it no longer belongs to). All projects never draws project folders; a chosen project lists its sections too. Active and Finished fold from their headings (one `section()` in `renderNavigation`; keys `active`/`review` in `pandacode.sidebar.collapsedSections`; `.section-fold` headings are roving stops). Settled (stage `completed`; there is no archive, and a task still `archived` from older data or a mirror counts as settled in `taskStage()`, its Reopen clearing the flag first; closed by default, `pandacode.sidebar.completedOpen`; 10 rows, then "Show 25 more") docked at the bottom of `#navigation`, above the Bots bar: the list is a flex column and `.completed-group` is `position: sticky; bottom: 0` with `margin-top: auto` (`sidebar-tree.css`), so its heading never scrolls out of sight; open, its rows scroll inside a panel capped at `clamp(84px, 100vh - 600px, 30vh)` (so Active and Finished keep about half the list) while the sections above scroll in the list (`renderNavigation` sets the list's `scroll-padding-bottom` to the dock's height so keyboard focus never lands under it). It stays inside `#navigation`, so morph, roving focus and every handler are unchanged. Membership never depends on the sort; Active and Settled have their own order (Active by latest start, Settled by completion, never `updatedAt`); Finished follows the Sort and view choice (Manual: never-arranged tasks newest first, then `sidebarOrder`) and is draggable under Manual. Running threads are always Active. However a thread is opened (click, ⌘1…9, ⌘⇧[ / ], board, palette), `selectSession` records the section its row was in (`sectionHold`, `sectionOf()`), and the open thread stays there, so a click on its row never moves it; once a held thread runs, the hold becomes Active: it stays there while open and goes to its section when you open another thread, never back to Settled. The open thread also stays listed in Settled past its first page (as `shownTasks` does for capped lists). Sorting lives in `src/sidebar-sort.ts` (pure, `tests/sidebar-sort.test.mjs`): the header's Sort and view menu (`showSidebarSort`, saved as `pandacode.sidebar.sort`) picks tasks Manual/Recent/Created and 3–15 tasks shown per section (Finished; one segmented row; Pinned is never capped). The stored `projects`/`group` fields still parse but are unused. Manual puts never-ranked tasks first, then `sidebarOrder`; natively a New task published by its first prompt takes rank 0 and shifts the others down once the sidebar has been arranged (`rank_published_drafts` in `storage.rs`, a TEMP trigger, so no schema change), so a later reorder never sinks it; `reorder_sessions` never ranks drafts. Pinned always keeps manual order; only Manual rows are draggable. The filter field (`#sidebar-filter`, Esc clears; `/` focuses it from the task list or anything that is not a control, never while typing, and is left alone when the field is hidden: narrow windows hide it, and so does the Bots panel, which has its own search) sets `state.query`, matches title, branch, PR/issue and project, and while set shows matches in folded sections, closed Settled and past every cap; heading clicks then change nothing, so nothing is saved; with no match the list says "No tasks match". Rows: two-line cards in Active, Finished and Pinned (one line under a chosen project, and in Settled); needs-you states show a word (Approval, Answer, Failed, `Limited · <reset>`), unread rows a dot and bold title. Each row is `.task-row#task-row-<id>` holding `.task-item` plus sibling `.task-actions` buttons (`data-task`, never `data-id`, `tabindex=-1`) that cover the status/age slot behind a solid `--row-bg`, the row's own hover/focus/selected background (the title never shrinks): tick and a … menu (`showSidebarTaskMenu`, four groups: pin/move — moves only where rows can move — · rename (by id, without opening)/read/new task from the branch · copy branch/path/ID · Settle or Reopen/delete). Remove project lives in Settings → Projects. The list is one Tab stop (`syncRovingFocus` in `thread-order.ts`): ↑/↓/Home/End move, →/← open and close headings, ⌘↩ ticks, Shift+F10 opens the menu; ⌘1…9 and ⌘⇧[ / ] (never while typing in a field). Undo (toast or ⌘Z) after settling (restoring the exact stage and unread mark; native `set_task_stage` allows `in_progress` only to undo settling a stopped/failed run) and unpin. Menus (`choice-menu.ts`) are the `--glass-*` material (solid under reduced transparency/contrast), take `heading`/`separator` items and `segment`/`short` items for one-row segmented choices (← → step along them), and mark the current choice with a trailing check (one rule in `styles.css`; model and project menus keep their fill). Preview samples: `?sections`; specs `tests/sidebar-sections.spec.ts`, `tests/thread-order.spec.ts`, `tests/sidebar-keyboard.spec.ts`.
