# Headless host

Moved verbatim from `AGENTS.md`, which keeps a short summary of each bullet. Paths and links below are relative to the repository root.

- Headless host ([docs/headless.md](../headless.md)): `pandacode serve` (dispatched in `main.rs`, `handle_serve`) runs the same app on an always-on server with no window and no frontend — `setup_common` in `lib.rs` is the desktop startup minus GUI (overlay/tray/appearance/VM watch), `on_run_event` is the shared exit handler (a window close never stops serve; SIGTERM/SIGINT do, with the same 12 s agent deadline), and both build paths share one `app_context()` because a second `generate_context!` re-embeds the Info.plist static. `src-tauri/src/headless.rs` holds the CLI (`--sign-in` device flow on stdout via `remote.rs`'s headless helpers, `--sign-out`, `--full-access`, `--device-name`) and the native twins of the window's real jobs: queue drain (`drain_queue`, mirroring the bot gateway and frontend `dispatchQueue`), pull-request links and limit resumes (`Store::due_limit_resumes`) at run end / on a timer, and a fail-fast for app-action tools. Frontend behaviors with real effects need a native twin there — see the docs checklist. `drain_queue` is sync-on-purpose (spawns internally): awaiting the send chain through a second async fn trips a rustc Send-resolution ambiguity. `PANDACODE_SECRETS_FILE=1` (set by serve by default) selects the macOS-style 0600 file backend on Linux/Windows too (`secret_store::file_mode`). Bots are configured headlessly with `serve --import-bots <file>` (or dumped with `--export-bots`): `headless_bots.rs` deserializes each entry straight into the UI's `BotInput`/`ChannelInput`/`ScheduleInput` and applies through the same constructors (`bots::create/update/set_capabilities`, `channels::add`, `schedule::create`, `guard::add_rule`), matching by name/kind+label/title/pattern so re-applying converges; the wiring then starts added channels live via `channels::start` (channel loops snapshot config at boot, so hand-written rows need a restart).
