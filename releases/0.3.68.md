# Router-first teams, automatic failover, and model switches

## New

- **Panda Router first.** Team leads now send every assignment through Panda Router by default. An assignment that names no model is routed too while routing is on. A lead picks a model itself only when you name one, and uses its own model only when routing has nothing left.
- **Same model, another provider.** When a worker's harness fails (for example GPT-6.1 Sol through Command Code), the worker moves to the same model on another installed harness and runs again on a fresh session. The lead sees a "Failover:" note with the real error.
- **Unavailable models.** A model whose harness errors is paused on that harness for 10 minutes, doubling up to 2 hours. Two paused models pause the whole harness until something on it succeeds. Paused models never reach Panda Router or the lead's roster, and the pauses survive a restart. Settings → Model routing lists them with the time left, the reason, and **Allow now**.
- **Models for teams.** Settings → Model routing has a switch for each installed harness and each of its models. Switched-off models are never picked for team workers, by the router, profiles, fallbacks or failover. A model the lead is explicitly asked to use still runs.

## Fixed

- A failed run no longer counts as a weak result, which used to rule that model out on every harness. Only results that fail review escalate to a stronger model.
- PandaCode's own errors (setup, attachments, saving, a cancelled launch) never pause a model. Only harness failures do.
- Failovers count toward an assignment's three attempts but never use up a worker's follow-ups.

## Known limitations

- After a failover the worker starts over from its original prompt. Changes it already made stay in the checkout, but its earlier conversation does not carry over.
- Failover happens for team workers. A failed ordinary task pauses the model for future routing but does not switch harness by itself.
