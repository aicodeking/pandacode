# Remote tasks in busy projects, and remote subagents and teams on the desktop

## New

- **Start a task on another computer even while an agent works in that project.** If the project's main folder on that computer is busy, has uncommitted changes or is on another branch, the task now starts in a new worktree instead of failing, and the desktop and phone say so in one line (for example "Started in a worktree: Studio has an agent working in orbit."). The busy folder is never touched. Two tasks started at the same moment never share the main folder.
- **Subagents and team workers show on the desktop that started a remote task.** Running subagents appear live and stay after a reconnect or when the run ended while you were offline. An architect team running on the other computer shows its workers, their status, model, current step and transcript, read-only.

## Fixed

- Sending or steering a message to a remote task that is still starting queues it instead of showing "still starting".
- A start that fails or is cancelled late no longer leaves a worktree or a stopped task behind on the other computer.
- The worktree note still appears if the start's reply was lost and the task connected later.
- Long worker transcripts load from the newest message and page back correctly.

## Known limitations

- The other computer needs this version for the worktree fallback and for teams on the desktop; older versions keep their previous behaviour.
- Team workers on a remote task are read-only on the desktop, and their transcripts refresh when the team changes rather than streaming live.
