# Faster model and harness switching

## Added

- **Warm agent spares.** PandaCode starts an idle agent ahead after a reply finishes, on a model, harness, effort, or permission pick in a local task, and when you begin typing a draft. At most two idle spares are kept across all harnesses and expire after 10 minutes.
- **Live Claude Code switches.** Picking an explicit model, reasoning effort, or non-**Full access** permission mode updates a waiting Claude Code process over its control channel without restarting it, and falls back to a fresh start if refused.
- **Background handshake and Codex thread preloading.** **Codex** and supported Agent Client Protocol (ACP) harnesses (**Kimi**, **OpenCode**, **Grok**, **DeepSeek**, **Command Code**, **Kilo**, **GitHub Copilot**, **Devin**, and **Hermes**) spawn and complete `initialize` ahead of your prompt, keyed to your working folder, environment, and watched login or configuration files. Local Codex tasks with an existing conversation also preload `thread/resume` without sending a turn.
- **Cold-launch racing and cancellation.** Sending a message while a handshake spare is still starting races it against a cold launch after a short grace window so a slow spare never holds up a turn. Superseded, discarded, or disabled starts cancel immediately and terminate their process groups.
- **Start agents ahead setting.** **Settings → Agents → Start agents ahead** (on by default) controls all background agent preparation; turning it off stops any starting or waiting spare right away.

## Changed

- **Instant model, harness, effort, and permission picks.** Composer choices show immediately and save in the background. Effort changes queue in order without blocking model rows or further effort picks. Re-picking the same harness and model keeps your chosen reasoning effort; switching to another model or harness resets effort to **Default** (and switching harnesses keeps automatic teams when moving to **ZCode**).
- **Cached model and team catalogs.** Hovering or focusing the model button preloads the picker, and model and team lists open immediately from a 5-minute cache while refreshing in the background. Failed refreshes keep the saved list with a **Couldn't refresh** note and wait 30 seconds before retrying, updates wait while the pointer rests over the model list so rows do not jump, and **Esc** ignores active IME composition.
- **Held sends and draft preservation.** Sending from the main composer or `/btw`, starting from the board, continuing past a usage limit, **Keep fixing** in Council, and reopening **Model** or **Permissions** wait for an in-flight preference save before acting. If a save is refused, PandaCode restores the previous setting, keeps your typed draft unsent, and shows what could not be changed.

## Privacy

- **Local CLI preparation only.** When **Start agents ahead** is on, PandaCode starts only the agent CLIs you installed and selected, and sends no user prompt (local Codex tasks with a saved thread load that conversation ahead without sending a turn). Starting a CLI can still connect to its provider and run startup hooks, plugins, or MCP servers from your own configuration; **Turn off agent telemetry** still applies. Model catalog caching keeps lists in memory only and never polls in the background.

## Known limitations

- Warm spares are not started for key-based Claude Code relays (**GLM Coding Plan**, **MiMo Token Plan**, **Alibaba Token Plan**), **Antigravity**, **Cline**, **Cursor**, **ZCode**, **Muse**, **Pi**, or **omp**, nor for cloud tasks, Connect remote mirrors, agent-team leads and workers, `/btw` side-thread picks, or skill, `/goal`, `/compact`, and `/review` turns.
- Switching a waiting Claude Code spare to or from the `default` model alias, into or out of **Full access**, or across fast-mode or conversation changes restarts the spare instead of updating it in place. OpenCode 2.x sign-ins stored in `opencode.db` are not watched by file key.
- Verified locally with TypeScript unit tests, Rust library tests against local fake-CLI harnesses, and Chromium Playwright browser tests. End-to-end wall-clock switching latency against live provider servers has not been benchmarked, and desktop platform installers were not built or tested on native machines before CI.
