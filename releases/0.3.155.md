# Faster SQLite database operations

## Improved

- **Faster startup and everyday database operations.** New indexes and the `running_tools`, `running_subagents`, and `architect_team_meta` trackers keep activity and team lookups fast. SQLite uses an 8 MiB page cache and in-memory temporary storage (`temp_store = MEMORY`) during normal operation, caps retained journal size with `journal_size_limit`, and caches more prepared statements through expanded use of `prepare_cached`.
- **Less time holding the database lock.** The changes cover startup, the sidebar, opening threads, transcript search, the prompt-activity calendar, team and watchdog rollups, schedules, attachments, bot activity, and Connect mirror operations. Of 54 paired benchmark cases, 45 were faster, 4 showed write trade-offs, and 5 were neutral. [Database benchmarks](https://github.com/aicodeking/pandacode/blob/v0.3.155/docs/db-benchmarks.md)

## Upgrade and compatibility

- **First launch installs the indexes and trackers once.** The paired benchmark on the earlier schema-38 build measured about 1 second of setup time on a 218 MiB database, with roughly linear scaling across the two tested sizes. PandaCode 0.3.155 runs the same additive index and tracker setup synchronously while keeping `PRAGMA user_version = 37`. It installs `running_tools`, `running_subagents`, and `architect_team_meta` and removes the superseded `architect_team_status` table and triggers from 0.3.133–0.3.154 and the unused `turn_changes_retained` index. Setup uses a 64 MiB page cache and file-backed temporary storage (`temp_store = FILE`) so large databases can spill index sorts to disk and avoid running out of memory. [Migration timings](https://github.com/aicodeking/pandacode/blob/v0.3.155/docs/db-benchmarks.md#7-migration-at-two-scales)
- **Rollback to 0.3.151–0.3.154 is supported without data loss.** The upgrade preserves all existing projects, threads, messages, teams, bots, schedules, attachments, and settings. After rollback, both writable startup and read-only lookups for the Usage prompt calendar and project-scoped Skills continue to work.
- **Newer database schemas are preserved.** For `user_version > 37`, PandaCode skips all persistent schema and index DDL, leaving the on-disk schema intact. Workspaces using custom sidebar ordering may create a connection-local `TEMP` trigger. Startup runs best-effort recovery against base tables.

## Known limitations

- **Some writes take longer.** Deleting a project and its associated data (`delete_project_cascade`), batched remote-mirror subagent writes, and saves of small team snapshots were slower in the benchmarks.
- **Malformed team snapshots block affected operations.** Agent updates and project removal fail closed when a team snapshot cannot be parsed. Valid JSON and JSON5 snapshots continue to work.
- **Bot activity logs are trimmed periodically.** A log can briefly exceed its row cap between trims.
- **SBOM scan coverage.** Desktop runtime dependencies are unchanged from v0.3.151–v0.3.154. The v0.3.154 release notes record 0 Critical and 0 High findings in the desktop lockfile SBOM scans, with 2 Medium and 3 Low findings in Rust and 6 Low findings in npm. They also record that the four compressed macOS DMG and Linux AppImage installers remain `not-scanned` and that the Windows setup and macOS updater inventories cover package metadata. [SBOM-COVERAGE.json](https://github.com/aicodeking/pandacode/releases/download/v0.3.155/SBOM-COVERAGE.json), [SBOM-COVERAGE.md](https://github.com/aicodeking/pandacode/releases/download/v0.3.155/SBOM-COVERAGE.md)
