# Skill updates that fail cleanly

## Fixed

- **Skills library: an update never lands on a file of yours.** When an update to an active skill would add a file at a path where you already keep one, PandaCode now refuses before writing anything: `<path> already exists and PandaCode did not write it; move it away and try again.`
- **A failed update puts the previous version back.** If an update stops partway (for example on a full disk), the files it created are removed and the previous version of the skill is restored, in a project and in your home folder alike. A file someone else changed in the meantime is left alone, and anything that could not be put back is named in the error.
- **Turning a skill off only removes Git exclude lines PandaCode wrote for it.** A line in an activation's record that isn't one PandaCode would build for that skill's own folder or rule file (for example `/src/` in an edited record) is now left in the exclude list and logged. Lines for the skill are still removed when a skills-folder link was replaced by a real folder since it was turned on.
- **A `.git` set up to point PandaCode elsewhere is not trusted.** A project whose `.git` links to a nested repository's Git folder, or whose Git settings (`core.worktree`) move its top level above the project, no longer gets an exclude line.
- **No empty folders left behind** after an update that drops files in a subfolder, or for a skill that has its own `skills` subfolder. They used to block turning the skill on again.
- **Your home folder:** a skill or rule file is now opened without blocking and must be a regular file before PandaCode rewrites it.

## Known limitations

- Exclude lines written in the old (0.3.114) format for a project opened at a subfolder of its repository are left in place, so a line you added yourself at the repository root is never removed by mistake.
- Checked with Rust unit tests. In CI the Skills tests run on Linux only; the case-only rename test runs only on a case-insensitive disk (macOS). Not clicked through by hand in the built app.
- In your home folder, skill and rule files are still rewritten in place and links are still followed, as before.
