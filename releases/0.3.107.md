# A Skills manager for every agent

## New

- **Settings → Tools → Skills** lists every skill installed for every agent, with a chip per agent. When an agent's app isn't installed, its chip names it.
- Switch between **All projects** and each project to see that project's own skills. The page opens on the project of the thread you came from.
- Turn a skill off for one project, or for all of PandaCode, with one switch. The skill's files are never touched. Agents PandaCode runs follow the switches from the next turn. Where an agent can only be asked not to use a skill, the row says **May still load**.
- **Add skill** installs from a GitHub, GitLab or skills.sh link, or a local folder, through a pinned version of the Vercel Skills CLI (`skills@1.7.6`) with its telemetry off. New skills are safety-scanned first: flagged copies are quarantined (with **Restore**) or switched off until you review them.
- **Uninstall** removes a skill's copies in the view you're in, with **Undo**.
- Typed, steered, queued and picked slash commands, and bot workspaces, all respect the switches.

## Changed

- **Rules & library** now holds rules and a read-only bot library ("Install for agents…"). The old skill catalogs have been removed; add skills from the Skills page instead.

## Known limitations

- Codex, OpenCode and Claude-family harnesses are blocked from using a switched-off skill. Other harnesses are only asked not to use it, and some consoles can't be told at all.
- If several agents' apps are missing, their chips can crowd a row's project chip at narrow widths.
- Quarantine, uninstall and Undo across drives have been tested on macOS only. Windows and Linux runs, and live installs through the Skills CLI, have not been exercised.
- Packaged native installers have not been manually exercised on real hardware for this release.
