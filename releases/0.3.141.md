# Google Colab integration and live runtime indicator

Not published as a standalone GitHub Release; all changes below shipped in 0.3.142.

## Added

- **One-click Google Colab sign-in and settings.** Connect Colab in Settings → Connections → Cloud sandboxes with **Sign in with Google**. This uses Google OAuth2 with the Colab CLI's client or your own Google Cloud OAuth client JSON. If no local Colab CLI OAuth client is installed and you don't supply your own OAuth client JSON, the first click installs Google's pinned `google-colab-cli==0.8.0` with `uv`, so that path needs `uv` (your own OAuth client JSON or `gcloud` avoid it). **Use gcloud ADC** signs in with `gcloud` instead: it runs `gcloud auth application-default login`, which rewrites the shared gcloud Application Default Credentials file other tools on this machine also use, and requests the broader `cloud-platform` scope. Pick the default hardware (CPU, a T4, L4, G4, A100 or H100 GPU, or a v5e-1 or v6e-1 TPU) and turn on High-RAM where Colab offers it. The card shows your Compute Unit balance and what the chosen hardware uses per hour. Native Colab tools and Google's `colab-mcp` each have their own switch. Tokens stay in PandaCode's private secret store and never reach the webview.
- **Cloud agents and VM tools on Colab.** Choose **Google Colab** in New task → **Run on** to run a task on a Colab runtime with the hardware from Settings. Colab runtimes also appear in the VM panel and to the `pandacode_vm_*` tools.
- **Native Colab tools and optional `colab-mcp`.** With the native `pandacode_colab_*` tools on, agents can:
  - see active runtimes and compute units (`pandacode_colab_status`);
  - run Python or a checkout `.py`/`.ipynb` file on a persistent Jupyter kernel, with plots returned inline as PNG images (`pandacode_colab_run_python`);
  - run shell commands over SSH (`pandacode_colab_exec`);
  - list, upload, download and delete runtime files (`pandacode_colab_files`);
  - create, stop or restart runtimes, or open one in the browser (`pandacode_colab_manage`).

  Creating a runtime spends compute units, so PandaCode always asks first, even in Full access mode. Google's `colab-mcp` is separate from these native tools: it connects agents to the Colab notebook you have open in your browser. It runs from a pinned commit with `uvx`, so it needs `uv` installed. When it is on, PandaCode adds it to each local run for the harnesses that support it, without changing the harness's own MCP configuration.
- **Floating thread runtime indicator.** A small indicator in the conversation pane lists each Colab runtime the thread is using, whether it came from native tools, VM tools or a Cloud Agent. Each runtime has a live stopwatch or uptime clock, and expanding it shows a detail card with:
  - **Open in Colab** and **Refresh**;
  - **Restart kernel** and **Stop**, each confirmed inline;
  - **Dismiss** for errored, stopped or pending runtimes.

  Thread–runtime links survive an app relaunch. The indicator works fully with the keyboard and screen readers, and in Increase Contrast and forced-colors modes.

## Known limitations

- Verified locally on macOS (Apple silicon) with Chromium, WebKit, Rust unit tests, strict Clippy and the website build. Cross-platform CI (Linux, Windows and macOS checks, release builds and their startup smoke checks) was completed with 0.3.142, which ships these changes.
- Colab runtimes are ephemeral. An idle runtime is held for roughly 90 minutes before it expires, and stopping a runtime discards its unsaved files and kernel state.
- Colab sign-in and runtime actions were tested locally against loopback mocks. Live GPU and TPU quotas, runtime idle timeouts and OAuth client availability depend on your Google Colab account and tier.
