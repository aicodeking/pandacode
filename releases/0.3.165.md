# Safer SQLite recovery for existing installs

## Fixed

- **Corrupt JSONB stays out of recovery queries.** Tracker triggers, startup recovery, team queries, project removal, agent-update checks, and profile initialization now validate JSON5 text with `json_valid(..., 2)` in place of the permissive flag `6`. Opening a database from `0.3.156`–`0.3.164` automatically replaces older tracker triggers with the corrected definitions.
- **Recovery preserves mixed arrays and numeric precision.** When interrupting saved teams or settling subagent tools, SQLite keeps non-object entries and updates the status of the applicable objects. Reading array values as JSON with `json(content -> fullkey)` preserves signed and unsigned 64-bit integers and high-precision decimals. JSON5 literals are normalized to JSON without rounding through floating-point values.
- **Team snapshots repair dangling tracker triggers atomically.** The snapshot writer rechecks the schema version and whether `architect_team_meta` exists inside an immediate transaction before dropping dangling triggers. Persistent repair requires `PRAGMA user_version <= SCHEMA_VERSION` (currently `37`), protecting newer databases, including `v39` and later.
- **JSON5 team snapshots behave consistently during fallback.** Status lookups, active-team discovery, and runnable-team queries accept valid JSON5 in the same way when tracker data is available or when the app falls back to saved snapshots.
- **A malformed row no longer blocks shared-channel recovery.** Queued deliveries and recovery posts isolate row-decoding errors so healthy deliveries and posts can still be processed.
- **Existing-install upgrade coverage runs in the regular SQLite test suite.** Eight version fixtures exercise upgrade, rollback with writes, and re-upgrade. The matrix checks automatic trigger repair, preservation of saved data, `PRAGMA integrity_check`, and `PRAGMA foreign_key_check`.

## Upgrade and compatibility

- **Sequential rollback.** `PRAGMA user_version` stays at `37` for rollback to `0.3.151`–`0.3.164`. Quit one version before opening another against the same data directory. Concurrent use is unsupported. In the tested concurrent-write scenario, the `0.3.152` write rolled back cleanly and left the database intact.
- **Direct upgrade from `0.3.154` or earlier.** First launch runs the one-time additive index and tracker setup introduced in `0.3.156`. [Migration timings](https://github.com/aicodeking/pandacode/blob/v0.3.164/docs/db-benchmarks.md#7-migration-at-two-scales)

## Known limitations

- **SBOM scan coverage.** The release workflow publishes `SBOM-COVERAGE.json` and `SBOM-COVERAGE.md` alongside the installers when the reports are generated. The macOS `.dmg` and Linux `.AppImage` containers are reported as incomplete and unscanned. The workflow scans identifiable package metadata from Windows installers and macOS updater archives, plus the Rust and npm lockfile inventories. The published reports record the actual coverage for this release. [SBOM and scan coverage](https://github.com/aicodeking/pandacode/blob/v0.3.164/docs/releasing.md#sboms-and-scan-coverage)

## Verification

- **Automated SQLite fixtures.** The matrix represents `0.3.151`, `0.3.152`, `0.3.153`, `0.3.154`, `0.3.156`, `0.3.157`, `0.3.158`, and `0.3.161`. It uses SQLite databases and SQL representing the historical versions. Manual launches of historical GUI installers were outside this verification.
- **Local macOS (Apple silicon).** The local checks cover the desktop build, Node and release-script tests, the website build, Clippy, and targeted Rust tests for storage, teams, bots, project removal, and agent updates.
- **GitHub Actions and packaged platform checks.** The eight-job main-push CI covers Rust library tests, per-platform Clippy, TypeScript and Node tests, the website build, and macOS ONNX parity. The release workflow builds all six targets and requires signing, notarization, stapling, and Gatekeeper checks on both macOS targets. It runs packaged startup checks on Windows and Linux. Physical Windows, Linux, and Intel Mac hardware were outside the local checks.
