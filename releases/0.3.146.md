# Serve your PandaCode session on any port

## Added

- **Serve the live session in any browser.** Turn on **Web access** under **Settings → Connections → Remote access**, pick any open port (`1–65535`, or `0` for an automatic port; defaults to `47322`), and open or copy the session link. Browser tabs share the same live projects, tasks, agent streams, terminals and settings as the running desktop app in real time over HTTP and WebSocket.
- **Start or move the web server from the CLI and headless host.** Launch the desktop app with `--port <port>` (alias `--web-port`) and optionally `--host <addr>` (alias `--web-host`; `--host` requires `--port`), or set `PANDACODE_WEB_PORT` / `PANDACODE_WEB_HOST` (these apply only when launching a new instance, and `PANDACODE_WEB_HOST` only alongside `PANDACODE_WEB_PORT`). On macOS the binary sits inside the app bundle (`/Applications/PandaCode.app/Contents/MacOS/pandacode`) and is not on `PATH` by default. Re-running with `--port <port>` moves an already-running desktop session via single-instance handoff; the result is reported in the desktop window, not the invoking terminal. In headless mode, `pandacode serve --port <port>` serves the same browser UI alongside PandaCode Connect. See [Local web UI](https://github.com/aicodeking/pandacode/blob/main/docs/headless.md#local-web-ui---port).
- **Local-by-default security and browser-mode experience.** The server binds to `127.0.0.1` by default, requires a fresh per-run 256-bit bearer token (passed in the URL `#token=` fragment and stripped from the address bar on load, with one-click token rotation), validates `Host` and `Origin` headers, and rate-limits failed auth. It blocks desktop-only host commands (embedded browser, clipboard, microphone, window chrome, overlays, Finder/Explorer, tray actions and Tauri plugins) at runtime, backed by a test guard that requires every registered desktop command to be explicitly classified. Native-only actions adapt cleanly in browser tabs: folder and file pickers fall back to keyboard-accessible path prompts, external links open in the browser, desktop-only voice input and crash-report folder actions are hidden, and stopping or moving the server confirms before disconnecting active tabs.

## Known limitations

- Verified locally on macOS (Apple silicon) with Rust unit tests, strict Clippy, the Node unit, design-token and release tests, the website build, and the Chromium and WebKit Playwright suites for the web bridge and Web access settings. Windows and Linux packages are covered by the GitHub Actions release builds and their startup smoke checks.
- The built-in web server speaks plain HTTP without TLS. Keep it on loopback (`127.0.0.1`) and forward over SSH (`ssh -L <port>:127.0.0.1:<port> <host>`) or a private Tailscale/WireGuard network rather than exposing it directly on an untrusted LAN.
- Browser tabs do not support desktop-only OS integrations such as local voice dictation or native OS file dialogs (use the built-in path prompt instead).
- The release SBOM vulnerability scan (`SBOM-COVERAGE.json`) reports the same pre-existing upstream dependency findings carried over from `v0.3.145` (1 Critical and 1 High in `pandacode-rust`, 9 High in `pandacode-npm`); `0.3.146` introduces no new vulnerability findings.
