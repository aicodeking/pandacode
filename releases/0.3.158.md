# Colab HTTPS recovery on unclean connection drops and deadline-safe error reporting

## Fixed

- **Colab assignment recovery handles unclean HTTPS (`rustls`) drops without `close_notify` (superseding unpublished `0.3.153`).** When a proxy or peer closes a Google Colab HTTPS connection without sending a TLS `close_notify` alert — either before response headers arrive or mid-body — `is_tls_error` no longer misclassifies `rustls`'s `UnexpectedEof` as a fatal TLS failure. Colab runtime assignment now treats these unclean drops as recoverable transport errors, reconciles an already-created runtime via a same-`nbh` GET, and retries safely when no runtime was created, while keeping real TLS handshake, certificate, protocol, and fatal alert errors fail-closed.
- **Per-phase deadlines preserve HTTP refusal status on stalled error bodies and tighten retry classification.** `call_until` and `send_text_until` now enforce deadlines per request phase so an HTTP `4xx` or `500` response whose error body stalls until the deadline still reports the received HTTP status and refusal guidance instead of retrying or collapsing into a generic transport timeout. `retryable()` now fails closed on any TLS error (including mid-body on `502`–`504`) and never retries `3xx`, `4xx`, `500`, `501`, or `505` responses.
- **Loopback HTTPS (`rustls`) test coverage and release-note list cleanup.** Added real loopback HTTPS (`rustls`) tests covering pre-header and mid-body unclean TCP drops without `close_notify` alongside untrusted self-signed certificate rejection, and removed a stray blank line in `releases/0.3.153.md` so its limitations render as a single list.

## Known limitations

- **Colab quotas and capacity still apply.** Recovery depends on Google Colab answering the reconciliation request before the assignment deadline expires, and does not override Colab quota, GPU availability, or session limits.
- **Loopback-only drop verification.** Recovery from dropped, truncated, and stalled HTTPS and HTTP assignment responses was verified against local loopback mock servers rather than a live Google Colab network drop.
- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.158/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.158/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.158/SBOM-COVERAGE.md)).** Desktop build dependency scans (`pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`) and installer inventories are generated during the release build; four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` cannot inspect components inside them, and the Windows setup `.exe` and macOS `.app.tar.gz` artifact inventories identify only 2 metadata components each.
- **Public website changelog deployment.** The public changelog at `https://pandacode.bambooed.ai/changelog/` is deployed separately from GitHub Releases via Cloudflare Workers (`website/README.md`); GitHub Releases (linked from Settings → About) and the `latest.json` updater manifest carry the current release notes immediately.
