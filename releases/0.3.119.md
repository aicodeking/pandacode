# Claude Code usage that keeps working, team workers that never wait, errors you can dismiss

This release also carries the changes prepared as 0.3.115 to 0.3.118, which were never published.

## New

- **Team workers no longer stop to wait for approvals.** Workers dispatched by a team lead run with full access, and their approval prompts and questions are answered automatically under the lead's authority. Tools that always ask (such as deploys and scheduling) are declined with guidance instead of hanging. A request a worker can't settle ends that worker with a reason the lead can read, rather than leaving it stuck.
- **Reasoning effort per worker.** A lead can set the reasoning effort for each worker when it dispatches or follows up, fitted to what the chosen model supports.
- **A compact Workers panel.** Workers are listed by status in a short list, with a tally at the top (for example "3 working · 2 done"), an effort chip on each row, a header that stays in view while you scroll and full keyboard support. Failed workers and reviewers below the target score are marked clearly.
- **Repeated errors show once.** When an agent hits the same error several times in a turn (for example seven identical `ENOTFOUND` failures), the thread now shows one row with a `×7` count instead of seven rows. A turn that produced only errors folds into the turn before it.
- **Every error can be dismissed.** Each error row has a Dismiss button, and a turn with several different errors has **Dismiss all**. A toast offers **Undo** for five seconds (⌘/Ctrl+Z also works outside text fields). A turn whose errors were all dismissed keeps a quiet "N errors dismissed" note.
- **Long errors collapse.** A long error shows its first line with a chevron that expands the rest.
- **The same in the launcher.** The launcher window groups, collapses and dismisses errors the same way, with its own Undo line and **Dismiss all**.
- **Every tool call reads as one short sentence.** Shell commands, file reads and edits, searches, web fetches and MCP tools now show what they did: `Read main.ts lines 3130–3220`, `Searched for “isImeKey” in src`, `Ran tests playwright · 119 passed`, `Committed “fix: tidy rows”`, `Waited for server.log to contain “ready”`. Compound commands lead with the step that mattered and fold the rest into `+N more commands`. This works for every harness, including older threads.
- **Honest failures and risks.** Failed steps read `Couldn't force-push origin x` or `Tests failed · 3 of 120` in the failure colour, even when a pipe hid the exit code. Destructive steps (`rm -rf ~`, `git reset --hard`, `terraform apply -auto-approve`, `pulumi up --yes`) carry a `destructive` badge with the reason in a tooltip. Deleting scratch folders such as `.work/` or `/tmp` is not flagged, and a step that never ran is not blamed.
- **Image thumbnails in tool rows.** Screenshots and images an agent views or produces show a small thumbnail beside the file name. That includes Read of a PNG, Codex `imageView`, Playwright and PIL scripts, `ffmpeg` and `sips`. Click a thumbnail for a full viewer with Reveal and Copy. Thumbnails also appear in the team workers panel and in the launcher.
- **Better cards and summaries.** Expanded cards show the useful part, such as the diff (an edit that failed is marked "Not applied"), test tallies, search results or the command. Group headers summarise in plain English, like "Read 3 files, edited 2 files and ran 4 commands".
- **Rows fit narrow windows.** At narrow widths the object and quote shrink first, then the `+N more` tail, so the verb, badges and exit code stay visible.

## Changed

- **Side threads stay out of teams.** A By the way (`/btw`) side thread starts without your saved default team and never inherits a worker's access or a lasting grant.
- **Tighter rules for remote devices, bots and schedules around teams.** Because team workers run with full access, these now need the right permission before they can drive a thread that leads a team:
  - A phone or other remote device needs **Full access for remote tasks** turned on to start a team, send to a team lead, approve its requests, answer its questions, archive or reopen it, edit its goal, queue to it or resume it.
  - A bot needs Full mode to run team turns or approve a team lead's requests from chat. Declining and cancelling still work from anywhere.
  - A schedule last saved from a remote device skips its run, with a recorded reason, when its thread now leads a team and the switch is off.
- **Failures are shown, not swallowed.** Many actions that used to fail silently now say so: the menu bar popover and the running-agents widget show an alert, settings pages show a dismissable banner beside the control that failed (for example remote sign-in and rules import), and an unexpected error anywhere raises one calm toast.
- **Toasts can be closed.** Every toast has a close button, stays while you hover or focus it, and no longer reads its buttons out as part of the message to screen readers. A toast with Undo is not replaced by a routine notice while it is showing.
- Error messages read as plain text: no more "Error: …" prefixes or "[object Object]".

## Fixed

- **Claude Code limits show up even when PandaCode can't read them directly.** If the saved login has expired, the usage service is rate limiting, or the Keychain item can't be read without a prompt, PandaCode now runs your own Claude Code once (`claude -p /usage` with safe mode, no tools, one turn and no saved session) so it can refresh its own login, then reads again. If that still fails, the card shows the numbers Claude Code printed, and otherwise your last good reading, marked as a saved snapshot. PandaCode never writes Claude Code's credentials. You can turn this off under Settings → Providers → Claude Code (**Let PandaCode ask Claude Code for usage when it can't read it**).
- **No more empty cards while waiting.** While a Claude check is running, the card shows your last saved reading straight away with "Checking limits…" (or "Asking Claude Code…") under it. The menu bar's Claude row does the same and no longer disappears on an error.
- **Every Claude problem says what to do.** Signed-out cards give the `claude auth login` command to copy, then **Refresh**. A rate limit says when a Refresh can check again and enables the button then. An outdated Claude Code gives `claude update` to copy. Reset times that have already passed are hidden.
- **Skills library: turning skills and rules on and off is safer in projects.** In project scope PandaCode no longer writes through a link that leads outside the project or into its `.git` folder, a hard-linked file, or a FIFO or other special file; it refuses with a message naming the path. Links between rule files (`AGENTS.md -> CLAUDE.md`) and between skills folders (`.agents/skills -> ../.claude/skills`) still work.
- **A failed write no longer leaves a half-changed project.** Every path is checked before anything is written. Existing rule and skill files are replaced through a temporary file, so a failed write keeps the old version. A failed or unsaved activation removes what it wrote and its Git exclude line, and names any file it had to leave.
- **Git exclude lines are kept tidy.** The line uses the folder the files actually land in, gitignore's special characters are escaped, and a path with a newline or other control character is refused. When two activations share a line (for example the same skill in two worktrees), turning one off keeps the line for the other. A line is only edited in an exclude list that belongs to the activation's own repository.
- **An edited activation record can't make PandaCode delete other files.** A recorded path that isn't where that skill or rule is written is left alone and reported as kept.
- **Moving a skill to a new folder** removes the old copy only after the new one is saved, so a failed save leaves the old copy working.
- **Phone: a slash command for a switched-off skill** now says the skill is switched off, without starting the agent.
- **Phone: cloning a project or adding a worktree** now refreshes which folders the Skills library switches apply to, as on the desktop.

## Privacy and security

- Claude Code is run at most once per Claude setup every 15 minutes (plus one extra run when you press Refresh), never twice at once, never during a server-set rate-limit wait, never for API-key or other non-subscription setups, and never while the Keychain is locked. It runs in PandaCode's own app-data folder with telemetry, error reports, nonessential traffic and self-update turned off, and with no API keys or OAuth tokens in its environment. It is stopped after 45 seconds (or as soon as the Keychain locks).
- PandaCode doesn't start a run while Claude Code's own login-refresh lock is held, so it never races a Claude Code session you have open.
- A Keychain read you denied, or two macOS dialogs nobody answered, stop automatic reads until you press Refresh, so the same dialog doesn't come back on its own.
- The last good reading is saved in `claude-usage-last.json` in PandaCode's app-data folder (owner-only permissions). It is tied to the account by a keyed hash, so it never stands in for a different account or after a sign-out.
- Thumbnails are served by a new local `tool_image` command. It only loads an image that the same task's own tool records name: an image the agent viewed, or one a finished command wrote. Relative paths must stay inside the task's checkout, network paths are never loaded, symlinks are not followed, and images are size-capped and downscaled. Nothing is sent over the network.

## Upgrading

- Earlier versions didn't record which device saved a schedule, so after updating, schedules you made before 0.3.119 are treated as saved remotely. They run as before unless their thread leads a team and **Full access for remote tasks** is off. In that case the schedule shows why it skipped; open it on the desktop and save it once to run it again.

## Known limitations

- **Errors:**
  - Dismissing an error deletes it from the thread's saved history once the Undo window ends; it can't be restored after that.
  - In a thread that runs on another computer, a dismissed error is hidden on this computer only, and only until PandaCode restarts.
  - Tested in the browser preview (Chromium, and WebKit for the thread, toast, launcher and banner tests) and with Rust unit tests of the delete command. The full browser suite was not run as a whole on the final merge: the error-related test files were, on a heavily loaded machine, and four tests in them that also time out on the previous release under that load were not confirmed there. It has not been clicked through by hand in the built app on any platform.
  - This change was reviewed in seven rounds by automated reviewers; a final round to check the last fixes could not run.
- **Tool rows:**
  - Images saved by a script piped in from another command (`cat <<EOF | python3`) don't get a thumbnail. Only the last literal path a script saves is shown on the row.
  - Some row wording is a best guess. When a compound command fails, the card names the step that most likely failed, but that isn't certain.
  - Checked with unit tests (TypeScript and Rust) and the Chromium browser specs for the tool rows and image viewer. Not clicked through by hand in the packaged app on every platform.
- **Skills library:**
  - These changes were checked with unit tests (including links, hard links, FIFOs, shared exclude lines, failed writes and failed saves) and by reading the code. They have not been clicked through by hand in the built app.
  - A small timing gap remains: a parent folder swapped for a link between PandaCode's check and its write is still followed.
  - If PandaCode crashes mid-write, a `.<name>.pandacode-<uuid>.tmp` file can stay beside the file it was replacing and shows in `git status`; delete it by hand.
  - In user scope (your home folder) rule files are still rewritten in place and links are still followed, as before.
  - On Windows there is no hard-link check, and links are refused when the project root can't be resolved.
  - Full details are in [docs/skills-library.md](https://github.com/aicodeking/pandacode/blob/main/docs/skills-library.md).
- **Team workers:**
  - The changes were checked with unit tests, the browser suites for the Workers panel and side threads, and the full Rust suite. They have not been clicked through by hand in the built app on every platform.
- **Claude Code usage:**
  - Claude Code may answer `/usage` from its own snapshot without refreshing the login. The card then shows those numbers and tries again at the next 15-minute slot.
  - On Windows, Claude Code started without a window usually needs the forced stop at its time limit.
  - Checked with Rust and TypeScript unit tests, the Chromium browser specs for the usage panel, Settings and the menu bar, and live runs against Claude Code 2.1.322 on macOS. Not clicked through by hand in the packaged app on Windows or Linux.
