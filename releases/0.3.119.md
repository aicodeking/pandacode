# Claude Code usage that keeps working

## Fixed

- **Claude Code limits show up even when PandaCode can't read them directly.** If the saved login has expired, the usage service is rate limiting, or the Keychain item can't be read without a prompt, PandaCode now runs your own Claude Code once (`claude -p /usage` with safe mode, no tools, one turn and no saved session) so it can refresh its own login, then reads again. If that still fails, the card shows the numbers Claude Code printed, and otherwise your last good reading, marked as a saved snapshot. PandaCode never writes Claude Code's credentials. You can turn this off under Settings → Providers → Claude Code (**Let PandaCode ask Claude Code for usage when it can't read it**).
- **No more empty cards while waiting.** While a Claude check is running, the card shows your last saved reading straight away with "Checking limits…" (or "Asking Claude Code…") under it. The menu bar's Claude row does the same and no longer disappears on an error.
- **Every Claude problem says what to do.** Signed-out cards give the `claude auth login` command to copy, then **Refresh**. A rate limit says when a Refresh can check again and enables the button then. An outdated Claude Code gives `claude update` to copy. Reset times that have already passed are hidden.

## Privacy and security

- Claude Code is run at most once per Claude setup every 15 minutes (plus one extra run when you press Refresh), never twice at once, never during a server-set rate-limit wait, never for API-key or other non-subscription setups, and never while the Keychain is locked. It runs in PandaCode's own app-data folder with telemetry, error reports, nonessential traffic and self-update turned off, and with no API keys or OAuth tokens in its environment. It is stopped after 45 seconds (or as soon as the Keychain locks).
- PandaCode doesn't start a run while Claude Code's own login-refresh lock is held, so it never races a Claude Code session you have open.
- A Keychain read you denied, or two macOS dialogs nobody answered, stop automatic reads until you press Refresh, so the same dialog doesn't come back on its own.
- The last good reading is saved in `claude-usage-last.json` in PandaCode's app-data folder (owner-only permissions). It is tied to the account by a keyed hash, so it never stands in for a different account or after a sign-out.

## Known limitations

- Claude Code may answer `/usage` from its own snapshot without refreshing the login. The card then shows those numbers and tries again at the next 15-minute slot.
- On Windows, Claude Code started without a window usually needs the forced stop at its time limit.
- Checked with Rust and TypeScript unit tests, the Chromium browser specs for the usage panel, Settings and the menu bar, and live runs against Claude Code 2.1.322 on macOS. Not clicked through by hand in the packaged app on Windows or Linux.
