# ZCode 3.18.2 works again

## Fixed

- **ZCode starts again.** PandaCode finds a file moved in ZCode 3.18.2, restoring model lists and runs. Older versions keep working.
- **Clearer failures.** When ZCode exits before answering, PandaCode shows its exit status and message, with credentials removed. Stray output no longer blocks model discovery; an early crash is retried once.
- **Plan runs work again.** ZCode 3.18.2 stopped reporting Plan as a mode; PandaCode no longer stops these runs with “ZCode did not apply the selected access mode”.
- **Same-name models stay selectable.** Models offered by different providers appear separately, such as “GLM-5.3 (BigModel API)” and “GLM-5.3 (BigModel API 2)”. Existing tasks keep their model.
- **Tool details return.** Tool rows show commands and other inputs again, restoring changed-file detection. Context used no longer counts cached tokens twice. A saved thinking level no longer blocks a run when ZCode's default model does not support it.

## Changed

- **Fewer ZCode launches.** Model lists are kept for five minutes. Refresh reloads them.

## Known limitations

- ZCode 3.18.2's allow/deny prompt was not observed: a simple command ran without asking. Approval handling is unchanged.
- ZCode 3.18.2 does not report whether Plan is on; PandaCode trusts its acknowledgement.
- Tested with ZCode 3.18.2 on macOS (Apple Silicon) only. Windows and Linux were not tried by hand.
