# Steadier thread scrolling

## Fixed

- **Thread scrolling no longer snaps back to the bottom on macOS.** In the native app (WKWebView), scrolling up through a long thread could jump you back to the newest turn. When older turns load at the top, PandaCode now clamps long replies before restoring your scroll position instead of relying on WebKit's `overflow-anchor`, so your place holds. Scrolling also stays put during trackpad settle jitter and elastic overscroll, while a reply is streaming or a pane updates, and when long replies further up finish formatting in the background.

## Changed

- **A quieter thread scroll indicator.** The scroll rail on the left of a thread is now transparent and borderless, with no background fill, rounded corners, blur or shadow, so only its ticks show over the conversation. Hovering a tick still shows the frosted-glass preview card for that turn.

## Known limitations

- Verified locally on macOS (Apple silicon) with Rust unit tests, strict Clippy, the Node unit, design-token and release tests, the website build, and the Chromium and WebKit Playwright suites for thread scrolling and the scroll indicator. Windows and Linux packages are covered by the GitHub Actions release builds and their startup smoke checks.
- Scroll behaviour in the native macOS WKWebView is covered by automated Playwright WebKit checks; trackpad momentum and elastic overscroll feel can still vary with system scrolling settings.
