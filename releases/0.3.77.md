# Faster diffs in the Changes view

## Changed

- **Diffs show up right away.** Syntax highlighting now runs in background workers with Shiki's WebAssembly engine instead of on the main thread. Lines appear at once and pick up their colors a moment later, so opening the Changes view, scrolling or switching wrap and layout never freezes the window. On a 4,000-line file the first rows used to take about a second; they now take tens of milliseconds.
- **Large files stay smooth.** Long diffs are split into hunk groups that mount a few at a time, and only the rows near what you're looking at are drawn. Diffs up to 40,000 lines render in full instead of falling back to plain text.
- **The highlighter is ready before you need it.** It starts right after the window opens and warms the languages of the files you've changed first. The parts of a diff that are on screen are highlighted first, and the files you just looked at keep their colors when you come back.
- **Refreshes don't redraw.** An open diff stays on screen while the Changes view reloads, and is only swapped when its text actually changed.
- **Cheaper git calls.** Loading one file's diff no longer scans the status of the whole repository, the repository check is cached, and every `git`/`gh` call PandaCode runs returns a few milliseconds sooner.

## Known limitations

- Clicking into the Changes view in the first moment after launch can still show uncolored lines for about 0.1–0.2 s while the highlighter compiles its first grammar.
- If the highlighting workers can't start, diffs are highlighted on the main thread as before.
- Single hunks over 5,000 lines are shown without colors.
