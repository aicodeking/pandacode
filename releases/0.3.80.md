# Schedules: wake-ups, timed messages and workflows

## New

- **Agents can come back later.** An agent can wake its own thread in 20 minutes, at a time, on a repeat (every N minutes, daily, weekdays or chosen days), or when another thread finishes. Waking its own thread never asks for approval.
- **Messages to other threads, later.** An agent can send another thread a message at a set time or when a thread finishes. It asks you first, even in Full access, while "Ask before agents message other threads" is on.
- **A wake-ups strip in every thread.** Above the composer, a calm line shows the next wake-up ("Next wake-up in 12 min · Check the CI run"). Open it to see each schedule with Run now, Snooze, Pause, Edit and Remove, plus a short history of what ran.
- **Start one from anywhere.** Type `/wake 30m check CI` (or `/wake 9:00 …`, `/wake tomorrow …`), or pick Schedule a wake-up… from the `+` menu, a thread's sidebar menu or the command palette. Threads with a wake-up coming show a small clock in the sidebar.
- **Thread traces.** A message sent by a schedule carries a "Woken by …" marker: the schedule's repeat, which run it is, who set it, why it fired (time reached, Run now, or another thread finishing and whether it succeeded). The details fold away under "Wake-up details", and tool activity reads like "Scheduled a wake-up · in 30 min".
- **Settings → Schedules.** Every schedule across your threads in one place, filterable by Agents, Yours and Paused. Make your own with an editor for every kind of timing, start from templates, and see an activity log. Switches let you turn off agent scheduling, choose whether agents ask before messaging other threads, set a per-thread limit for agents, or pause everything (nothing is lost: due runs and finished-thread triggers wait until you resume).
- **Workflows.** Chain 2 to 6 threads: start now, at a time, daily, on weekdays, or after a thread finishes, and each step messages the next thread once the previous step's thread has finished. A workflow shows as one unit with a single switch, Run from start, and Remove.

## Safety

- Agents can only cancel schedules an agent made, never yours.
- Chains that would loop back on themselves are refused. Agent "after" schedules run once by default, and agent repeats stop after 20 runs unless they ask for more.
- Bot conversations keep their own bot schedules and don't get these tools.
- A message for a busy thread waits in its queue; one for a thread with an open harness console waits until the console closes.

## Known limitations

- Schedules run only while PandaCode is open. A schedule missed while the app was closed runs once when it opens, not once per missed slot.
- Agents can't edit or pause a schedule; they cancel it and make a new one.
