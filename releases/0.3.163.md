# Google Colab runtime assignment recovery

## Fixed

- **One final lookup for late runtime assignments.** After the last retryable assignment POST failure or when the POST budget expires, PandaCode looks up the same notebook ID (`nbh`). If that GET returns only an XSRF token and reconciliation time remains, PandaCode pauses briefly when time allows and makes one final bounded GET for the same notebook before reporting failure.
- **Recovery from unusable HTTP `2xx` assignment replies.** A close-delimited response with truncated JSON or a successful reply missing a complete runtime assignment now triggers bounded GET reconciliation for the same notebook without replaying the POST.
- **Allowlisted Colab and Google OAuth errors.** Non-`2xx` error responses show the HTTP status and any recognized Google OAuth or RPC error identifier, such as `invalid_grant` or `RESOURCE_EXHAUSTED`. HTTP `412` assignment refusals show session, quota, or capacity guidance, and HTTP `400` GPU refusals show accelerator quota or entitlement guidance. Arbitrary response text stays out of user-facing errors.
- **TLS failures stay visible during reconciliation and unassign.** A terminal TLS failure during a reconciliation GET is reported even after an earlier POST drop. When an HTTP `404` unassign response fails TLS mid-body, PandaCode returns the TLS error and keeps the local session record.

## Known limitations

- **Local web access (`--port`).** The `#token=` URL grants full control of the PandaCode session as the host user, including starting agents, running terminal commands, and editing workspace files. The built-in server uses plain HTTP. Keep it on loopback (`127.0.0.1`) or reach it over SSH, Tailscale, or WireGuard. Browser tabs lack host-only capabilities such as local voice dictation, the embedded browser, native clipboard access, and OS file and tray actions. [Local web UI](https://github.com/aicodeking/pandacode/blob/v0.3.163/docs/headless.md#local-web-ui---port)
- **SBOM scan coverage.** The build publishes Rust and npm lockfile SBOMs. Compressed `.dmg` and `.AppImage` installers remain listed as `not-scanned` because `syft` cannot identify components inside them. Windows installers and macOS updater archives expose package metadata only. [JSON coverage report](https://github.com/aicodeking/pandacode/releases/download/v0.3.163/SBOM-COVERAGE.json) · [Markdown coverage report](https://github.com/aicodeking/pandacode/releases/download/v0.3.163/SBOM-COVERAGE.md)
- **Public website changelog deployment.** The Cloudflare Workers deployment updates the public changelog separately from GitHub Releases. Settings → About links to GitHub Releases, and the updater's `latest.json` carries the current release notes. [Public changelog](https://pandacode.bambooed.ai/changelog/) · [Website deployment](https://github.com/aicodeking/pandacode/blob/v0.3.163/website/README.md)

## Verification

- **Colab network fixtures.** Loopback `rustls` HTTPS tests covered pre-header drops, mid-body truncations, untrusted certificate rejection, and fail-closed mid-body TLS alerts, including HTTP `502` during assignment reconciliation and HTTP `404` during unassign. Separate loopback HTTP tests covered late reconciliation, unusable close-delimited `2xx` recovery, stalled error bodies, and allowlisted non-`2xx` error formatting. The network failures were simulated on loopback. Live Google Colab network drops were outside this verification.
- **Local macOS (Apple silicon).** The targeted Colab and HTTP suite passed 44 tests with 0 failures and 1 ignored. The full Rust library suite passed 4,181 tests with 0 failures and 114 ignored (`RUST_TEST_THREADS=2`). Clippy passed with `--all-targets -- -D warnings`. The desktop and website builds passed. `npm test` passed all 1,517 tests, and `npm run test:release` passed all 107 tests.
- **GitHub Actions CI and release.** The eight-job main-push CI covers the full Rust library suite on Linux, per-platform Clippy (`-D warnings`), TypeScript and Node unit tests, the website build, and macOS ONNX parity. The official artifact-only preflight verifies all six installer checksums, version-bound updater signatures, and `latest.json` before tagging. The tag workflow rebuilds and verifies the assets before publishing to GitHub Releases and npm.
- **Packaged platform checks.** Both macOS builds run Developer ID signing, notarization, stapling, and Gatekeeper checks. Windows and Linux run packaged launch and stay-alive checks. Manual installer and GUI testing on physical hardware was outside this verification.
