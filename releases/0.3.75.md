# Sub-workers, better team messaging and a leaner harness

## New

- **Sub-workers.** A team worker can start its own sub-workers when the work really splits, one level deep: at most 3 running and 6 in total, and only inside its own files. They count against the team's assignment limit, and a read-only worker can only start read-only helpers.
- **Parked workers.** A worker waiting on its sub-workers is parked: its process exits to free memory (about 250–390 MB each), and it picks up again with their results. This uses no attempt and no architect round. The team panel shows it as **Waiting on sub-workers**, with sub-workers indented under it.
- **Team messages without polling.** Every team tool result carries a short digest of unread messages. Agents can message the whole team (`all`) and reply to a message. An urgent message reaches a running worker in its current turn.
- **Team notes.** A shared board of up to 64 short facts (API shapes, decisions) that every teammate can read and that new workers receive when they start.

## Changed

- **The architect rests while workers run.** Only an urgent message, a blocker, a failure or settled results wake it. It no longer keeps a spare process idling while its workers run.
- **Faster streaming.** A long reply re-parses only its unfinished last block. In a 50 KB benchmark, rendering work fell from 13.7 s to 2.3 s, and memory growth from 94 MB to under 1 MB. Streamed text reaches the window in merged batches (about 30 per second) instead of one event per chunk.
- **Quieter UI.** Team updates that change nothing visible no longer repaint anything. A tool update redraws only its own row. Memory kept for recently opened threads is capped.
- **Fewer tokens per turn.**
  - Workers get 80% shorter app instructions and about a third of the team tool text.
  - Architect review turns are about a third of their old size.
  - Simulator tools appear only for iOS or Android projects or a shown simulator.
  - VM tools are trimmed to list and create until you have a VM or a connected cloud machine.

## Known limitations

- The new `pandacode_sub_workers` and `pandacode_team_notes` tools use the generic tool row in the transcript for now.
- Urgent messages are counted as read once the worker's run accepts them; one that fails after that does not reappear.
- These gains cut PandaCode's own overhead; time spent by the model itself is unchanged.
