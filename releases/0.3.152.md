# Host-owned queue holds, reconnect sync, and stricter release verification

## Fixed

- **Host-owned queue holds across desktop, headless `pandacode serve`, and browser tabs.** Failed, stopped, and newly usage-limited runs are now paused directly by the host before the turn finishes. Stopping a run or clicking **Send now** from a browser tab no longer races an automatic drain on the desktop, and headless hosts no longer let a later follow-up bypass a failed, stopped, or usage-limited run even when no browser is connected.
- **Headless usage-limit recovery and concurrent queue drains.** When headless `pandacode serve` continues automatically after a usage-limit reset, it clears resumable holds so queued follow-ups can drain once the continuation finishes (and restores a hold if launching the continuation fails). Concurrent drain wakes on a headless host are now coalesced rather than dropped, preventing a newly queued follow-up from stalling idle.
- **Consistent browser queue state across connection, reconnect, and live updates.** Initial browser snapshots, reconnect/lagged-stream resyncs, and live queue updates now share one ordering clock so stale replies cannot resurrect removed rows or restore cleared pause banners, and reconnecting a browser tab refreshes active pause reasons from the host.
- **Bot threads honor explicit queue holds.** Bot conversations now check for active queue holds before claiming the next queued follow-up.

## Known limitations

- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.152/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.152/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.152/SBOM-COVERAGE.md)).** Desktop build dependency scans (`pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`) report 0 Critical and 0 High findings, with pre-existing lower-severity counts of 2 Medium and 3 Low in Rust and 6 Low in npm. Four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` cannot inspect components inside them, and the Windows setup `.exe` and macOS `.app.tar.gz` artifact inventories identify only 2 metadata components each.
- **Public website changelog deployment.** The public changelog at `https://pandacode.bambooed.ai/changelog/` is deployed separately from GitHub Releases via Cloudflare Workers (`website/README.md`) and may lag behind the latest GitHub Release until redeployed.

## Verification

- **Local macOS (Apple silicon):** Rust `message_queue`, `headless`, `web_server`, and `bots` library unit tests (173 passed, 1 ignored live-network test), Clippy (`--all-targets -- -D warnings`), `npm run build`, Node unit tests (1,471 passed), release-script tests (101 passed), website build, Playwright Chromium queue and web-bridge suites (`web-bridge`, `message-queue`, `queue-parity`, `steering`, `usage-limit`: 58 passed), and Playwright WebKit `web-bridge` suite (19 passed).
- **GitHub Actions CI and release:** `ci.yml` runs the full Rust library test suite on Linux, per-platform Clippy (`-D warnings`) on macOS, Windows, and Linux, TypeScript/unit tests, website build, and ONNX parity on macOS. `release.yml` requires a verified artifact-only preflight (`verify_preflight` checking installer checksums, updater signatures, and `latest.json` with `publish` skipped) before official `aicodeking/pandacode` publishes, enforces Developer ID signing, notarization, stapling, and Gatekeeper verification for both `PandaCode.app` and `.dmg` installers on official macOS builds (while keeping signing optional for local builds and forks without signing secrets), and runs Windows and Linux packaged startup smoke checks (confirming launch and stay-alive, not full GUI rendering).
