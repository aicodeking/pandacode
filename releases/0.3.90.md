# Faster, smarter machine orchestration

## Added

- **Agents can pick the computer for you.** With Agent orchestration on, an agent can launch a thread with `machine: "auto"`: PandaCode picks the online linked computer that has the right harness and model and the fewest running threads.
- **Lineage in the Agents panel.** Threads running on your other computers now sit in the dock's Agents flyout as "Lineage · N running", with Open, Stop and Stop all. Above the composer there is only a one-line "Waiting on N threads · Stop" while the agent waits.
- **Offline computers are clear.** A thread on a computer that has been offline for five minutes reads "Offline", stops holding up the agent, and the agent is told once so it can decide what to do. A named launch on an offline computer is refused straight away.
- **You can cut off a computer that left your account.** It now shows in Settings → Remote access as "Left the account" with Unlink. Until you unlink it, agents can still read the threads they already ran there, but can't start or change anything.
- **You can change an offline computer's access** without waiting for it to come back.

## Changed

- **Launches start faster.** PandaCode loads each linked computer's model list in the background and reads the checkout with one git call instead of five. In an emulated test, the first agent event arrived after 1.6 s instead of 3.6 s. A harness's first launch on a computer can still wait for its model list.
- **Status changes redraw much less.** One thread changing status now touches about 50 parts of the window instead of about 260.

## Known limitations

- Orchestration has only been tested against simulated hosts, never on two real computers. Try it on your own pair before relying on it for long jobs.
- Launching and messaging threads don't ask for approval when the task runs in Full access, like every other PandaCode tool. The link's access level still limits what the thread can do.
