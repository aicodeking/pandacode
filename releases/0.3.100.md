# Account pools: keep working when a Claude or Codex account hits its limit

## Added

- **Account pools for Claude Code and Codex.** Add several of your own Claude Pro/Max or ChatGPT accounts under Settings → Providers → Connections and turn on **Account pool**. When a run stops at a usage limit, PandaCode holds that account until its reset, moves the conversation to the next ready account and continues in the same run with "Continue where you left off." The switch takes about as long as starting the CLI, the transcript gets one note naming the move, and the composer shows the new account.
  - Accounts near a limit are left before the next turn when another has room, so most switches happen between turns. New conversations without a chosen account start on the account running the fewest tasks, so parallel tasks and team workers spread out.
  - Settings lists every account as Ready, Near limit, Out until (with the weekday for weekly limits), Not signed in, or Same login as another. Each has an **In pool** switch, and **Try now** clears a hold early.
  - Holds survive a restart. Stop and messages sent during a switch are kept: a message that no account took goes back to your queue.
  - No new network requests: the pool only reads the limit information the CLIs already report.
- **One-click account sign-in.** **Add account…** creates a private folder for the account and starts the CLI's own login: Claude's or OpenAI's sign-in page opens in your default browser, and the account joins the pool once you're signed in. If the page shows a code, paste it into the field in Settings. **Sign in** does the same for an account that isn't signed in yet, and **Copy sign-in command** remains as a fallback.

## Known limitations

- Pools cover Claude Code and Codex only, and only subscription logins: a connection that only sets an API key is not a member. Cloud runs and goal operations are not pooled.
- A real Claude session was resumed from a moved transcript in a live test. The Codex move was checked against Codex's source and with test scripts, not yet with a live second account.
- One-click sign-in was tested with stand-in login scripts; a full sign-in with a second real account was not completed here. Only one Codex sign-in can run at a time (Codex uses a fixed local port).
- Pool only accounts you own; each needs its own subscription.
