# Fix for the voice crash on macOS

## Fixed

- **Voice no longer crashes PandaCode on macOS.** In 0.3.108, opening Settings → Voice (which lists microphones), starting dictation with the microphone button or ⌘/Ctrl+Shift+D, or pressing Test microphone closed the app. The audio library had a memory bug that only appeared in release builds, so it got past testing. PandaCode now uses a corrected version. On macOS and Windows your saved microphone choice is kept.

## Changed

- When a recording stops on its own at the limit, or the microphone stops, the message now ends “Choose Transcribe recording to transcribe it, or discard it.” instead of “…to send the captured audio”.
- If the on-device speech engine stops unexpectedly, the message now suggests a speech service if it keeps happening.

## Known limitations

- On Linux, a microphone picked in 0.3.108 no longer matches: Settings → Voice shows it as “not connected” and recording uses the system default until you pick your microphone again. The list now shows raw ALSA device ids (such as `hw:CARD=PCH,DEV=0`) instead of card names, and some entries, such as `null`, capture only silence. **System default** and the PipeWire and PulseAudio choices are unaffected.
- A release-profile test of the audio code listed devices and recorded from a real microphone on an Apple silicon Mac; with the old audio library the same test crashed. CI runs it on macOS runners, which only have virtual audio devices. The packaged app, Intel Macs with a real microphone, Windows, Linux, the microphone permission prompt and real speech services have not been tested by hand. Everything else listed under Known limitations in the 0.3.108 notes still applies.
