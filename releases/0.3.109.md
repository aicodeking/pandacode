# Fix for the voice crash on macOS

## Fixed

- **Voice no longer crashes PandaCode on macOS.** In 0.3.108, opening Settings → Voice or clicking the microphone closed the app. The audio library had a memory bug that only appeared in release builds, so it got past testing. PandaCode now uses a corrected version. On macOS and Windows your saved microphone choice is kept.

## Changed

- When a recording stops on its own at the limit, or the microphone stops, the message now ends “Choose Transcribe recording to transcribe it, or discard it.” instead of “…to send the captured audio”.
- If the on-device speech engine stops unexpectedly, the message now suggests a speech service if it keeps happening.

## Known limitations

- On Linux, a microphone picked in 0.3.108 or earlier no longer matches, so recording uses the system default until you pick your microphone again in Settings → Voice. The list now shows ALSA device ids (such as `hw:CARD=PCH,DEV=0`) instead of card names. **System default** and the PipeWire and PulseAudio choices are unaffected.
- A release build recorded from a real microphone in a local test on an Apple silicon Mac (the same test crashed with the old audio library). CI's macOS runners only have virtual audio devices. The microphone permission prompt, real speech services, and real microphones on other platforms have not been tested by hand. Everything else listed under Known limitations in the 0.3.108 notes still applies.
