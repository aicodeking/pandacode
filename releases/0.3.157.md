# OpenCode v2.4+ model and effort discovery, plus Windows npm shim fixes

## Fixed

- **OpenCode v2.4+ models and reasoning efforts appear again (#421, #419, #420).** OpenCode v2.4.0 stopped waiting for plugins to activate inside `/api/model`, so one-shot `opencode --standalone api model.list` calls returned an empty list on cold startup and left only **Default** available. PandaCode now starts a private `opencode serve --stdio --port 0` discovery server in an isolated folder with a per-call random password, waits for `/api/plugin` readiness before reading `/api/model`, retries transient empty/503 responses, rejects empty catalogs instead of masking fallback, and falls back cleanly through `--standalone api model.list`, `--standalone models`, and `models` while leaving OpenCode v1 unchanged.
- **OpenCode npm installations on Windows resolve `@opencode/cli` and avoid `.ps1` / POSIX shell shims (#420, #421).** Windows batch-shim resolution now recognizes both `@opencode/cli` (`./bin/opencode.cjs`) and `opencode-ai`, redirects `.ps1` executable paths to a sibling `.exe`/`.com`/`.cmd`/`.bat` launcher (or returns a clear message if none exists), and skips extensionless POSIX scripts during PATH discovery so Windows never attempts to execute them directly.

## Known limitations

- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.157/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.157/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.157/SBOM-COVERAGE.md)).** Desktop build dependency scans (`pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`) and installer inventories are generated during the release build; compressed installers (`.dmg` and `.AppImage`) remain `not-scanned` because `syft` cannot inspect components inside them, while the lockfile SBOMs cover shipped Rust and npm dependencies.
- **Public website changelog deployment.** The public changelog at `https://pandacode.bambooed.ai/changelog/` is deployed separately from GitHub Releases via Cloudflare Workers (`website/README.md`); GitHub Releases (linked from Settings → About) and the `latest.json` updater manifest carry the current release notes immediately.

- **Local macOS (Apple silicon):** Rust `providers`, `launch`, and `extra_models` library unit tests (818 passed, 0 failed), live smoke test `installed_opencode_catalog_reports_efforts` against installed OpenCode (`2,337` models, `2,028` with reasoning efforts), Clippy (`--all-targets -- -D warnings`), `npm run build`, Node unit tests, release-script tests (107 passed), and website build (`npm run site:build`).
- **GitHub Actions CI and release:** `ci.yml` runs the full Rust library test suite on Linux, per-platform Clippy (`-D warnings`) on macOS, Windows, and Linux, TypeScript/unit tests, website build, and ONNX parity on macOS. `release.yml` requires a verified artifact-only preflight (`verify_preflight` checking installer checksums, version-bound updater signatures across all six platforms, and `latest.json`), enforces Developer ID signing, notarization, stapling, and Gatekeeper verification on official macOS builds, and runs Windows and Linux packaged startup smoke checks (confirming launch and stay-alive, not full GUI rendering).
