# Web reconnect reliability, queue-hold ordering, Linux install guidance, and changelog accuracy

## Fixed

- **Queue-hold events stay in host order.** The host now assigns a monotonic sequence number (`holdSeq`) inside the queue-hold lock and includes it on every `queue-changed` hold event (`held: true` / `held: false`). Connected desktop and web clients ignore stale hold events with an older sequence so a delayed reset notice cannot re-apply a hold already cleared by Resume.
- **Reconnecting tabs no longer merge output across runs.** On WebSocket reconnect or event-stream lag, browser tabs now clear pre-disconnect live stream cards and reload persisted history before rendering new events — keeping Stop active while the host is running, isolating replacement runs from finished runs, and clearing stale stop/Send-now state when a new run takes over.
- **Deleted drafts close cleanly on reconnect.** When a draft open in a browser tab is discarded or deleted on the host while offline and `get_task` reports it missing on reconnect, PandaCode removes the stale draft and clears its composer cleanly while keeping drafts open on transient lookup errors.
- **Accurate Linux AppImage SBOM coverage notes and install guidance.** Updated `SBOM-COVERAGE.{json,md}` and [`docs/releasing.md`](https://github.com/aicodeking/pandacode/blob/v0.3.164/docs/releasing.md#sboms-and-scan-coverage) to state accurately that Linux AppImages bundle `WebKitGTK`, `JavaScriptCoreGTK`, `GTK`, and supporting shared libraries under `usr/lib` (with `glibc`, Wayland/EGL, and GPU drivers supplied by the host) and remain `incomplete` / `not-scanned` because `syft` cannot inventory bare shared libraries inside compressed AppImages. The release `Installing` section now documents the Linux FUSE 2 (`libfuse2`) / `--appimage-extract-and-run` prerequisite and links to the pinned [`README.md#install`](https://github.com/aicodeking/pandacode/blob/v0.3.164/README.md#install) guide.
- **Website changelog published release count and labels.** Classified all 64 historical unpublished `releases/*.md` notes (49 pre-public `0.2.x` notes, 13 verified rolled-up `0.3.x` notes, and 2 standalone unpublished `0.3.x` notes) separately from published GitHub Releases so `/changelog/` matches the live GitHub Release count and labels non-published notes accurately.

## Upgrade and compatibility

- **In-place upgrade from `v0.3.163` or `v0.3.162`.** No database schema changes (`PRAGMA user_version = 37`), and the `queue_holds` IPC response shape is unchanged.
- **Direct upgrade from `v0.3.156`–`v0.3.158`.** Upgrading directly across `v0.3.161`–`v0.3.163` also brings the features and fixes shipped in [`v0.3.161`](https://github.com/aicodeking/pandacode/releases/tag/v0.3.161) (including the additive `task_model_runs` export metadata table), [`v0.3.162`](https://github.com/aicodeking/pandacode/releases/tag/v0.3.162), and [`v0.3.163`](https://github.com/aicodeking/pandacode/releases/tag/v0.3.163) (Google Colab runtime assignment recovery).
- **Direct upgrade from `v0.3.154` or earlier.** First launch runs the one-time additive SQLite index and tracker setup introduced in `v0.3.156` synchronously — measured at ~1 second on a 218 MiB (~25k-message) database and ~2.1 seconds at 2× scale, and potentially longer on cold or fragmented databases ([migration timings](https://github.com/aicodeking/pandacode/blob/v0.3.164/docs/db-benchmarks.md#7-migration-at-two-scales)).

## Known limitations

- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.164/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.164/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.164/SBOM-COVERAGE.md)).** Generated during the release build with `syft 1.55.0` and `grype 0.121.0` (vulnerability DB `2026-11-27T06:22:11Z`); `pandacode-rust.cdx.json` scans 707 Rust lockfile components (0 Critical, 0 High, 2 Medium, 3 Low; `advisories: []`) and `pandacode-npm.cdx.json` scans 95 npm lockfile components (0 Critical, 0 High, 0 Medium, 6 Low; `advisories: []`). Four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` finds no identifiable package inventory inside them (the Linux AppImages bundle `WebKitGTK`, `JavaScriptCoreGTK`, `GTK`, and supporting shared libraries under `usr/lib`, which are therefore not scanned), while the Windows setup `.exe` and macOS `.app.tar.gz` inventories identify 2 package-metadata components each (0 findings).
- **Public website changelog deployment.** The public changelog at `https://pandacode.bambooed.ai/changelog/` is deployed separately from GitHub Releases via Cloudflare Workers ([`website/README.md`](https://github.com/aicodeking/pandacode/blob/v0.3.164/website/README.md)) and remains on an earlier snapshot until deployed; GitHub Releases (linked from Settings → About) and the `latest.json` updater manifest carry the current release notes immediately.
