# Atomic queue-hold updates, offline browser reconnect cleanup, and changelog accuracy

Not published as a standalone GitHub Release; all changes below shipped bundled inside [v0.3.161](https://github.com/aicodeking/pandacode/releases/tag/v0.3.161).

## Fixed

- **Queue holds update atomically when a usage limit clears or auto-resumes.** Dismissing a usage limit or completing an automatic limit resume now checks and updates the task's queue hold in one atomic step, preventing a concurrent manual Resume or state change from another window, browser tab, or PandaConnect client from being overwritten.
- **Browser tabs cleanly close deleted idle threads and clear stale "Send now" state on reconnect.** When an open idle thread is deleted on the host while a browser tab is offline, reconnecting now clears the open transcript, subagent pane, and inspector cleanly instead of leaving stale messages behind. Reconnecting after a missed run completion also clears any pending "Send now" override so a later queue update cannot trigger an unintended browser-side send.
- **Website changelog accuracy and broken unpublished release-note links fixed.** Updated the website changelog builder so rolled-up unpublished versions (`0.3.155`, `0.3.153`, `0.3.143`, `0.3.141`) are clearly labeled as shipped in their parent release instead of counted or marked as standalone published releases, and repaired the broken `v0.3.153` SBOM download links in [`releases/0.3.153.md`](https://github.com/aicodeking/pandacode/blob/v0.3.161/releases/0.3.153.md) to point to `v0.3.154` (where those changes shipped).

## Upgrade and compatibility

- **In-place upgrade from `v0.3.156`–`v0.3.158`.** No database schema migration runs on startup, and rollback to `0.3.151`–`0.3.158` remains supported without data loss (`PRAGMA user_version = 37`).
- **Direct upgrade from `v0.3.154` or earlier.** First launch runs the one-time additive SQLite index and tracker setup introduced in `v0.3.156` synchronously — measured at ~1 second on a 218 MiB (~25k-message) database and ~2.1 seconds at 2× scale, and potentially longer on cold or fragmented databases ([migration timings](https://github.com/aicodeking/pandacode/blob/v0.3.161/docs/db-benchmarks.md#7-migration-at-two-scales)).

## Known limitations

- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.161/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.161/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.161/SBOM-COVERAGE.md)).** Generated during the release build with `syft 1.55.0` and `grype 0.121.0`; `pandacode-rust.cdx.json` scans 707 Rust lockfile components (0 Critical, 0 High, 2 Medium, 3 Low) and `pandacode-npm.cdx.json` scans 95 npm lockfile components (0 Critical, 0 High, 0 Medium, 6 Low). Four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` cannot inspect their contents, and the Windows setup `.exe` and macOS `.app.tar.gz` inventories identify 2 package-metadata components each.
- **Public website changelog deployment.** The public changelog at `https://pandacode.bambooed.ai/changelog/` is deployed separately from GitHub Releases via Cloudflare Workers (`website/README.md`) and remains on an earlier snapshot until deployed; GitHub Releases (linked from Settings → About) and the `latest.json` updater manifest carry the current release notes immediately.

- **Platform testing scope:** Apple silicon macOS was tested locally and in CI. Intel macOS (`darwin-x86_64`), Windows (`x86_64` and `aarch64`), and Linux (`x86_64` and `aarch64`) installers were not manually GUI-tested on physical hardware for this release; they are built and verified in GitHub Actions with Developer ID signing, notarization, stapling, and Gatekeeper checks on both macOS targets and packaged launch/stay-alive smoke checks on Windows and Linux.
- **GitHub Actions CI and release:** `ci.yml` runs the full Rust library test suite on Linux, per-platform Clippy (`-D warnings`) on macOS, Windows, and Linux, TypeScript/unit tests, website build, and ONNX parity on macOS. `release.yml` requires a verified artifact-only preflight (`verify_preflight` checking installer checksums, version-bound updater signatures across all six platforms, and `latest.json` with `publish` skipped) before tagging `v0.3.160`, guards published tags against commit mismatches, and keeps code signing optional for local builds and forks without signing secrets.
