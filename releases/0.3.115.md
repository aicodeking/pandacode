# Safer Skills library switches

## Fixed

- **Skills library: turning skills and rules on and off is safer in projects.** In project scope PandaCode no longer writes through a link that leads outside the project or into its `.git` folder, a hard-linked file, or a FIFO or other special file; it refuses with a message naming the path. Links between rule files (`AGENTS.md -> CLAUDE.md`) and between skills folders (`.agents/skills -> ../.claude/skills`) still work.
- **A failed write no longer leaves a half-changed project.** Every path is checked before anything is written. Existing rule and skill files are replaced through a temporary file, so a failed write keeps the old version. A failed or unsaved activation removes what it wrote and its Git exclude line, and names any file it had to leave.
- **Git exclude lines are kept tidy.** The line uses the folder the files actually land in, gitignore's special characters are escaped, and a path with a newline or other control character is refused. When two activations share a line (for example the same skill in two worktrees), turning one off keeps the line for the other. A line is only edited in an exclude list that belongs to the activation's own repository.
- **An edited activation record can't make PandaCode delete other files.** A recorded path that isn't where that skill or rule is written is left alone and reported as kept.
- **Moving a skill to a new folder** removes the old copy only after the new one is saved, so a failed save leaves the old copy working.
- **Phone: a slash command for a switched-off skill** now says the skill is switched off, without starting the agent.
- **Phone: cloning a project or adding a worktree** now refreshes which folders the Skills library switches apply to, as on the desktop.

## Known limitations

- These changes were checked with unit tests (including links, hard links, FIFOs, shared exclude lines, failed writes and failed saves) and by reading the code. They have not been clicked through by hand in the built app.
- A small timing gap remains: a parent folder swapped for a link between PandaCode's check and its write is still followed.
- If PandaCode crashes mid-write, a `.<name>.pandacode-<uuid>.tmp` file can stay beside the file it was replacing and shows in `git status`; delete it by hand.
- In user scope (your home folder) rule files are still rewritten in place and links are still followed, as before.
- On Windows there is no hard-link check, and links are refused when the project root can't be resolved.
- Full details are in [docs/skills-library.md](https://github.com/aicodeking/pandacode/blob/main/docs/skills-library.md).
