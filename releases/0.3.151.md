# Browser queue hold sync and headless drain fixes

## Fixed

- **Opening or reloading a browser tab no longer pauses waiting follow-up queues.** Connecting a browser session to a running desktop or headless host previously marked queued follow-ups as paused after a restart; browser tabs now leave active host queues free to drain automatically.
- **Browser tabs now display the exact pause reason and load active holds on connect.** Connecting or reloading a browser tab picks up active queue holds from the host (including holds placed before a follow-up is queued) and shows whether a queue is paused after a failed run, a usage limit, a stopped run, or a desktop restart. **Resume** stays hidden while a usage limit is active, and automatic recovery at limit reset remains owned by the host.
- **Bot threads and headless follow-ups stay in sync across browser tabs.** Browser tabs now refresh cleanly when bot threads or headless `pandacode serve` send, cancel, or restore queued messages, and ignore stale queue updates arriving out of order.
- **Headless `pandacode serve` guards concurrent queue drains.** A per-thread drain guard prevents two queued follow-ups from launching at the same time on a headless host, and failed queued launches are now marked as failed rather than stopped.

## Known limitations

- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.151/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.151/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.151/SBOM-COVERAGE.md)).** Desktop build dependency scans (`pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`) report 0 Critical and 0 High findings, with pre-existing lower-severity counts of 2 Medium and 3 Low in Rust and 6 Low in npm. Four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` cannot inspect components inside them, and the Windows setup `.exe` and macOS `.app.tar.gz` artifact inventories identify only 2 metadata components each.
