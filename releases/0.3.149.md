# Theme import security update and notarized macOS disk images

## Fixed

- **Updated `.vsix` theme archive parser (`zip` 9.5.1).** Upgraded the Rust `zip` crate used to read VS Code `.vsix` theme packages (from local imports and Open VSX installs, including through the local web UI) from `2.4.2` to `9.5.1`, resolving `GHSA-m665-v7pm-7grj` (Critical) and `GHSA-q7v9-x93c-xqv3` (High).

## Changed

- **Notarized macOS disk images.** Release builds now notarize, staple, and Gatekeeper-verify each `.dmg` container itself in addition to `PandaCode.app` inside it and the macOS updater archive.
- **Publish-time asset verification.** The release workflow now checks all six platform installers, their `.sha256` sidecars, updater minisign signatures (when signing is enabled), and `latest.json` before creating a GitHub Release.
- **Accurate desktop SBOM scope.** The `pandacode-npm` lockfile inventory now excludes `mobile/` (not shipped in the desktop app), keeps the highest severity when deduplicating repeated advisories, and logs a warning if the grype vulnerability database build time cannot be read.

## Known limitations

- Verified locally on macOS (Apple silicon) with Rust `vsix_themes` and `web_server` unit tests, strict Clippy (`--all-targets -- -D warnings`), `npm run build`, `npm test`, `npm run test:release` (95 tests), and the website build. Windows and Linux packages and the full cross-platform test matrix are covered by the GitHub Actions CI and release workflows (including Windows/Linux startup smoke checks).
- **SBOM scan coverage (`SBOM-COVERAGE.json`).** Compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, `PandaCode-Linux-aarch64.AppImage`) are reported as `not-scanned` because `syft` finds no identifiable components inside them; build dependencies are inventoried in `pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`.
