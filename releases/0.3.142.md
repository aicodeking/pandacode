# Smooth thread scrolling and left-side scroll indicator

## Added

- **Left-side one-click thread scroll indicator.** A slim floating rail along the left edge of the conversation pane shows a tick for each turn in the thread. Long threads are grouped into chronological ranges, while the first, latest and live turns keep their own ticks. Hovering or focusing a tick shows a preview with the turn number and the start of its prompt; clicking a tick, or dragging along the rail, smoothly jumps straight to that turn, even an older one outside the part of the thread currently drawn. The rail also has:
  - a **Load earlier messages** chevron at the top when older history is available;
  - a **Jump to latest** chevron at the bottom that smoothly returns to the end and resumes following;
  - full keyboard navigation (arrow keys, Home/End, Enter/Space, Escape) and wheel pass-through to the thread.

  It causes no layout shift and works in dark, light, sky and wallpaper themes, and with Increase Contrast, Reduce Transparency and forced colors.

## Fixed

- **Scrolling up in a thread no longer snaps back to the bottom.** Small upward trackpad or smooth-scroll steps (1–2 px) from the bottom now stop following the end of the thread right away instead of sticking to it. Re-selecting the open thread, background refreshes after switching threads, window resizes and opening a thread from its tile all keep your reading position.
- **Smoother scrolling and WebKit stability.** Scrolling inside code blocks and tool output no longer breaks outer thread following, and background trimming of long threads pauses while you scroll. Smooth jumps hold their target when deferred rows change the layout mid-jump, and give way immediately to the wheel, touch or keyboard. On WebKit (the macOS app), fractional scroll rounding, raw-text Markdown paints, deferred reply clamps and transient layout clamps no longer cause sudden jumps or widen the window unexpectedly.

## Also included from 0.3.141

0.3.141 was not published separately, so its Google Colab integration and floating thread runtime indicator ship in this release. Full details are in [the 0.3.141 notes](https://github.com/aicodeking/pandacode/blob/main/releases/0.3.141.md).

- **One-click Google Colab sign-in and settings.** Connect Colab in Settings → Connections → Cloud sandboxes with **Sign in with Google**, which uses Google OAuth2 with the Colab CLI's client or your own Google Cloud OAuth client JSON. If no local Colab CLI OAuth client is present, the first click installs Google's pinned `google-colab-cli==0.8.0` with `uv`, unless you provide your own OAuth client JSON or use `gcloud`. **Use gcloud ADC** instead runs `gcloud auth application-default login`, which rewrites the shared gcloud Application Default Credentials file other tools on this machine also use, and requests the broader `cloud-platform` scope. Pick the default hardware (CPU, a T4, L4, G4, A100 or H100 GPU, or a v5e-1 or v6e-1 TPU), turn on High-RAM, and see your live Compute Unit balance and hourly usage. Tokens stay in PandaCode's private secret store and never reach the webview.
- **Cloud Agents, VM tools, native Colab tools and optional `colab-mcp`.** Run Cloud Agents on Colab (New task → **Run on** → **Google Colab**), and manage Colab runtimes in the VM panel and with the `pandacode_vm_*` tools. Native `pandacode_colab_*` tools run Python, notebooks and shell commands, manage runtime files and handle the runtime lifecycle; creating a runtime spends compute units, so PandaCode always asks first, even in Full access mode. Optionally, Google's `colab-mcp` runs per local run with `uvx` so agents can work with the Colab notebook open in your browser.
- **Floating thread runtime indicator.** A live stopwatch or uptime pill in the conversation pane expands into a card with **Open in Colab**, **Refresh**, inline-confirmed **Restart kernel** and **Stop**, and **Dismiss** for errored, stopped or pending runtimes. Thread–runtime links survive an app relaunch, and the indicator fully supports the keyboard, screen readers, Increase Contrast and forced colors.

## Known limitations

- Verified locally on macOS (Apple silicon) with Chromium, WebKit, Rust unit tests, strict Clippy and the website build. Windows and Linux packages are covered by the GitHub Actions release builds and their startup smoke checks.
- Native macOS trackpad inertia and elastic rubber-band feel are checked by hand in the packaged app, in addition to the automated Playwright WebKit checks.
- Colab runtimes are temporary. An idle runtime is held for roughly 90 minutes before it expires, and stopping a runtime discards its unsaved files and kernel state.
- Colab sign-in and runtime actions were tested locally against loopback mocks. Live GPU and TPU quotas, idle timeouts and OAuth client availability depend on your Google Colab account and tier.
