# Antigravity ACP hardening

## Fixed

- **Antigravity tasks start only in the approval mode you picked.** Standard, Accept edits, Plan and Full access now map to Antigravity's own Default, Accept edits, Plan and Auto modes. Full access also launches the `agy` CLI with `--dangerously-skip-permissions` and approves offered one-time permissions. Standard and Plan tasks, and any task on a server that advertises no modes at all, refuse to start when their mode is missing rather than running in agy's default mode, which in agy 1.5.7+ is Auto; Accept edits and Full access fall back to Default when their own mode is absent. The message tells you to run `agy update` outside PandaCode or to switch from the standalone ACP server to the `agy` CLI.
- **Resumed Antigravity threads recover.** When agy no longer has a saved session, PandaCode tries `session/load` (if the server supports it) and then starts a fresh session, noting this in the task's status. Account-pool rotations that rewrite the prompt as a resume never fall back to an empty session.
- **Quota and rate limits are no longer reported as sign-in errors.** Antigravity's `-32000` errors and its trailing `⚠` warning banners for exhausted quota, credits, `RESOURCE_EXHAUSTED` or HTTP 429 now show the usage-limit notice with its reset time and can rotate a pooled account. Context-window errors show the server's own text and are no longer treated as sign-in problems or account limits. A real sign-in failure says to run `agy acp --login` and includes the server's message.
- **Lingering Antigravity agents shut down cleanly.** An agent kept alive between turns is asked to close its session, then signalled and reaped along with its process group within a few seconds, so background checkpoint writers and orphaned children no longer pile up. A lingering agent is also stopped before its console opens on the same thread.
- **Named connections stay isolated.** Each Antigravity launch is pointed at the Gemini directory chosen by the named connection, the provider environment or `ANTIGRAVITY_GEMINI_DIR`, in that order, via `--gemini-dir`. A relative directory is rejected before the agent starts so it cannot be created inside your project. Model and command discovery run in a private empty folder and a per-run temp folder rather than the shared system temp.
- **Antigravity console safeguards.** The console always opens the `agy` CLI, even when the standalone ACP server is also installed, with agy's self-update paused while you type. It explains why it cannot open for the ACP server alone, a named Antigravity connection, a custom provider `GEMINI_DIR`, or Approve for me mode.
- **Usage, versions and updates no longer trigger agy self-updates.** Version probes, the update check and `agy -p /usage` run with `AGY_CLI_DISABLE_AUTO_UPDATE`. They tolerate update banners printed before the JSON, and usage is never read from the ACP server binary or from the default account when a custom Gemini directory is set. Settings → Agents shows the `agy` CLI's real version and reports "ACP installed" only for the standalone server.
- **Honest privacy row for Antigravity.** Telemetry is turned off for task sessions through `agy acp --disable-telemetry`. The harness-privacy view now marks Antigravity as partial because the console, usage checks and standalone ACP server have no switch, and agy may save the choice with your Google account.
- **Model list and router cards.** Antigravity accepts only the models it advertises, with no custom IDs. Its efforts and variant suffixes no longer leak into GitHub Copilot's model list. Panda Router maps current Antigravity models (Gemini 4 Argon, Claude Sonnet 5.5, Claude Opus 5.5, GPT-OSS 120B Medium) to their cards and keeps Gemini 4 Neon, Carbon and Hydrogen on their own cards, so none of them is ever matched to Argon.

## Added

- **Antigravity hooks and MCP servers in Capabilities.** Enabled Antigravity hooks and its configured MCP servers now appear in the capabilities view next to the other harnesses'.

## Known limitations

- Verified locally on macOS (Apple silicon) with Chromium, WebKit, Rust unit tests, strict Clippy and the website build. Windows and Linux packages are covered only by the GitHub Actions release builds and their startup smoke checks.
- Antigravity's standalone ACP server advertises no approval modes, so tasks refuse to start on it until you switch to the `agy` CLI.
