# Bug fixes across Windows, cloud agents and harnesses

## Fixed

### Windows

- **The window can no longer freeze for good.** Moving to Tauri 2.12 removes the keyboard and focus deadlock in the old windowing library (#255, thanks @gmanzienko).
- **No more crash at launch on older CPUs.** Windows x64 builds no longer include ONNX Runtime, which crashed on CPUs without AVX2. Panda Router uses its keyword heuristic on Windows x64 for now (#205, thanks @trfi).
- **Opening a large project does less work.** The file tree no longer opens every file in a folder to list it, which security scanners slow down on Windows (#249). We couldn't test this on Windows, so please tell us if opening a project is still slow.
- **Antigravity no longer leaves large temp folders behind.** Each turn's temp files now go in a folder PandaCode cleans up (#248).

### Cloud agents

- **DigitalOcean, Vultr, Hetzner and RunPod tasks can start.** The shared SSH key can now be saved, and DigitalOcean's reply is read correctly (#206, thanks @hongkongkiwi and @zupat).
- **Cloud machines run your OpenCode generation.** A computer on OpenCode v2 now installs v2 on the machine, including one that already has v1 (#209, thanks @hongkongkiwi and @zupat).
- **Modal:** a new sandbox no longer fails with "expires in N minutes" (#226).
- **Blaxel:** commands inside a sandbox no longer fail with HTTP 403, and refusals now show the provider's own message when it is safe to (#208).
- **boat:** free-trial accounts can start tasks, with a 2-hour limit, and other errors are no longer mistaken for the trial limit (#218, thanks @hongkongkiwi).
- Files uploaded to Docker machines are now private while they wait to be copied. A failed OpenCode login import can no longer show credentials in its error.

### Harnesses

- **Reasoning effort is back for OpenCode v2** (#193).
- **pnpm installs are found.** Harnesses installed with `pnpm add -g` no longer show as Not installed (#221, thanks @hongkongkiwi).
- **ZCode works from the desktop app.** The CLI inside the app is now detected (#224, thanks @hongkongkiwi). Runs no longer fail on model selection, and a thread whose saved session is gone recovers and tells you it started without its history (thanks @zj-linjie).
- **Slower agents get more time to start.** Each startup step now has 120 s, renewed by any reply from the agent, up to 300 s in total, and the error says how far it got (#232).
- **Maintenance commands work with a team on.** `/compact`, `/status` and similar commands run on the lead's harness and leave the team as it was (#235, thanks @hongkongkiwi for the first version).

### Tasks and bots

- **New chat no longer opens two chats.** Moving a New task to No project keeps its model, mode, connection, text and attachments (#252, #193).
- **Connections are clearer.** A connection's tab in the model picker now says to choose a model, because only picking a model saves it (#252).
- **Bots keep their instructions after a harness switch**, and a failed turn no longer loses them (thanks @Bonskills).
- **Codex project skills go where Codex reads them.** Existing ones move on their next sync, and files you edited are kept.

### Interface

- **Window resizing is smoother in long threads.** Rows off screen skip their work during a drag: about 2–3× less work per step in a 200-message thread in our Chrome test (#199). We haven't measured a real window drag in the app.
- The model picker no longer fades its rows.

### Mobile

- The keyboard inset now recovers when you swipe the keyboard away on iOS. Mobile ships separately from this release.

## Known limitations

- On Windows x64, Panda Router no longer uses its ONNX profiler.
- Nothing in this release was run on Windows by us, apart from the Tauri update, which its contributor tested on Windows 11. The fixes for #248 and #249 in particular need real-world confirmation.
- E2B still retries at its 1-hour limit after any refused keep-alive, because we don't have a real refusal to match against.
- Forks, side threads and the harness console don't inherit a task's connection.
- A follow-up message sent right after an Antigravity turn ends the previous agent, so a checkpoint still running then is lost.
- Edit on a sent message still forks into a new task and leaves the original unchanged. This is by design (#214).
