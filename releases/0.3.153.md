# Colab runtime assignment recovery

## Fixed

- **Colab checks for an existing runtime when an assignment response drops or is cut off.** PandaCode looks up the same notebook after every retryable POST failure, including the final attempt. It reuses a runtime Colab has already created or sends another POST with the fresh assignment token if time and retries remain.
- **Colab bounds the full assignment flow to 165 seconds.** Each POST has at most 75 seconds, with 20 seconds reserved for reconciliation within PandaCode’s 180-second runtime creation allowance.
- **Truncated Colab refusals keep their HTTP status.** Cut-off 4xx and HTTP 500 responses stay terminal, preserving the service status and any quota, capacity, or credentials guidance. TLS and certificate failures also fail immediately.
- **Cloud HTTP logs distinguish when a connection closed.** Diagnostics distinguish a drop before headers from an interruption while reading the response and omit URLs, headers, and credentials. Cloud clients retain Reqwest’s existing 15-second TCP keepalive idle threshold.

## Known limitations

- **Colab quotas and capacity still apply.** Recovery depends on Colab answering the reconciliation request before the assignment budget expires.

- Recovery from dropped and cut-off assignment responses was verified against loopback mock servers rather than a live Colab network drop.
- **Local web access (`--port`) ([`docs/headless.md`](https://github.com/aicodeking/pandacode/blob/v0.3.153/docs/headless.md#local-web-ui---port)).** The `#token=` URL grants full control of the PandaCode session as the host user (including starting agents, running terminal commands, and editing workspace files). The built-in web server speaks plain HTTP, so keep it on loopback (`127.0.0.1`) or reach it over an SSH tunnel, Tailscale, or WireGuard rather than exposing it on an untrusted network. Host-only capabilities — local voice dictation, the embedded browser, native clipboard access, and OS file/tray actions — are unavailable in browser tabs.
- **SBOM scan coverage ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.153/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.153/SBOM-COVERAGE.md)).** Compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, and `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because Syft cannot inspect their contents. The Windows setup `.exe` and macOS `.app.tar.gz` inventories cover package metadata.

## Verification

- **Local macOS (Apple silicon).** The full Rust library suite passed with 3,972 passed and 110 ignored using `RUST_TEST_THREADS=2` after a default-concurrency run hit a SQLite timing assertion outside Colab. Checks also included Clippy (`--all-targets -- -D warnings`) after cleaning the PandaCode crate, `npm run build`, Node unit tests (1,471 passed), release-script tests (101 passed), `npm run site:build`, and `git diff --check`.
- **GitHub Actions CI and release:** `ci.yml` runs the full Rust library suite on Linux and Clippy on macOS, Windows, and Linux. `release.yml` verifies release artifacts and runs packaged startup smoke checks on Windows and Linux.
