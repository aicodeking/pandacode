# PandaCode restarts itself after a crash and keeps your unsent text

## New

- **Restart after a crash.** If PandaCode crashes, it starts again by itself and shows a notice saying what happened and when. The notice stays until you close it.
  - It does not restart after you quit, force quit or kill it.
  - After 3 crashes in 10 minutes, or 2 crashes in a row right after launch, it stops restarting for up to 10 minutes and says so.
  - If the thread you had open may have caused the crash, it is kept closed and the notice offers **Open thread**.
  - **Show crash report** opens the report in your file manager. Reports stay on your computer; nothing is sent anywhere.
  - Turn restarts off in Settings → General → Crash recovery.
- **Unsent text survives a crash.** What you typed in a thread, a New task or a bot shared channel comes back at the next launch. Settings → General → Crash recovery has **Keep unsent drafts** (on by default) and **Clear saved drafts**.
- **`pandacode serve` is covered too.** A crashed host restarts, and its next start prints one line saying when it crashed and whether it restarted. Under systemd the service manager stays in charge and PandaCode's own restart is off.

## Privacy

- Crash reports are plain text in `crash-reports/` in the app data folder (at most 10, kept 90 days). A report can contain file paths, text from your work or a credential that was in an error message, so check it before attaching it to an issue.
- Unsent drafts are kept as plain text in the app's local storage for up to 30 days. A pasted secret is kept too, until the message is sent or cleared, or you turn **Keep unsent drafts** off.
- On Linux the app data folder is now set to owner-only at every start.

## Known limitations

- Crash recovery has only been run on macOS. The Windows and Linux code builds in CI but has not been tried on a real machine, and the native "could not start" dialog and its Linux fallbacks have not been seen running.
- The very last keystrokes before a hard crash can be missing, because the webview may write local storage to disk slightly late. Attachments and drafts over 50,000 characters are not kept.
- A crash that ends PandaCode before it can report it (for example a stack overflow on a thread PandaCode did not start) is treated like a kill: no restart and no notice.
- `pandacode serve --sign-in` that crashes during sign-in restarts as plain `serve`, which exits as not signed in. Run the sign-in again.
- There is no button to delete crash reports; delete the `crash-reports/` folder by hand.
- On Linux, `pandacode serve` under `xvfb-run` is only guarded when `xvfb-run` is in `/usr/bin` or `/bin`.
- More limits are listed in `docs/crash-recovery.md`.
