# Lighter streaming

## Changed

- **Streaming replies do less work per update.**
  - Each update now paints in one animation frame instead of two.
  - Markdown is parsed only for new text, and unchanged blocks are kept on the page instead of replaced.
  - In the public benchmark (`bench/t3-compare`), streaming a 50 KB reply took 32% less script time, 39% less style recalculation and 68% fewer DOM changes, with identical output.
- **Long code blocks stream more cheaply.** An open code fence is painted line by line instead of being re-parsed on every update.
- **Scrolling while a reply streams no longer forces a layout after each update.** The transcript still stays pinned to the bottom while you follow it, and it still holds its place when you scroll up.
- **The visual progress picture-in-picture no longer restyles the whole conversation pane on every streamed block.**

## Known limitations

- Total main-thread time for the benchmark reply drops only about 2.5%. Painting, compositing and garbage collection still dominate, and the time from the last update to the final paint is unchanged.
