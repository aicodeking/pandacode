# Reliable browser follow-up queues and stricter release checks

## Fixed

- **Browser-queued follow-ups and Resume now drain on the host.** Queue mutations (`queue_add`, `queue_update`, `queue_remove`, `queue_take_steered`, `queue_reorder`, `queue_take`, `queue_restore`) and hold changes (`set_queue_hold`) now broadcast `queue-changed` across connected clients, browser **Resume** explicitly releases the host hold, and headless `pandacode serve` respects queue holds and broadcasts claim/restore updates. Browser-queued follow-ups now run once on the desktop or headless host without stalling or double-sending.

## Changed

- **Enforced preflight and updater-signature gates for official publishes.** In `aicodeking/pandacode`, `release.yml` now requires a green `workflow_dispatch` preflight run on `main` for the exact commit before publishing, requires verified updater minisign signatures and `latest.json` (`--require-signed`) whenever official or updater-signed builds publish (also failing if `.app.tar.gz` updater archives are present without signatures), and writes signed macOS install notes only when both `APPLE_CERTIFICATE` and `APPLE_SIGNING_IDENTITY` are configured. Local builds and forks without signing secrets remain optional.

## Known limitations

- Verified locally on macOS (Apple silicon) with Rust `message_queue`, `headless`, and `web_server` unit tests (98 tests), `vsix_themes` unit tests (3 passed, 2 ignored live-network tests), strict Clippy (`--all-targets -- -D warnings`), `npm run build`, `npm test`, `npm run test:release` (98 tests), the website build, Playwright Chromium and WebKit suites for `web-bridge.spec.ts` (14 tests each, including browser-to-host queue and Resume regressions), and Chromium suites for `message-queue`, `queue-parity`, `steering`, and `usage-limit` (39 tests). In GitHub Actions, `ci.yml` runs the full Rust library test suite on Linux, per-platform Clippy (`-D warnings`) across macOS, Windows, and Linux, and ONNX parity on macOS; `release.yml` runs Windows and Linux packaged startup smoke checks (confirming the app launches and stays alive, not GUI rendering) and, for Developer ID builds (including this official release), notarizes, staples, and Gatekeeper-verifies both `.dmg` containers and `PandaCode.app`.
- **SBOM scan coverage and closed `v0.3.148` exception ([`SBOM-COVERAGE.json`](https://github.com/aicodeking/pandacode/releases/download/v0.3.150/SBOM-COVERAGE.json), [`SBOM-COVERAGE.md`](https://github.com/aicodeking/pandacode/releases/download/v0.3.150/SBOM-COVERAGE.md)).** The carried-over `v0.3.148` security exception is closed: upgrading `zip` to `9.5.1` (resolving `GHSA-m665-v7pm-7grj` and `GHSA-q7v9-x93c-xqv3`) and excluding `mobile/` from `pandacode-npm` in `v0.3.149` left zero Critical and zero High findings in both desktop lockfile scans (`pandacode-rust.cdx.json` and `pandacode-npm.cdx.json`), with no dependency changes since `v0.3.149`. The four compressed installers (`PandaCode-macOS-arm64.dmg`, `PandaCode-macOS-x64.dmg`, `PandaCode-Linux-x86_64.AppImage`, `PandaCode-Linux-aarch64.AppImage`) remain `not-scanned` because `syft` finds no identifiable components inside them.
